# Falsified directions · MT / Streaming

> Every entry is backed by A/B data. If premises change (table structure, window, corpus, CPU), re-evaluation is allowed, but new decomposition evidence must come first; differential-testing discipline in [benchmarking methodology](../bench/methodology.md). Rules: [index](../negative.md).

| Direction | Result | Conclusion |
|---|---|---|
| frame-per-job MT encoding | rejected at design time | multi-frame output burdens the decode side (unfriendly to single-frame consumers); stage-2 single-frame overlap jobs are the right answer |
| enlarging overlap only, without strip prefill | ineffective | insertion paths only insert job-local positions; strips never get indexed; enlarging overlap is mathematically ineffective |
| fixed-grid prefill to find periodic repeats | mathematically unsolvable | clustered 5-grams recursively bury twin slots with equal values / phase-alignment traps; dfast/chain suffer the same burial; **seeding at job start is mandatory** |
| huge pledge without a job_size cap | memory blowup | MAX_JOB_SIZE=1GiB (same as zstdmt) |
| thread_local pool across thread::scope bursts | always misses | scope threads are fresh each time; the pool must be owned by the encoder and carried across bursts |
| reading directly into Read's spare capacity (beyond the read-pump double copy) | dropped | handing uninitialized buffers to arbitrary Read impls violates the trait contract |
| streaming-MT checksum absorb off the calling thread, four placements (2026-09-15; XXH64 has NO chunk-level merge — the spec's `mergeAccumulator` is a finalize fold, the avalanche is non-invertible and the lane rounds chain non-linearly, so per-job digests cannot combine and one serial state must absorb in order; zstdmt's SerialState is an ordered per-job `XXH64_update` under a mutex, not a merge) — (a) pool-job pickup like zstdmt (our bursts freeze the whole range at post, so no ordering is even needed), (b) sidecar thread via the existing `AsyncChecksum`, (c) hash fused into the pump memcpy (`write_appending`), (d) baseline = absorb on the calling thread at fire time | in-process interleaved 3/4-way A/B, 32MiB w8, write AND read (64KiB) paths: caller absorb is **free** (write text.fastest x1.005-1.041, read-path every cell x0.958-1.013 on/off); sidecar x0.96-1.25 (never beats caller, text.fastest x1.09-1.25), pool pickup x1.15-1.23 text.fastest / x1.05-1.11 text.fast, fused pump x1.08-1.21 text cells; the caller's absorb cost shows only in slow machine states (first session measured on/off 1.19-1.20 at text.fastest, `Xxh64::absorb` = 16.65% of whole-process cycles) | the fire-time caller absorb already rides the fire→drain window that overlaps the encode span on a thread that would otherwise wait at the barrier; every offload pays the same 1.6ms of hash PLUS a new concurrent memory stream competing with 8 encoders on the bandwidth-saturated fastest-tier cell (sidecar extends the burst; pool pickup starts after the first job finishes and pokes past the last; fused copy runs slower than memmove and pays on the pump directly). The residual on/off tax at text.fastest is a **resource tax** (serial hash sum ≈ pump memcpy sum ≈ encode span), not a placement tax — no thread placement can remove it; only a cheaper hash or de-saturating the cell (the pump/burst item) can. Nothing landed; the pre-change placement stands |
| ping-pong buffer recycling (regenerate the accumulate buffer into a spare when the dead prefix is not enough, retiring the old allocation behind an in-order assembled watermark) — the "pump never waits on workers" form | interim interleaved A/B (2026-09-16) measured it **equal** to the simpler quiesce-gated wrap+grow on every fastest/fast stream-mt8 cell, while the audit found three lifecycle defects in the WIP form: the spare was reused without clearing the retired buffer's length (stale-prefix corruption plus runaway capacity at the 256 MiB ceiling), and the poison abort completed unclaimed jobs without setting `done` or decrementing the posted count (an infinite spin in the quiesce wait) | the in-buffer wrap is a move of the live tail whose destination **overlaps** the views of still-running jobs — it cannot run ahead of quiescence at all without ring-buffer job views (zstdmt's model; a different job-contract), and the measured overlap value on the epoch-sized buffer is zero: the pump laps the workers about once per epoch and the quiesce wait is bounded by the in-flight encode span. Landed the quiesce-gated form |
| larger read-side pump pulls (64 / 128 KiB staging chunk instead of 16 KiB) | interleaved A/B, mt8 read path, text/json × fastest/fast (2026-09-16): 64 KiB median ratio vs 16 KiB 0.89-1.00 (below 1 on 5 of 6 cells), 128 KiB 0.85-1.00 (below 1 on 5 of 6) | a pull larger than the grid's posting granularity overshoots the epoch boundary inside one append, so the buffer pressure shifts to mid-epoch recycle points (quiesce-gated) instead of boundary-aligned ones; the 16 KiB chunk stays (kept as a persistent per-encoder buffer — the zeroing, not the size, was the cost) |
