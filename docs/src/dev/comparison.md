# zstdx vs. official zstd

This document compares **zstdx** — this repo's pure-Rust zstd implementation, a fork of KillingSpark/zstd-rs (ruzstd) with a from-scratch encoder added (`crates/zstdx/src`, CLI `crates/zstdx-cli`, bench `crates/zstdx-bench`) — against **official zstd v1.6.0**, the C reference implementation (`/root/programs/fork/zstd`, library `lib/`, CLI `programs/`), across four domains: encoder front-end, entropy coding, decoder, and systems architecture; citations use `crates/zstdx/src/...:symbol` vs `lib/...:symbol`.

The page records design-level A/B reasoning and a symbol-level index across both code trees; it is re-verified against both trees on major changes instead of being a dated snapshot. The authoritative current capability/gap state lives in [status](status.md) and [todo](todo.md).

## How to read this document

Differences come in three categories, used as sub-section markers in every domain: **A** — zstdx solves a problem both sides share with its own approach (includes documented ports that deviate); **B** — zstdx-only techniques with no counterpart in official zstd; **C** — official-zstd techniques zstdx lacks (gaps). Machinery the zstd format mandates (wire layout, FSE spread, repcode semantics, block framing, ...) is excluded from "differences" and only appears under Similarities.

Two tree-wide facts worth pinning: the AVX-512 VBMI kernels are **encoder-side only** (`crates/zstdx/src/encoding/block_enc/compressed.rs:histogram_small_alpha_avx512`, `crates/zstdx/src/bit_io/bit_writer.rs:uniform4_pack_avx512`) — the zstdx decoder contains no SIMD, just 16-byte u128 copies and BMI2 dispatch; and zstdx's whole-window MT overlap (see Architecture A) is *larger* than libzstd's default `overlapLog` fraction, a deliberate deviation, not an oversight.

## Similarities

### Format-mandated

- Frame/block framing: header descriptor, window descriptor (10+exp), dictID/FCS widths, skippable magic 0x184d2a50..=5f, 3-byte block headers with Raw/RLE/Compressed types and the 128 KiB cap, default 128 MiB window limit — `crates/zstdx/src/decoding/frame.rs:read_frame_header`/`is_skippable_magic`, `crates/zstdx/src/decoding/block_decoder.rs:read_block_header`, `crates/zstdx/src/decoding/frame_decoder.rs:DEFAULT_MAX_WINDOW_SIZE` vs `lib/decompress/zstd_decompress.c:ZSTD_getFrameHeader_advanced`/`readSkippableFrameSize`/`ZSTD_getcBlockSize`, `lib/zstd.h:ZSTD_WINDOWLOG_LIMIT_DEFAULT`.
- FSE: spread step `p += (ts>>1)+(ts>>3)+3`, low-probability (−1) symbols at table top, decode-entry recurrence, NCount wire format, predefined LL/ML/OF distributions (logs 6/6/5), RLE routed through a degenerate one-cell table — `crates/zstdx/src/fse/fse_decoder.rs:build_decoding_table`/`read_probabilities`, `crates/zstdx/src/decoding/sequence_section_decoder.rs:pack_rle_entry`, `crates/zstdx/src/fse/fse_encoder.rs:LL_DIST/ML_DIST/OF_DIST` vs `lib/common/fse.h:FSE_TABLESTEP`, `lib/common/fse_decompress.c:FSE_buildDTable_internal`, `lib/common/entropy_common.c:FSE_readNCount_body`, `lib/common/zstd_internal.h:LL_defaultNorm`, `lib/decompress/zstd_decompress_block.c:ZSTD_buildSeqTable_rle`.
- Sequence coding: LL/ML/OF code ladders with dense LUTs below 64/131, table-modes byte (ll:6|of:4|ml:2), backward encoding with initial states from the last sequence and ML→OF→LL flush, repcode semantics incl. the ll0 swap — `crates/zstdx/src/encoding/seq_codes.rs:LL_META/ML_META`, `crates/zstdx/src/encoding/block_enc/compressed.rs:encode_sequences`, `crates/zstdx/src/decoding/sequence_execution.rs:do_offset_history` vs `lib/common/zstd_internal.h:LL_bits/ML_bits`, `lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body`, `lib/decompress/zstd_decompress_block.c:ZSTD_decodeSequence`.
- Huffman wire format: weight-list description (raw 4-bit or FSE-compressed, weight-FSE tableLog ≤ 6, interleaved states), weights→table math, 4-stream literals with 6-byte LE16 jump table and `(n+3)/4` split, all size formats, X1/X2 entry layouts — `crates/zstdx/src/huff0/huff0_encoder.rs:write_table_desc`, `crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_literals`, `crates/zstdx/src/huff0/huff0_decoder.rs:build_x2_table` vs `lib/compress/huf_compress.c:HUF_writeCTable_wksp`/`HUF_compressWeights`, `lib/common/entropy_common.c:HUF_readStats_body`, `lib/decompress/huf_decompress.c:HUF_DEltX1`/`HUF_DEltX2`.
- Bit-IO directions: LSB-first writer with whole-byte flush; reversed readers keep an LE u64 window consumed from the MSB — `crates/zstdx/src/bit_io/bit_writer.rs:BitWriter::write_bits_64`, `crates/zstdx/src/bit_io/bit_reader_reverse.rs:BitReaderReversed::refill` vs `lib/common/bitstream.h:BIT_addBits`/`BIT_initDStream`/`BIT_reloadDStream`.
- Checksum, dictionaries, budgets: XXH64 truncated to 32 bits and computed only when the flag is set, dict content reachable only until output exceeds the window, per-sequence output-overrun rejection, trailing empty last block on empty/exact-multiple input — `crates/zstdx/src/decoding/scratch.rs:set_checksum_enabled`, `crates/zstdx/src/decoding/decode_buffer.rs:repeat_from_dict`, `crates/zstdx/src/encoding/frame_compressor.rs:trailing_empty` vs `lib/decompress/zstd_decompress.c:ZSTD_decompressBegin`, `lib/compress/zstdmt_compress.c:ZSTDMT_writeLastEmptyBlock`, `lib/decompress/zstd_decompress_block.c:ZSTD_execSequenceEnd`.

### Ported machinery

- Matcher family and optimal parser are per-tier ports: single-probe fast with ip0/ip1 pipeline, 8-byte/5-byte dfast double hash, head+chain lazy search, the full `zstd_opt.c` port (bt1 insertion, all-matches collection, price algebra ×256, rescale/scale/update stats, btultra2 two-pass first block), and the btlazy2 DUBT tree with its lazy-generic selection loop (`crates/zstdx/src/encoding/match_generator/parse_fast.rs`/`parse_dfast.rs`/`parse_chain.rs`/`parse_btlazy.rs`, `crates/zstdx/src/encoding/dubt.rs`, `crates/zstdx/src/encoding/btlazy.rs`, `crates/zstdx/src/encoding/opt.rs:Finder::insert_bt1`/`get_all_matches`/`bit_weight`/`rescale_freqs` vs `lib/compress/zstd_fast.c:ZSTD_compressBlock_fast_noDict_generic`, `lib/compress/zstd_double_fast.c:ZSTD_compressBlock_doubleFast_noDict_generic`, `lib/compress/zstd_lazy.c:ZSTD_HcFindBestMatch`/`ZSTD_insertDUBT1`/`ZSTD_DUBT_findBestMatch`, `lib/compress/zstd_opt.c:ZSTD_insertBtAndGetAllMatches`/`ZSTD_rescaleFreqs`/`ZSTD_initStats_ultra`).
- FSE encoder table machinery is ported: the arithmetic `FSE_CTable` form (`deltaNbBits`/`deltaFindState` packed into u64 `tt` entries), the U64-spread fast branch for tables without −1 symbols, and the NCount writer's `remaining`/`threshold`/`nbBits` ladder — `crates/zstdx/src/fse/fse_encoder.rs:FSETable::tab`/`build_table_from_probabilities`/`write_table` vs `lib/compress/fse_compress.c:FSE_buildCTable_wksp`/`FSE_writeNCount_generic`. FSE normalization and NCount reading are documented ports (`normalize_count`/`normalize_m2`/`optimal_table_log`/`RTB_TABLE` vs `lib/compress/fse_compress.c:FSE_normalizeCount`/`FSE_normalizeM2`/`FSE_optimalTableLog`); Huffman X1/X2 decode fast loops and the X1/X2 choice are explicit ports incl. the `algoTime` cost table — `crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved[_x2]`/`select_x2_table` vs `lib/decompress/huf_decompress.c:HUF_decompress4X1_usingDTable_internal_fast_c_loop`/`HUF_selectDecoder`.
- Huffman code construction ports libzstd's shape: a two-queue tree over count-sorted leaves, depth-clamped by `HUF_setMaxHeight`'s Kraft repayment, with the exact-cost treeless/repeat decision of `HUF_compress_internal` — `crates/zstdx/src/huff0/huff0_encoder.rs:build_lengths_into`, `crates/zstdx/src/encoding/block_enc/compressed.rs:compress_literals` vs `lib/compress/huf_compress.c:HUF_buildCTable_wksp`/`HUF_setMaxHeight`/`HUF_compress_internal`.
- Decode-execute fusion ("the libzstd model" per its doc) with the wildcopy copy stack (dec32/dec64 overlap tables) — `crates/zstdx/src/decoding/block_decoder.rs:decompress_block_flat`, `crates/zstdx/src/decoding/sequence_execution.rs:wildcopy_literals`/`overlap_copy8` vs `lib/decompress/zstd_decompress_block.c:ZSTD_decompressSequences_body`, `lib/common/zstd_internal.h:ZSTD_wildcopy`, `ZSTD_overlapCopy8`.
- Dictionary training and emission descend from libzstd's scheme: per-epoch segment selection with distinct k-mer scoring (fastcover's shape) and the `ZDICT_finalizeDictionary` table+header layout — `crates/zstdx/src/dict/cover.rs:select_segment`, `crates/zstdx/src/dict/mod.rs:build_dict`, `crates/zstdx/src/dict/finalize.rs` vs `lib/dictBuilder/fastcover.c:FASTCOVER_selectSegment`, `lib/dictBuilder/zdict.c:ZDICT_finalizeDictionary`.
- Per-stream entropy mode selection (RLE/predefined/repeat/custom decision tree) and sequence-code computation — `crates/zstdx/src/encoding/block_enc/compressed.rs:select_from_counts`, `crates/zstdx/src/encoding/seq_codes.rs:pack_seq` vs `lib/compress/zstd_compress_sequences.c:ZSTD_selectEncodingType`, `lib/compress/zstd_compress_internal.h:ZSTD_LLcode`/`ZSTD_MLcode`.
- Recently landed ports: the gear-hash long-distance matcher (`crates/zstdx/src/encoding/ldm.rs` vs `lib/compress/zstd_ldm.c:ZSTD_ldm_blockCompress`) and the post-parse block splitter (`crates/zstdx/src/encoding/block_enc/split.rs` vs `lib/compress/zstd_compress.c:ZSTD_deriveBlockSplits`).

### Converged design

- 4-lane position-mod-4 histograms recombined at the end, chosen for OoO friendliness on both sides — `crates/zstdx/src/encoding/block_enc/compressed.rs:histogram_literals` vs `lib/compress/hist.c:HIST_count_parallel_wksp`.
- MT job invariants: first block of every job is self-describing (entropy reset), repcodes gated until three literal-offset sequences rewrite history, overlap strip indexed into the search tables, job size floored/capped (1 MiB / 1 GiB), warm per-worker state pooled, worker failures deferred to ordered assembly, MT auto-engages only with >1 usable core — `crates/zstdx/src/encoding/match_generator/mod.rs:gate_repcodes`/`prefill_window`, `crates/zstdx/src/encoding/mt.rs:MAX_JOB_SIZE`/`MIN_JOB_SIZE`/`poison`, `crates/zstdx/src/encoding/frame_compressor.rs:take_slice_state` vs `lib/compress/zstdmt_compress.c:ZSTDMT_compressionJob`/`ZSTDMT_JOBSIZE_MAX`/`ZSTDMT_getCCtx`/`JOB_ERROR`, `lib/compress/zstd_compress.c:ZSTD_invalidateRepCodes`.
- Streaming architecture: pull decoder core + Read/Write wrappers, pledged size written into the frame header, decode output buffer sized window + 2·block + overlength, BMI2 runtime CPU-feature dispatch — `crates/zstdx/src/stream/write.rs:Encoder::auto_finish`, `crates/zstdx/src/encoding/frame_header.rs:FrameHeader.frame_content_size`, `crates/zstdx/src/decoding/flat_buffer.rs:ensure_block_space`, `crates/zstdx/src/decoding/sequence_section_decoder.rs:decode_sequences` vs `lib/compress/zstd_compress.c:ZSTD_compressStream2`/`ZSTD_CCtx_setPledgedSrcSize`, `lib/decompress/zstd_decompress.c:ZSTD_decodingBufferSize_internal`.

## Encoder front-end

### A. Own approach to a shared problem

- Dictionary trainer estimator: deterministic fastCover-style scheme of zstdx's own — shuffled samples, an 8-byte k-mer frequency table (capped at 2^21 entries, strided sampling), per-epoch sliding-window scoring by summed *distinct* k-mer frequency with selected-segment zeroing, a k-sweep scored on a held-out split (`crates/zstdx/src/dict/cover.rs:select_segment`, `crates/zstdx/src/dict/mod.rs:build_dict`); official fastcover computes exact whole-corpus d-mer frequencies into a 2^f bucket table (f=20, d=8, k=2000, splitPoint 0.75, accel table — `lib/dictBuilder/fastcover.c:FASTCOVER_defaultAccelParameters`) over in-memory samples. Both finish with the `ZDICT_finalizeDictionary` layout (entropy tables + header), zstdx's being a documented port (`crates/zstdx/src/dict/finalize.rs`) whose divergences (dead `repStartValue` analysis skipped, raw-encoding blocks still contributing their parse) are measured irrelevant.
- 32-bit hash entries with positional reconstruction: `(pos & 0xffff_ffff)+1` keeps zero as dead sentinel and rebuilds high bits from the scan position (`crates/zstdx/src/encoding/match_generator/tables.rs:pack_pos`); the scan loops resolve entries as distances inline, so only entry-roundtrip tests keep the explicit inverse. C keeps full U32 window indices validated against `window.lowLimit`/`minChain` (`lib/compress/zstd_lazy.c:ZSTD_HcFindBestMatch`).
- Monotone-origin table entries: every matcher table (fast/dfast/chain/opt) stores u32 entries biased by a per-state origin coordinate that advances past each invalidated span, so stale entries rebuild as out-of-window positions and invalidation stays O(1) with no clears (`crates/zstdx/src/encoding/opt.rs:Finder::resolve`, `crates/zstdx/src/encoding/match_generator/tables.rs:pack_pos`); C validates against `windowLow`/`btLow`/`nextToUpdate` and rewinds window limits for the btultra2 stat seed (`lib/compress/zstd_opt.c:ZSTD_insertBtAndGetAllMatches`/`ZSTD_initStats_ultra`).
- Offset-gain store gate: `crates/zstdx/src/encoding/match_generator/price.rs:pays_for_offset` (`ml*4 >= ilog2(offset)+7`, reps exempt) refuses hash-path candidates whose offset code outweighs the length — derived from libzstd's lazy gain arithmetic (`lib/compress/zstd_lazy.c:ZSTD_compressBlock_lazy_generic`) but applied as an emission gate, which C never does; the chain strategy's variant `pays_for_offset_lit` prices displaced bytes at the previous block's Huffman code lengths.
- Fast-tier acceptance bar: in dense blocks the single-probe tier declines far candidates whose displaced literals, priced at fed-back code lengths, do not cover the offset (`crates/zstdx/src/encoding/match_generator/parse_fast.rs`, folding to constant-true outside dense mode); C's fast accepts every ≥mls candidate (`lib/compress/zstd_fast.c:ZSTD_compressBlock_fast_noDict_generic`) — ratio/speed tuning of the same single-probe design.
- Miss-step curve: zstdx grows the probe step quadratically with the literal run, `1 + min(miss_count>>2, 255)`, with a dense-mode doubling of the pair advance; C grows linearly (`step++` per `kStepIncr=128` bytes, `lib/compress/zstd_fast.c:_start`) — same problem, zstdx-chosen curve justified against its denser tables.
- Zero-copy slice architecture: the match window borrows the caller's buffer via raw pointer (`crates/zstdx/src/encoding/match_generator/mod.rs:adopt_window`/`ExtWindow`, driven by `crates/zstdx/src/encoding/frame_compressor.rs:compress_slice_to_vec`), eliminating the read pass, window compaction and window allocation; C always copies input into the internal window (`lib/compress/zstd_compress.c:ZSTD_window_update`); byte-identity between streaming and slice paths is asserted in tests.
- Window policy: the frame window rides the per-level `LEVEL_PARAMS` row (W19-W26), and LDM-carrying rows deliberately declare a wider frame window than the parser's search domain — `chain_reach` pins the tree/chain walk at the stock row window while LDM candidates carry the distance classes beyond it (`crates/zstdx/src/encoding/match_generator/params.rs:LEVEL_PARAMS`, `chain_reach`); C couples windowLog and search domain, reaching farther only by widening the tables.
- Job prefill indexing is covered under Architecture A (strip indexing style) — the stride constant is shared with C's `fastHashFillStep` but applied to a job-model need C does not have.

### B. zstdx-only

- Job-start seed offset for periodic repeats: prefill scans the strip tail for a position whose 8 bytes plus 48 backward bytes agree with the anchor (`crates/zstdx/src/encoding/match_generator/mod.rs:acquire_seed`/`seed_scan`/`SEED_AGREE`) and installs its distance as a direct probe; three seed emissions rotate `rep` onto the period, with an 8192-probe retirement budget (`SEED_MATCHES`/`SEED_BUDGET`); C has nothing analogous — on clumped periodic data its single-probe slots are buried by recent same-hash recurrences.
- AVX-512 kernels inside the matcher: occupancy-mask seed scan over 8 overlapping 64-byte loads per 64-candidate block (`crates/zstdx/src/encoding/match_generator/gates.rs:seed_scan_avx512`) and non-temporal streaming table clears above 4 MiB of slots (`crates/zstdx/src/encoding/match_generator/tables.rs:clear_table_avx512`); official front-end SIMD is limited to the row-hash tag compare (`lib/compress/zstd_lazy.c:ZSTD_row_getMatchMask`, SSE/NEON/RVV) — no AVX-512, no streaming stores anywhere in `lib/compress`.
- Packed single-stream sequence collection: one 24-byte `SeqWord` per sequence (ll/ml/of codes + pre-merged add-bits + width; a 16-byte pack was measured and rejected — see negative.md), consumed by table selection, table description and bitstream without materializing raw triples (`crates/zstdx/src/encoding/seq_codes.rs:pack_seq`, fused histogram pass in `crates/zstdx/src/encoding/block_enc/compressed.rs:choose_tables_fast`); C's `SeqStore_t` stores raw (offBase, ll, ml) triples and recomputes codes later (`lib/compress/zstd_compress_internal.h:ZSTD_storeSeq`, `lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences`).
- Zero-sequence block bypass: literals stay in the window and the block encoder reads them directly, with an early Raw verdict from the sampled entropy gate before any encode-and-discard writes (`crates/zstdx/src/encoding/block_enc/compressed.rs:compress_block`); C routes every block through the seqStore/literal buffer (`lib/compress/zstd_compress.c:ZSTD_buildSeqStore`).
- Sampled incompressibility gate: strided ~1024-point literal sample with Miller-Madow bias correction, distinct>208 prescreen, sticky `gate_hold` across blocks; a dictionary-seeded stream drops the flat description weight from the reject floor since its candidate is treeless (`crates/zstdx/src/encoding/block_enc/compressed.rs:sampled_gate_rejects`); C's only analogue is the `suspectUncompressible` hint (`lib/compress/zstd_compress.c:ZSTD_compressLiterals`), without sampling or an entropy-floor estimator.
- Fastest-tier table pressure as a first-class tuning axis: 2^15 entries (H15 rows), dual-anchor sparse indexing of long matches (`crates/zstdx/src/encoding/match_generator/tables.rs:TableEmit::emit`, ≤16 B dense / else start+2 & end-2), newest-wins proximity bias — a measured redesign of C's fill policy (`lib/compress/zstd_fast.c:_match`, mls=7, 2^14-2^16 table); analysis in `docs/src/dev/perf/matchers.md`.
- Fused checksum absorption: the RLE uniformity scan runs XXH64 rounds inline, raw-block copies hash while copying, with a sidecar-thread offload (`crates/zstdx/src/encoding/levels/fastest.rs:compress_fastest`, `crates/zstdx/src/encoding/checksum.rs:BlockChecksum`/`SliceChecksum::Offload`); C hashes frame content in separate passes (`lib/compress/zstd_compress.c:XXH64_update`) — topology details under Architecture A.

### C. Gaps vs. official zstd

- Row-hash matchfinder: per-row byte tags + head index, cached incremental hashing, salted epochs, SIMD tag masks, auto-selected for greedy/lazy/lazy2 (`lib/compress/zstd_lazy.c:ZSTD_RowFindBestMatch`/`ZSTD_row_getMatchMask`/`ZSTD_resolveRowMatchFinderMode`); zstdx's lazy band (rows 5-12) uses hash chains only, with a cold-start DUBT head on row 9.
- Content-adaptive pre-split: the 2-byte-hash fingerprint splitter cuts the raw input before parsing, auto-enabled for btopt+ W≥17 (`lib/compress/zstd_preSplit.c:ZSTD_splitBlock`); zstdx parses whole 128 KiB blocks and only re-splits post-parse (`crates/zstdx/src/encoding/block_enc/split.rs`, a port — see Similarities).
- Input-size profile rows: 4 srcSize profiles per level in `lib/compress/clevels.h:ZSTD_defaultCParameters`, selected by `ZSTD_getCParams`, can downgrade the strategy row plus negative levels; zstdx keeps one row per level with runtime shrinking of window/hash/chain logs for known sizes (`crates/zstdx/src/encoding/match_generator/params.rs:adjust_params`) — the strategy row itself never downgrades, and negative levels clamp to Fastest.
- Dictionary-aware compression beyond the ST content load: noDict/dictMatchState/extDict/dedicatedDictSearch template modes for every strategy (`lib/compress/zstd_fast.c:ZSTD_compressBlock_fast_dictMatchState_generic`, `lib/compress/zstd_lazy.c:ZSTD_dedicatedDictSearch_lazy_search`, `ZSTD_count_2segments` plumbing); zstdx encodes with dictionaries on the single-threaded paths only (`crates/zstdx/src/encoding/dictionary.rs:reset_with_dictionary` seeds match history + entropy tables), without the dict-specialized matcher templates, and MT encode falls back to ST.
- Greedy/lazy spectrum granularity: official levels 5-12 sweep three parsers (greedy→lazy→lazy2) with searchLog 3-6 and targetLength 0-32; zstdx compresses the band into one chain parser at depths 4-32 (rows differ by depth only), and lacks `lazySkipping` insert suppression (`lib/compress/zstd_lazy.c:ZSTD_insertAndFindFirstIndex_internal`) — partially superseded by the miss-step growth.

## Entropy coding

### A. Own approach to a shared problem

- NCount writer bookkeeping: zstdx assembles the description in a 64-bit register accumulator flushed as unaligned u64 stores, with `threshold`/`nb_bits` tracking ilog2(remaining) incrementally instead of a per-symbol lzcnt (`crates/zstdx/src/fse/fse_encoder.rs:FSETable::write_table`); official threads the same ladder bit-by-bit through the BitStream (`lib/compress/fse_compress.c:FSE_writeNCount_generic`) — same wire, vectorized bookkeeping.
- NCount reader: zstdx reads bit-at-a-time through its forward `crates/zstdx/src/bit_io/bit_reader.rs:BitReader`, skipping zero runs 2 bits at a time (`crates/zstdx/src/fse/fse_decoder.rs:read_probabilities`); official parses a forward 32-bit LE window, decides width with `(bitStream & (threshold-1)) < max`, and consumes zero runs up to 12 groups per iteration via `countTrailingZeros32` (`lib/common/entropy_common.c:FSE_readNCount_body`).
- Huffman encoder bit accumulation: zstdx inserts codes at the bottom of the accumulator and consumes input in reverse via `rchunks(4)`, writing output forward (`crates/zstdx/src/bit_io/bit_writer.rs:BitWriter::write_packed_codes_rev`); official keeps code values in the top bits of a size_t container with per-tableLog unroll factors and two-container double-buffering (`HUF_zeroIndex1`/`HUF_mergeIndex1`) breaking the dependency chain; zstdx instead batches 4 symbols per container fill (`lib/compress/huf_compress.c:HUF_addBits`/`HUF_compress1X_usingCTable_internal_body_loop`).
- Huffman encoder table format: zstdx stores `packed: [u16; 256]` as `(code << 4) | num_bits` plus a `(u32,u8)` tuple vector (`crates/zstdx/src/huff0/huff0_encoder.rs:HuffmanTable`); official stores one `HUF_CElt` size_t per symbol, value pre-shifted to the container top, enabling branch-free `HUF_addBits` (`lib/compress/huf_compress.c:HUF_setValue`/`HUF_getValueFast`).
- Literal incompressibility pre-check: zstdx computes the exact Shannon bound from one shared histogram and rejects when `entropy_bits + description + total*0.02 >= total*8`, with a distinct-symbol bound short-circuiting the log2 loop; a dictionary-seeded table drops the description term since its leading candidate is treeless (`crates/zstdx/src/encoding/block_enc/compressed.rs:compress_literals`/`entropy_bound_bits`); official uses a max-count heuristic `largest <= (srcSize >> 7)+4` and `ZSTD_minGain` (`lib/compress/huf_compress.c:HUF_compress_internal`, `lib/compress/zstd_compress_internal.h:ZSTD_minGain`).
- X1 DTable shape and lifetime: zstdx sizes the table naturally at `1 << max_bits` (any log 1..=11) and keeps a packed u16 mirror `(symbol<<8)|num_bits` for single-load decode (`crates/zstdx/src/huff0/huff0_decoder.rs:HuffmanTable.packed`); official rescales weights up to `HUF_DECODER_FAST_TABLELOG=11` and fills 2-byte `HUF_DEltX1` entries with U64 quad stores (`lib/decompress/huf_decompress.c:HUF_rescaleStats`/`HUF_DEltX1_set4`).
- Fast-loop applicability: zstdx's ported loops run at any tableLog (`index = bits >> (64−tl)`) with per-iteration bound re-checks and a scalar tail sharing reader state (`crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved`/`finish_streams`); official requires `dtLog == 11` and ≥8 bytes per stream else falls back to the generic body (`lib/decompress/huf_decompress.c:HUF_DecompressFastArgs_init`).
- Sequence-code precomputation locus: zstdx computes all three codes + add-bit payloads once at match-emission time into packed `SeqWord`s (`crates/zstdx/src/encoding/seq_codes.rs:pack_seq`); official stores raw (llBase, mlBase, offBase) in `SeqDef` and computes codes per sequence inside the encode loop (`lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body`).

### B. zstdx-only

- Batched literal-code writer: groups of 4 symbols per container fill, flushed below 8 pending bits so four ≤12-bit codes always fit, one unaligned u64 store per flush, overshoot snapped by `set_len` (`crates/zstdx/src/bit_io/bit_writer.rs:write_packed_codes_rev`, with a BMI2 dual variant `write_packed_codes_dual_bmi2`; bit-identity covered by the `packed_codes_rev_matches_write_bits` test); official encodes strictly one `HUF_addBits` per symbol.
- Flat-alphabet fast path: uniform code-length detection enables a two-symbols-per-byte bulk packer with an AVX-512VBMI kernel — 64 symbols/iteration via a 256-entry LUT (`permutex2var_epi8` pair) + bit-7 `mask_blend` (`crates/zstdx/src/bit_io/bit_writer.rs:write_uniform4_bulk`/`uniform4_pack_avx512`; docs: skewed instructions −48%, throughput +43%); official has no SIMD on the encode side (BMI2 attribute only).
- AVX-512 exact histogram for ≤16-symbol alphabets: 16 slot broadcasts × `cmpeq_epi8_mask`+popcnt, the popcount coverage sum doubling as a 17th-symbol detector with cold scalar fallback (`crates/zstdx/src/encoding/block_enc/compressed.rs:histogram_small_alpha_avx512`); official's non-SVE path is purely scalar 4-lane (`lib/compress/hist.c:HIST_count_parallel_wksp`).
- Strided Miller-Madow sampling gate (see Encoder B) also drives the literals path: ~1024 stride samples, entropy estimate + bias correction, rejects only near ≥8 bits/byte (`crates/zstdx/src/encoding/block_enc/compressed.rs:sampled_gate_rejects`); official samples only first+last 4096 bytes with a largest-count test (`lib/compress/huf_compress.c:HUF_compress_internal`).
- Fused three-histogram single pass: ll/ml/of counts filled in one traversal of the packed code words (`crates/zstdx/src/encoding/block_enc/compressed.rs:choose_tables_fast`; docs `6690a05`); official runs three separate `HIST_countFast_wksp` passes (`lib/compress/zstd_compress.c`).
- Combined bit pushes in the sequence encoder: three state-transition groups concatenated into one ≤36-bit value, then transitions+add-bits merged into a single ≤56-bit push, accumulator held in locals via `writer.hot_state()` (`crates/zstdx/src/encoding/block_enc/compressed.rs:encode_sequences`/`hot_push_raw`; docs: json −0.4% instructions); official issues up to six separate `BIT_addBits` calls per sequence (`lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body`).
- Decode-side merged table arena: all three packed FSE tables in one allocation at fixed slot offsets (`LL_SLOT=0`, `ML_SLOT=1<<LL_MAX_LOG`, `OF_SLOT=...`), addressed through a single base pointer, plus a pre-shifted bit window (`win = bits << consumed`, two shifts per read) and whole-loop BMI2 runtime dispatch (`crates/zstdx/src/decoding/sequence_section_decoder.rs:pack_tables`/`decode_sequences_impl_bmi2`); official keeps three independent `ZSTD_seqSymbol*` pointers (`lib/decompress/zstd_decompress_block.c:ZSTD_decodeSequence`).
- X2 pairability gate: the double-symbol table is built only when the pairable share of code space is ≥ ~80% (`eligible_slots * 5 < 4 << 11` keeps X1, `crates/zstdx/src/huff0/huff0_decoder.rs:build_x2_table`; docs: skewed.zst1 +43% by avoiding X2 on unpairable tables); official always builds whatever `HUF_selectDecoder` picked (`lib/decompress/huf_decompress.c:HUF_readDTableX2_wksp`).
- no-std log2: linear-mantissa approximation (error < 0.086) for every entropy/cost estimate (`crates/zstdx/src/fse/fse_encoder.rs:approx_log2`), tolerated by margin-based comparisons; official uses integer fixed-point cost models only (`lib/compress/zstd_compress_sequences.c:kInverseProbabilityLog256`).
- Float Shannon cost models: repeat-mode cost priced exactly through the previous table's per-symbol bits (`repeat_bit_cost` via `FSETable::symbol_bit_cost`), fresh-table cost estimated as the Shannon bound plus a description term (`entropy_bound_bits`/`description_bits`); official compares basic/repeat/fresh with accuracy-8 fixed point (`ZSTD_entropyCost`/`ZSTD_fseBitCost`/`ZSTD_crossEntropyCost`) — the float/fixed split has no counterpart on the other side.
- Compile-time table generation: `const fn`-generated LUTs and metadata arrays surface encoding errors at compile time (`crates/zstdx/src/encoding/seq_codes.rs:ll_meta`/`ml_meta`/`ll_code_lut`/`ml_code_lut`); official uses hand-written static arrays (`lib/common/zstd_internal.h:LL_bits`, `lib/compress/zstd_compress_internal.h:LL_Code`/`ML_Code`).

### C. Gaps vs. official zstd

- Huffman depth probing: `HUF_flags_optimalDepth` (enabled at strategy ≥ `HUF_OPTIMAL_DEPTH_THRESHOLD`) estimates `HUF_estimateCompressedSize + hSize` for every candidate tableLog and picks the best (`lib/compress/huf_compress.c:HUF_optimalTableLog`, `lib/compress/zstd_compress_literals.c`); zstdx builds once at the format maximum 11 (`crates/zstdx/src/huff0/huff0_encoder.rs:build_lengths_into`).
- Strategy-scaled literal thresholds: `ZSTD_minLiteralsToCompress` (8..64 bytes by strategy) and `ZSTD_minGain = (srcSize >> minlog) + 2` with minlog 6..7 (`lib/compress/zstd_compress_literals.c`) vs zstdx's fixed 1024-byte gate floor and flat 2% margins (`crates/zstdx/src/encoding/block_enc/compressed.rs:compress_literals`).
- ctz-accelerated NCount parsing — see A; zstdx's per-bit reader is tolerable only because table headers are small (`crates/zstdx/src/fse/fse_decoder.rs:read_probabilities` vs `lib/common/entropy_common.c:FSE_readNCount_body`).
- Hand-written x86-64 asm Huffman decode loop: `lib/decompress/huf_decompress_amd64.S` (~766 lines) dispatched under `ZSTD_ENABLE_ASM_X86_64_BMI2`; zstdx has no asm — its Rust loop does 1 table load + 2 shifts vs the asm's 3 dtable loads, with claimed memport/ALU-bound parity (`docs/src/dev/perf/decoding.md`; perf claim unverified here).
- X2 fast-loop register scheduling: official splits into a 3-way variant on x86 and 4-way on aarch64 (`lib/decompress/huf_decompress.c:HUF_4X2_3WAY`/`HUF_4X2_4WAY`); zstdx always decodes column-major 4 streams × 5 lookups (`crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved_x2`).
- SVE2 histogram: `lib/compress/hist.c:HIST_count_6_sve2` uses `svhistseg_u8` per-16-byte segment histograms on aarch64; zstdx's SIMD histogram is x86-AVX-512 only with scalar fallback elsewhere (`crates/zstdx/src/encoding/block_enc/compressed.rs:histogram_literals`).
- Predefined-vs-dynamic cross-entropy at high strategies: C prices the predefined distribution against the normalized counts with `ZSTD_crossEntropyCost` for strategy ≥ lazy (`lib/compress/zstd_compress_sequences.c:ZSTD_selectEncodingType`); zstdx keeps the fast-strategy heuristic gate outside dictionary-seeded streams, and its fresh-table side is a Shannon bound rather than a through-the-table cost (`crates/zstdx/src/encoding/block_enc/compressed.rs:select_from_counts`).
- Superblock re-entropy coding: multiple blocks re-emitted as one superblock with entropy tables shared/rewritten across sub-blocks (`lib/compress/zstd_compress_superblock.c`) — nothing comparable in zstdx; see Architecture C.
- longOffsets two-part offset emission for offsets larger than the accumulator budget (`lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body` longOffsets branch); zstdx relies on its 56-bit-capped combined push — equivalent wire for its ≤W26 windows, explicit long-offset mode absent.

## Decoder

### A. Own approach to a shared problem

- Ring-buffer execution path (ruzstd heritage): hand-written ring with modulo-free `wrap_add` and four layout cases, now confined to dictionary frames; `repeat_in_chunks` doubling matches libzstd's semantics but not its code (`crates/zstdx/src/decoding/ringbuffer.rs:RingBuffer`, `crates/zstdx/src/decoding/decode_buffer.rs:repeat_pre_reserved`/`repeat_in_chunks`, `crates/zstdx/src/decoding/frame_decoder.rs:decode_blocks` vs `lib/decompress/zstd_decompress_block.c:ZSTD_execSequence`/`ZSTD_safecopy` — libzstd never uses a ring, always linear `dst` + 3-pointer extDict).
- Window continuity as two-generation virtual address space: `crates/zstdx/src/decoding/flat_buffer.rs:FlatOut`/`FlatView` (`origin/prev_origin/seg_a_end`) makes virtual distances equal physical ones inside the active segment (`dst - offset` is the whole match algebra in `exec_one_flat`), straddling sources pushed to a `#[cold] copy_wrapped_match`; libzstd remaps per sequence at runtime via `ZSTD_checkContinuity` and splits matches across extDict/prefix (`lib/decompress/zstd_decompress_block.c:ZSTD_checkContinuity`).
- Monomorphized wrap/headroom instantiations: `crates/zstdx/src/decoding/sequence_execution.rs:execute_decoded_flat_inner::<NOWRAP, HEADROOM>` compiles the never-wrapped and guaranteed-slack cases to loops without mapping branches or per-sequence wildcopy gates; libzstd has one runtime-checked `ZSTD_execSequence`.
- Pre-shifted bit window: `win = bits << consumed` costs two shifts per read and `bits` is never carried across sequences (`crates/zstdx/src/decoding/sequence_section_decoder.rs:read`/`reload`); official carries `ptr`, `bitContainer`, `bitsConsumed` (`lib/common/bitstream.h:BIT_lookBitsFast`).
- Batched field extraction: all three add-bit fields read in ONE window read (`sum ≤ 31` ⇒ no mid-sequence reload; larger sums take the cold fallback) and all three state transitions in one 26-bit read, split by shifts+bzhi (`crates/zstdx/src/decoding/sequence_section_decoder.rs:decode_step`); official reads of/ml/ll bits with separate `BIT_readBitsFast` calls and conditional reload guards (`lib/decompress/zstd_decompress_block.c:ZSTD_decodeSequence`).
- Branch-free repcode resolution: slot index `code-1+ll0`, masked garbage slot load, rotation as selects (`crates/zstdx/src/decoding/sequence_execution.rs:do_offset_history`) vs C's branch tree (`ofBits > 1` / `LIKELY(ofBits == 0)` / `temp -= !temp`); the aarch64 variant of `ZSTD_decodeSequence` is closer but still branches on `ofBits`.
- Fused-loop state promotion: `SeqDecoder` destructured into loop locals in `execute_decoded_flat_inner` (SROA; fields written back only on success) vs `seqState_t` passed by pointer into `ZSTD_decodeSequence` (state stored through memory each call).
- Inline fixed-width copies: unaligned u64/u128 load-store motivated by measured libc PLT overhead of variable-length memmove (`crates/zstdx/src/decoding/sequence_execution.rs:copy8`/`copy16`) vs `lib/common/zstd_internal.h:ZSTD_copy16` (C compilers resolve memcpy inline, no PLT).
- Predefined-table caching: built once, then only repacked when changed (`crates/zstdx/src/decoding/scratch.rs:FSEScratch::{ll,ml,of}_predefined`) vs official's static const `LL_defaultDTable` etc., never built (`lib/decompress/zstd_decompress_block.c`).
- X1 fast loop indexed by the table's real log (`crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved`, tl ∈ 1..=11) vs official padding the table to log 11 and refusing the fast loop otherwise (see Entropy A); the X2 gate refinement is shared with Entropy B.
- Multi-frame stream plumbing: peek 4-byte magic, replay prefix, clean-EOF vs first-frame-EOF distinction, reusable `FrameDecoder` reset per frame (`crates/zstdx/src/decoding/frame_source.rs:start_frame`/`PrefixedReader`) vs `ZSTD_decompressStream`'s stage machine handling skippable frames inline (`lib/decompress/zstd_decompress.c`).

### B. zstdx-only

- Parallel decode — libzstd has NO decode-side MT (verified: no thread/pool/parallel/worker references under `lib/decompress/`; `lib/common/pool.c` serves only compress-side zstdmt). Design: header-only prescan cuts the input at restart points (blocks whose literals are not Treeless and no FSE stream is Repeat mode — `crates/zstdx/src/decoding/mt.rs:scan`/`restart_point`); stage A worker pool decodes literals+sequences into staging buffers with tables rebuilt fresh per segment (`mt.rs:decode_segment`, per-worker `SegmentScratch`); stage B executes matches on the calling thread in input order, carrying `offset_hist` across segments (`mt.rs:execute_segment`), with a piece-parallel variant splitting stage B on the encoder's MT job grid for ramp-guaranteed frames (`crates/zstdx/src/decoding/mt_pieces.rs`); staging bounded by a `consumed` atomic, worker panics captured via `catch_unwind` + poison mutex; falls back to sequential for dictionaries/small inputs/no second restart point.
- HEADROOM specialization: when the allocation provably holds block-max + 16 beyond the cursor (`crates/zstdx/src/decoding/flat_buffer.rs:WILDCOPY_SLACK` guaranteed by `ensure_block_space`), literal and match copies wildcopy unconditionally with zero per-sequence bounds work (`crates/zstdx/src/decoding/sequence_execution.rs:exec_one_flat`); libzstd always keeps the `oMatchEnd > oend_w` gate in `ZSTD_execSequence`.
- Bulk retry contract: capacity doubling on `TargetTooSmall` with a 64 KiB min hint (`crates/zstdx/src/bulk.rs:decompress`/`decompress_with`) vs libzstd's one-shot model where the caller must size `dst` (aided by `ZSTD_getFrameHeader`/`ZSTD_decompressBound`) — convenience layer, listed for completeness.
- no_std decoding core: the whole pipeline (ring + flat paths) builds without std, MT and BMI2 dispatch behind `#[cfg(feature = "std")]` (`crates/zstdx/src/decoding/`, `crates/zstdx/src/io_nostd.rs`).

### C. Gaps vs. official zstd

- Literals stored inside the destination buffer: in one-shot mode literals land after the current block in `dst`, else split with a tail in `litExtraBuffer`, consumed split-buffer-first so output never catches the literal buffer (`lib/decompress/zstd_decompress_block.c:ZSTD_allocateLiteralsBuffer`/`ZSTD_decompressSequences_bodySplitLitBuffer`); zstdx always decodes literals into a separate scratch `Vec` (`crates/zstdx/src/decoding/block_decoder.rs:parse_sections` → `literals_buffer`).
- Long-offset / prefetch sequence decoder: `ZSTD_decompressSequencesLong_body` (selected by long-offset share and `ddictIsCold`) prefetches future match data, plus 32-bit long-offset bit splitting (`lib/decompress/zstd_decompress_block.c`, `LONG_OFFSETS_MAX_EXTRA_BITS_32`); zstdx has a single fused loop, no prefetch variant, and assumes a 64-bit `usize` (the `sum ≤ 31` batching and u64 window are 64-bit-only).
- Hand-written Huffman asm — see Entropy C; decoder-side SIMD reach in zstdx is 16-byte u128 copies (SSE movdq codegen) + BMI2 runtime dispatch (`crates/zstdx/src/decoding/sequence_section_decoder.rs:decode_sequences`, same pattern as C's `DYNAMIC_BMI2`); no AVX-512 anywhere in the zstdx decoder (verified by grep).
- DSB loop alignment: `ZSTD_decompressSequences_body(SplitLitBuffer)` embeds `.p2align` directives tuning the decode loop's DSB/MITE behavior; zstdx has no alignment directives.
- In-place / caller-managed-window decode: `ZSTD_decompressFrame` clamps `oBlockEnd` when `ip ≥ op` (in-place), `ZSTD_checkContinuity` lets each call present a fresh disjoint output buffer serving as extDict, and `ZSTD_d_stableOutBuffer` keeps one output buffer across streaming calls (`lib/decompress/zstd_decompress.c`); zstdx assumes source/target are distinct buffers.
- Checksum opt-out knob: verification itself matches C's default on every decode path (compared digest vs stored word, `FrameDecoderError::ChecksumMismatch` — ST folds the compare into the trailer read in `crates/zstdx/src/decoding/frame_decoder.rs:verify_frame_checksum`, MT post-passes over the assembled output in `crates/zstdx/src/decoding/frame_checksum.rs`); what C still has exclusively is `ZSTD_d_validateChecksum` to disable it.
- Zero-copy DDict: `ZSTD_copyDDictParameters` points prefix/virtual/dict pointers straight at the dictionary bytes and table pointers at prebuilt tables inside the `ZSTD_DDict`, plus a multiple-DDict hash set (`lib/decompress/zstd_ddict.c`, `lib/decompress/zstd_decompress.c:ZSTD_DDictHashSet`); zstdx copies entropy tables and content into the scratch per frame (`crates/zstdx/src/decoding/scratch.rs:DecoderScratch::init_from_dict`), keys dictionaries in a `BTreeMap<u32, Dictionary>` (`crates/zstdx/src/decoding/frame_decoder.rs:dicts`), and dictionary frames forfeit the flat fast path.
- aarch64-specific tuning: single-load `ZSTD_seqSymbol` via memcpy + local prevOffset registers in `ZSTD_decodeSequence`, `PREFETCH_L1(match)` in `ZSTD_execSequence`; zstdx has no arch-specific sequence-path tuning beyond BMI2.
- Streaming input buffering: libzstd's streaming decoder copies input into an internal `inBuff` for header atomicity while zstdx reads straight from the `Read` impl and rewinds parsed-but-unconsumed block headers (`crates/zstdx/src/decoding/frame_decoder.rs:decode_from_to` `before_header` restore).

## Architecture and systems

### A. Own approach to a shared problem

- Job scheduler: bulk MT runs fresh scoped threads per call with an atomic-counter work queue over a fixed slot array plus condvar-ordered assembly on the calling thread (`crates/zstdx/src/encoding/mt.rs:compress_slice_mt` — `std::thread::scope`, `next_job: AtomicUsize`, `slots: Vec<Mutex<Option<Vec<u8>>>>`, `ready: Condvar`; `crates/zstdx/src/stream/encoder_mt.rs` drives the streaming queues) vs libzstd's long-lived worker pool created once per mtctx with a circular job queue and blocking pops (`lib/common/pool.c:POOL_create`/`POOL_thread`, `lib/compress/zstdmt_compress.c:ZSTDMT_createJobsTable`, `nbJobs = nbWorkers+2`).
- Warm state pooling: a thread-local bulk pool (`crates/zstdx/src/encoding/frame_compressor.rs:SLICE_STATE`) survives across calls on the same thread, while streaming workers lease persistent threads from a global pool that carry their `CompressState` across encoders and bursts (`crates/zstdx/src/stream/mt_pool.rs:THREAD_POOL`/`STATE_POOL`, depth-capped, idle-retired); libzstd has one always-warm arrangement (persistent factory + cctxPool).
- Streaming-MT driving policy: zstdx buffers into one contiguous `[history strip][pending]` buffer and fires a burst only once `max(workers,2)` job-sized slices accumulated, encoding the whole burst in parallel (`crates/zstdx/src/stream/encoder_mt.rs:burst_jobs`/`write`); libzstd creates a job as soon as `inBuff.filled >= targetSectionSize` and flushes completed-job output incrementally with per-job progress (`job->dstFlushed`, condvar signaled mid-job every 4 blocks — `lib/compress/zstdmt_compress.c:ZSTDMT_compressStream_generic`).
- Job sizing: zstdx divides the known input evenly targeting 2× workers (`len.div_ceil(workers*2)`, floor `max(1 MiB, overlap)`, cap 1 GiB — `crates/zstdx/src/encoding/mt.rs:job_size_for`); libzstd uses a fixed streaming section size `1 << max(20, windowLog+2)` clamped to [512 KB, 1 GB], independent of input length, with a user-facing `ZSTD_c_jobSize` knob zstdx lacks (`lib/compress/zstdmt_compress.c:ZSTDMT_computeTargetJobLog`).
- Overlap policy: zstdx uses the level's whole window as the overlap strip (per a measured reach choice), justified by fully indexing it (`crates/zstdx/src/encoding/mt.rs:compress_slice_mt`, `crates/zstdx/src/stream/encoder_mt.rs:overlap`); libzstd defaults to a fraction via overlapLog (window/8 for fast..lazy, up to full window only for btultra2), overridable via `ZSTD_c_overlapLog` (`lib/compress/zstdmt_compress.c:ZSTDMT_computeOverlapSize`).
- Strip indexing style: fast/dfast prefilled on a stride-3 sparse grid (the stride constant is libzstd's `fastHashFillStep`, `lib/compress/zstd_fast.c`) and chain fills run under the offset-gain store gate — an explicit deviation from libzstd's dense `ZSTD_loadDictionaryContent` fill, justified because zstdx strips are the full window (`crates/zstdx/src/encoding/match_generator/mod.rs:prefill_window`/`FillGrid` vs `lib/compress/zstd_compress.c:ZSTD_fillHashTable`/`ZSTD_updateTree`).
- Determinism-by-construction for pooled state: per-job head tables are cleared and the opt tables' origin coordinate advanced precisely because pooled states carry residue that would make output depend on worker scheduling (`crates/zstdx/src/encoding/match_generator/mod.rs:fill_window_grid`); whether libzstd performs equivalent targeted clears per job is unverified (its `ZSTD_compressBegin_*` re-inits match state).
- Checksum topology: zstdx selects among inline / offloaded / off backends behind one `BlockChecksum` trait with a 256 KiB threshold for the sidecar thread (`crates/zstdx/src/encoding/checksum.rs:SliceChecksum::new`, `ASYNC_MIN_INPUT`); in MT the whole input is hashed on the calling thread while workers compress (bulk) or interleaved during burst assembly (streaming) (`crates/zstdx/src/encoding/mt.rs:compress_slice_mt`, `crates/zstdx/src/stream/encoder_mt.rs:encode_jobs`) vs libzstd serializing absorption in job order through the SerialState (`lib/compress/zstdmt_compress.c:ZSTDMT_serialState_genSequences`) and zeroing the checksum flag for `jobID != 0`; the fused absorb into raw-block copies and RLE scans is covered under Encoder B.
- Streaming-encode state machine: input staged into a fixed buffer, whole blocks encoded as they fill, encoded bytes handed out from one output Vec (`crates/zstdx/src/stream/encoder_core.rs:FrameEncoderCoreSt::write`/`finish`/`split_output`) vs libzstd's stage machine with input buffering, block loop and stable-in/out bookkeeping (`lib/compress/zstd_compress.c:ZSTD_compressStream2`, `cctx->streamStage`).
- Streaming-decode framing on the write side: zstdx pre-parses the 3-byte block header to compute exactly how many staged bytes the next block plus trailer needs, because the inner `FrameDecoder` poisons itself on starved reads (`crates/zstdx/src/stream/write.rs:Decoder::next_block_need`/`pump`) vs libzstd copying into an internal `inBuff` decoded across explicit stages (`lib/decompress/zstd_decompress_internal.h:ZSTD_dStreamStage`).
- Parameter/level architecture: a closed enum of five strategy forms with a const 23-row `LEVEL_PARAMS` ladder indexed by numeric level and runtime shrinking of window/hash/chain logs to a known source length (`crates/zstdx/src/level.rs:Level::approximate_zstd`, `crates/zstdx/src/encoding/match_generator/params.rs:LEVEL_PARAMS`/`adjust_params`) vs 22 numeric levels × 4 input-size classes of full cParam tuples with the same shrinking done in `lib/compress/zstd_compress.c:ZSTD_adjustCParams_internal` (`lib/compress/clevels.h:ZSTD_defaultCParameters`).
- MT engagement demotion: zstdx silently falls back to the single-thread path for small inputs (<2 MiB), `workers < 2`, `Level::Uncompressed`, or single-core, byte-identical to the ST entry point (`crates/zstdx/src/encoding/mt.rs:compress_slice_mt`, test `small_inputs_fall_back_identically`); libzstd honors `nbWorkers` as configured (only the CLI decides `-T1` vs `--single-thread`).
- Error model: Rust `Result` + `#[non_exhaustive]` thiserror enums, an umbrella `Error` (Frame/Dictionary/Io/Unsupported/Parameter) convertible into io::Error for std and no_std, with "API ahead of implementation" encoded as a `Feature` enum value (`crates/zstdx/src/error.rs:Error`/`Feature`/`into_io`) vs C `size_t` error codes with `ZSTD_isError`/`ZSTD_getErrorName` and `RETURN_ERROR_IF` macros (`lib/zstd.h:ZSTD_getErrorCode`).
- no_std support: a minimal io module (Read/Write traits, `ErrorKind`) lets the whole library build without std, MT gated off entirely (`crates/zstdx/src/io_nostd.rs`, `crates/zstdx/src/stream/encoder_core.rs:FrameEncoderCore::new` returns `Error::Unsupported`) vs libzstd having no io layer at all (caller-supplied buffers, `lib/common/zstd_deps.h` for allocation only).

### B. zstdx-only

- Parallel decompression by restart-point segmentation — the decode-side design is described under Decoder B; from the systems side it is engaged via `crates/zstdx/src/bulk.rs:decompress_to_buffer_with` (`DecoderOptions::threads`) and relies on exactly the block shape MT/job encoders emit at job boundaries.
- Offloaded frame-checksum thread: a dedicated "zstdx-xxh64" worker consuming an SPSC ring of posted byte ranges (512 slots), spin-then-park handoff with a 32768-iteration budget so no post is missed, multiple concurrent frames multiplexed by state ids over one ring, Drop drains pending posts before the input can die (`crates/zstdx/src/encoding/async_checksum.rs:AsyncChecksum`/`Producer::post`/`run`); nothing similar exists in `lib/` (checksum always inline, see A).
- Burst-deterministic streaming job grid: streaming MT jobs are cut on boundaries derived from absolute stream offsets alone (pledged: fixed `job k = job_start + k*job_size`; unpledged: a growing schedule sizing the job at offset `o` for a `4o`-byte input), so without explicit flushes the frame bytes are independent of how writes were chunked; flush is the documented exception that re-grids (`crates/zstdx/src/stream/encoder_mt.rs:JobGrid`/`job_end`/`flush_block`); libzstd's streaming MT output inherently depends on how `ZSTD_compressStream2` calls arrive (`lib/compress/zstdmt_compress.c:ZSTDMT_compressStream_generic`).
- Pledged-stream/bulk byte identity: the streaming MT core shares `job_size_for` with the bulk path and holds back the final pledged-grid job until `finish()`, so a stream written exactly to its pledge is byte-identical to bulk MT output (hold-back lapses on pledge overshoot via the `pos <= n` guard) (`crates/zstdx/src/stream/encoder_mt.rs:pending`, `docs/src/dev/perf/mt-stream.md`); no equivalent guarantee exists in `lib/` (no shared-sizing mechanism between `ZSTDMT_initCStream_internal` and one-shot compression).
- Periodic-repeat seed at job start — mechanics under Encoder B; systems relevance: fixes periodic corpora whose period exceeds what table-only matching reaches, where libzstd relies on dense dict/table fill (no counterpart in `lib/compress/`).
- AVX-512 micro-kernels with runtime dispatch inside the codec — matcher seed scan and NT table clears under Encoder B, histogram and bit-writer kernels under Entropy B; libzstd's own kernels use SSE/AVX2-era intrinsics with compile-time gating (the only AVX-512 in `lib/` is the vendored `lib/common/xxhash.h` accumulate variant, compile-time `__AVX512F__`).
- Borrowed-window zero-copy slice path — mechanics under Encoder A; driven by `crates/zstdx/src/encoding/frame_compressor.rs:compress_slice_to_vec`, eliminating the window copy, compaction and staging buffer of the classic design (`lib/compress/zstd_compress.c:ZSTD_window_update` into roundBuff).
- Output-shape regression contracts as infrastructure: byte-identity between slice and streaming paths, MT vs ST ratio-loss bounds, cross-run determinism, dump-based cross-build snapshots, and a corruption smoke tool (flipped bytes must error, never panic) (`crates/zstdx/src/encoding/mt.rs:tests` `mt_output_is_deterministic`/`mt_ratio_stays_close_to_single_thread`, `crates/zstdx/src/encoding/frame_compressor.rs:level_ladder_roundtrips`, `crates/zstdx-bench/src/cmd/dump.rs`, `crates/zstdx-bench/src/cmd/corrupt.rs`); libzstd tests via zstreamtest/fuzzers and does not pin encoder byte-determinism as a contract (its MT output is job-schedule dependent).
- Compat shim mirroring the Rust `zstd` crate (libzstd bindings) API on top of the native engine: numeric levels, `io::Result`, `zstd::bulk`/`zstd::stream` module shapes, `set_pledged_src_size`/`include_checksum`/`multithread`/dictionary constructors applied until stream start (`crates/zstdx/src/compat/mod.rs`/`bulk.rs`/`stream.rs:EncoderState`); the C library is itself the native API so no analogous layer exists.
- Executor-agnostic streaming core: single-threaded and burst-MT frame encoders behind one enum with identical interfaces, so read/write wrappers never know which runs (`crates/zstdx/src/stream/encoder_core.rs:FrameEncoderCore` — `Single | Mt`); libzstd switches between `ZSTD_compressStream_generic` and `ZSTDMT_compressStream_generic` inside one function with different buffering layers.

### C. Gaps vs. official zstd

- Superblocks / target compressed block size: re-encoding a group of blocks as sub-blocks sharing one entropy frame, exposed as `ZSTD_c_targetCBlockSize` and CLI `--target-compressed-block-size=` (`lib/compress/zstd_compress_superblock.c:ZSTD_compressSuperBlock`, `lib/zstd.h`, `programs/zstdcli.c:usage_advanced`); no superblock/sub-block machinery anywhere in `crates/zstdx/src/encoding/` (also noted under Entropy C).
- LDM state shared across MT jobs: libzstd serializes the rolling LDM state and table through the job stream so far matches cross job boundaries (`lib/compress/zstdmt_compress.c:ZSTDMT_serialState_reset`/`ZSTD_ldm_generateSequences`); zstdx's LDM (`crates/zstdx/src/encoding/ldm.rs`) arms per job with a prefix-donation probe instead (`crates/zstdx/src/encoding/match_generator/params.rs:LdmArming`), and its window scale tops out at W26 where C's `--long` reaches windowLog 27+.
- Rsyncable job boundaries: rolling-hash synchronization points so compressed output stays stable under insertions (`lib/compress/zstdmt_compress.c:RSyncState_t`/`findSynchronizationPoint`, CLI `--rsyncable`); zstdx job boundaries are purely size-derived (`crates/zstdx/src/encoding/mt.rs:job_size_for`).
- Mid-stream parameter adaptation: changing cParams while compressing (applied to the next job), adaptive level driven by I/O rate, stable in/out buffer modes avoiding copies, `--patch-from` reference prefix compression (`lib/compress/zstdmt_compress.c:ZSTDMT_updateCParams_whileCompressing`, `lib/compress/zstd_compress.c:ZSTD_compressStream2`, CLI `--adapt`/`--patch-from`); zstdx options are fixed at construction — mutation after start is `ParameterError::AlreadyStreaming` (`crates/zstdx/src/options.rs:EncoderOptions`, `crates/zstdx/src/error.rs:ParameterError`, `crates/zstdx/src/compat/stream.rs:EncoderState`).
- Strategy-row selection by source size: C's srcSize profiles can pick a cheaper strategy row and `ZSTD_CParamMode_e` differentiates dict-attach vs standalone (`lib/compress/zstd_compress.c:ZSTD_adjustCParams_internal`/`ZSTD_CCtx_init_compressStream2`, CLI `--stream-size`/`--size-hint`); zstdx shrinks only window/table logs from the pledge (`crates/zstdx/src/encoding/match_generator/params.rs:adjust_params`) — see Encoder C.
- Encode-side dictionary API breadth: CDict objects, attach/load-prefix modes, per-job dict reload in MT, `dedicatedDictSearch` (`lib/compress/zstd_compress.c:ZSTD_CCtx_refCDict`/`ZSTD_CCtx_refPrefix`/`ZSTD_CCtx_loadDictionary`, `ZSTDMT_initCStream_internal`); zstdx supports the plain attach path (`crates/zstdx/src/options.rs:EncoderOptions::dictionary`, CLI `-D`) with matcher-side dict modes and MT dict reload absent — see Encoder C.
- Block/frame splitter controls (`ZSTD_c_blockSplitterLevel`/`ZSTD_c_splitAfterSequences`, experimental params 20/21 in `lib/zstd.h`); zstdx's splitter runs auto on the opt rows with no knobs (machinery itself is ported — see Similarities).
- Incremental job output progress: compressed bytes flushed before a job finishes (`dstFlushed` advanced mid-job, `ZSTDMT_toFlushNow`, `ZSTDMT_getFrameProgression` — `lib/compress/zstdmt_compress.c`); zstdx emits output only per completed job (`crates/zstdx/src/encoding/mt.rs:slots`), trading latency granularity for simplicity.
- User-facing shared thread pool: created once, shared across CCtxs, resizable at runtime (`lib/common/pool.c:POOL_resize`, `lib/zstd.h:ZSTD_createThreadPool`); zstdx's pools are internal (`crates/zstdx/src/stream/mt_pool.rs` — worker leases and states idle-retire after 5 s) with no create/share/resize API, and the bulk path still spawns threads per call.
- CLI tail: format conversion (gzip/xz/lz4), `-l` listing, memory limits, sparse/pass-through, async IO, `-b/-e/-i` benchmarks, training, full `--zstd=` pass-through (`programs/zstdcli.c:usage`/`usage_advanced`); the zstdx CLI covers the core zstd switches (multi-file/recursive/stdin-stdout, `-t` test, `-c/-o/-k/-rm/-f/-T`, levels 1-22, `--fast`, `--ultra`, `-D` dictionaries — `crates/zstdx-cli/src/main.rs`) with clap + tracing/indicatif progress.
- Test/bench infrastructure: decoder corpus generation, stream/CLI/fuzz suites incl. dictionary_round_trip and an external_matchfinder plug-in harness, a regression framework, benchfn-based benchzstd with datagen (`tests/decodecorpus.c`, `tests/zstreamtest.c`, `tests/fuzz/`, `tests/regression/`, `programs/benchzstd.c`); zstdx relies on in-crate Rust tests cross-checking against libzstd itself (dev-dependency interop assertions, fuzz-artifact replay in `crates/zstdx/src/encoding/frame_compressor.rs:fuzz_targets`), seven cargo-fuzz targets (`crates/zstdx-fuzz/fuzz_targets/{encode,encode_stream,decode,decode_dict,fse,huff0,interop}.rs`), and a bench crate with correctness-gated subcommands incl. an interleaved A/B matrix vs the zstd crate (`crates/zstdx-bench/src/main.rs:Command`).
- Partial-output streaming control: caller-owned in/out buffers with per-call pos/size advancement and three end directives allow flush throttling and zero-copy stable buffers (`lib/compress/zstd_compress.c:ZSTD_compressStream2` — `ZSTD_inBuffer`/`ZSTD_outBuffer`/`ZSTD_EndDirective`, decode `ZSTD_d_stableOutBuffer`); zstdx's io-trait wrappers own the buffering (`crates/zstdx/src/stream/write.rs:Encoder::drain`) and expose only write/flush/finish boundaries.
- Recommended-input-size and buffer-expectation protocol: `ZSTD_CStream_InSize`/`OutSize` plus runtime `ZSTD_setBufferExpectations` checks per stage; zstdx exposes only static constants (`crates/zstdx/src/stream/write.rs:Encoder::recommended_input_size` = one block) with no expectation enforcement.

## Summary

- zstdx's structural wins are throughput-shaped: MT decode (absent upstream), fused/packed encode pipelines, borrowed windows, pooled-state determinism, and encoder-side AVX-512 — all leveraged without changing the wire format. The 2026-09-19 full-corpus sweep puts the encoder geo-mean +8.67% denser over 120 cells, decode ST bulk winning 17/18 cells, and decode ST streaming x1.04-1.37 behind on compressible shapes (`docs/src/dev/bench/snapshot.md`).
- Ratio risks now concentrate in a short list of upstream adaptivity: the row-hash matchfinder and the preSplit fingerprint splitter remain zstd-only, and the float Shannon bounds on the fresh-table entropy pre-comparisons cap small-payload decisions vs zstd's exact fixed-point costs.
- The decode gap is narrow but real: zstdx's Rust fast loops sit within ~10% of libzstd's hand-written asm per `docs/src/dev/perf/decoding.md`, while literals-in-dst, prefetch variants, DDict zero-copy and DSB alignment remain unported; the dll-class binary payload is where zstdx's density lead is largest (−8..−13% size from balanced up).
- Feature-completeness gaps are mostly API-level, not format-level: superblocks, preSplit, rsyncable boundaries, mid-stream parameter changes, the dictionary matcher modes, and the CLI/FFI tail are all additive work on an already format-complete codec.
