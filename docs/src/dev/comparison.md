# Comparison with official zstd

zstdx is this repository's pure-Rust zstd implementation. It started as a fork of KillingSpark/zstd-rs (ruzstd) and added a from-scratch encoder in `crates/zstdx/src`, with the CLI in `crates/zstdx-cli` and the benchmark harness in `crates/zstdx-bench`. This page compares it with official zstd v1.6.0, the C reference at `/root/programs/fork/zstd` with the library under `lib/` and the CLI under `programs/`.

The comparison answers where the design departs from the reference, what zstdx adds, and what it still lacks. It covers four domains: encoder front-end, entropy coding, decoder, and systems architecture. Citations name a symbol in `crates/zstdx/src/...` against its counterpart in `lib/...`.

The page records design-level reasoning and a symbol-level index across both trees, and it is re-verified against both trees on major changes rather than kept as a dated snapshot. The authoritative current capability and gap state lives in [status](status.md) and [todo](todo.md).

## Reading this page

Differences fall into three categories, repeated in each domain's sub-sections. Own approach means zstdx solves a problem both sides share with its own approach, including documented ports that deviate. zstdx-only means techniques with no counterpart in official zstd. Gaps means official-zstd techniques that zstdx lacks. Format-mandated machinery is excluded from the differences and appears only under Similarities. That covers wire layout, FSE spread, repcode semantics and block framing.

Two facts hold across both trees. The AVX-512 VBMI kernels are encoder-side only, at `crates/zstdx/src/encoding/block_enc/compressed.rs:histogram_small_alpha_avx512` and `crates/zstdx/src/bit_io/bit_writer.rs:uniform4_pack_avx512`, so the zstdx decoder contains no SIMD beyond 16-byte u128 copies and BMI2 dispatch. The zstdx MT overlap strips run larger than libzstd's default `overlapLog` fraction, because they cover the row's search reach or the whole window on LDM-capture frames. That is a deliberate deviation.

## Similarities

### Format-mandated

- Frame and block framing: header descriptor, window descriptor with 10+exp, dictID and FCS widths, skippable magic 0x184d2a50 to 0x184d2a5f, 3-byte block headers with Raw, RLE and Compressed types and the 128 KiB cap, and the default 128 MiB window limit. zstdx implements it in `crates/zstdx/src/decoding/frame.rs:read_frame_header` and `is_skippable_magic`, `crates/zstdx/src/decoding/block_decoder.rs:read_block_header` and `crates/zstdx/src/decoding/frame_decoder.rs:DEFAULT_MAX_WINDOW_SIZE`. C implements it in `lib/decompress/zstd_decompress.c:ZSTD_getFrameHeader_advanced` and `readSkippableFrameSize`, `lib/decompress/zstd_decompress.c:ZSTD_getcBlockSize`, and `lib/zstd.h:ZSTD_WINDOWLOG_LIMIT_DEFAULT`.
- FSE: spread step `p += (ts>>1)+(ts>>3)+3`, low-probability symbols at table top with value -1, the decode-entry recurrence, the NCount wire format, predefined LL, ML and OF distributions at logs 6, 6 and 5, and RLE routed through a degenerate one-cell table. zstdx code is in `crates/zstdx/src/fse/fse_decoder.rs:build_decoding_table` and `read_probabilities`, `crates/zstdx/src/decoding/sequence_section_decoder.rs:pack_rle_entry`, and `crates/zstdx/src/fse/fse_encoder.rs:LL_DIST`, `ML_DIST` and `OF_DIST`. C code is in `lib/common/fse.h:FSE_TABLESTEP`, `lib/common/fse_decompress.c:FSE_buildDTable_internal`, `lib/common/entropy_common.c:FSE_readNCount_body`, `lib/common/zstd_internal.h:LL_defaultNorm`, and `lib/decompress/zstd_decompress_block.c:ZSTD_buildSeqTable_rle`.
- Sequence coding: LL, ML and OF code ladders with dense LUTs below 64 and 131, the table-modes byte with ll:6, of:4 and ml:2, backward encoding with initial states from the last sequence and the ML to OF to LL flush, and repcode semantics including the ll0 swap. zstdx code is in `crates/zstdx/src/encoding/seq_codes.rs:LL_META` and `ML_META`, `crates/zstdx/src/encoding/block_enc/compressed.rs:encode_sequences`, and `crates/zstdx/src/decoding/sequence_execution.rs:do_offset_history`. C code is in `lib/common/zstd_internal.h:LL_bits` and `ML_bits`, `lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body`, and `lib/decompress/zstd_decompress_block.c:ZSTD_decodeSequence`.
- Huffman wire format: weight-list description in raw 4-bit or FSE-compressed form with weight-FSE tableLog at most 6 and interleaved states, the weights-to-table math, 4-stream literals with a 6-byte LE16 jump table and the `(n+3)/4` split, all size formats, and X1 and X2 entry layouts. zstdx code is in `crates/zstdx/src/huff0/huff0_encoder.rs:write_table_desc`, `crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_literals`, and `crates/zstdx/src/huff0/huff0_decoder.rs:build_x2_table`. C code is in `lib/compress/huf_compress.c:HUF_writeCTable_wksp` and `HUF_compressWeights`, `lib/common/entropy_common.c:HUF_readStats_body`, and `lib/decompress/huf_decompress.c:HUF_DEltX1` and `HUF_DEltX2`.
- Bit-IO directions: an LSB-first writer with whole-byte flush, and reversed readers that keep an LE u64 window consumed from the MSB. zstdx code is in `crates/zstdx/src/bit_io/bit_writer.rs:BitWriter::write_bits_64` and `crates/zstdx/src/bit_io/bit_reader_reverse.rs:BitReaderReversed::refill`. C code is in `lib/common/bitstream.h:BIT_addBits`, `BIT_initDStream` and `BIT_reloadDStream`.
- Checksum, dictionaries and budgets: XXH64 truncated to 32 bits and computed only when the flag is set, dictionary content reachable only until output exceeds the window, per-sequence output-overrun rejection, and a trailing empty last block on empty or exact-multiple input. zstdx code is in `crates/zstdx/src/decoding/scratch.rs:set_checksum_enabled`, `crates/zstdx/src/decoding/decode_buffer.rs:repeat_from_dict`, and `crates/zstdx/src/encoding/frame_compressor.rs:trailing_empty`. C code is in `lib/decompress/zstd_decompress.c:ZSTD_decompressBegin`, `lib/compress/zstdmt_compress.c:ZSTDMT_writeLastEmptyBlock`, and `lib/decompress/zstd_decompress_block.c:ZSTD_execSequenceEnd`.

### Ported machinery

- The matcher family and the optimal parser are per-tier ports: single-probe fast with the ip0 and ip1 pipeline, 8-byte and 5-byte dfast double hash, head plus chain lazy search, the full `zstd_opt.c` port with bt1 insertion, all-matches collection, price algebra multiplied by 256, rescale, scale and update stats, the btultra2 two-pass first block, and the btlazy2 DUBT tree with its lazy-generic selection loop. zstdx code is in `crates/zstdx/src/encoding/match_generator/parse_fast.rs`, `parse_dfast.rs`, `parse_chain.rs` and `parse_btlazy.rs`, plus `crates/zstdx/src/encoding/dubt.rs`, `crates/zstdx/src/encoding/btlazy.rs`, and `crates/zstdx/src/encoding/opt.rs:Finder::insert_bt1`, `get_all_matches`, `bit_weight` and `rescale_freqs`. C code is in `lib/compress/zstd_fast.c:ZSTD_compressBlock_fast_noDict_generic`, `lib/compress/zstd_double_fast.c:ZSTD_compressBlock_doubleFast_noDict_generic`, `lib/compress/zstd_lazy.c:ZSTD_HcFindBestMatch`, `ZSTD_insertDUBT1` and `ZSTD_DUBT_findBestMatch`, and `lib/compress/zstd_opt.c:ZSTD_insertBtAndGetAllMatches`, `ZSTD_rescaleFreqs` and `ZSTD_initStats_ultra`.
- FSE encoder table machinery is ported. The arithmetic `FSE_CTable` form packs `deltaNbBits` and `deltaFindState` into u64 `tt` entries. The U64-spread fast branch serves tables without -1 symbols. The NCount writer uses the `remaining`, `threshold` and `nbBits` ladder. zstdx code is in `crates/zstdx/src/fse/fse_encoder.rs:FSETable::tab`, `build_table_from_probabilities` and `write_table`. C code is in `lib/compress/fse_compress.c:FSE_buildCTable_wksp` and `FSE_writeNCount_generic`. FSE normalization and NCount reading are documented ports through `normalize_count`, `normalize_m2`, `optimal_table_log` and `RTB_TABLE` against `lib/compress/fse_compress.c:FSE_normalizeCount`, `FSE_normalizeM2` and `FSE_optimalTableLog`. Huffman X1 and X2 decode fast loops and the X1 or X2 choice are explicit ports including the `algoTime` cost table, at `crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved` and `_x2`, plus `select_x2_table`, against `lib/decompress/huf_decompress.c:HUF_decompress4X1_usingDTable_internal_fast_c_loop` and `HUF_selectDecoder`.
- Huffman code construction ports libzstd's shape: a two-queue tree over count-sorted leaves, depth clamped by `HUF_setMaxHeight`'s Kraft repayment, and the exact-cost treeless or repeat decision of `HUF_compress_internal`. zstdx code is in `crates/zstdx/src/huff0/huff0_encoder.rs:build_lengths_into` and `crates/zstdx/src/encoding/block_enc/compressed.rs:compress_literals`. C code is in `lib/compress/huf_compress.c:HUF_buildCTable_wksp`, `HUF_setMaxHeight` and `HUF_compress_internal`.
- Decode-execute fusion, called the libzstd model in its documentation, uses the wildcopy copy stack with dec32 and dec64 overlap tables. zstdx code is in `crates/zstdx/src/decoding/block_decoder.rs:decompress_block_flat` and `crates/zstdx/src/decoding/sequence_execution.rs:wildcopy_literals` and `overlap_copy8`. C code is in `lib/decompress/zstd_decompress_block.c:ZSTD_decompressSequences_body`, `lib/common/zstd_internal.h:ZSTD_wildcopy` and `ZSTD_overlapCopy8`.
- Dictionary training and emission descend from libzstd's scheme: per-epoch segment selection with distinct k-mer scoring in fastcover's shape, and the `ZDICT_finalizeDictionary` table and header layout. zstdx code is in `crates/zstdx/src/dict/cover.rs:select_segment`, `crates/zstdx/src/dict/mod.rs:build_dict` and `crates/zstdx/src/dict/finalize.rs`. C code is in `lib/dictBuilder/fastcover.c:FASTCOVER_selectSegment` and `lib/dictBuilder/zdict.c:ZDICT_finalizeDictionary`.
- Per-stream entropy mode selection, the RLE, predefined, repeat and custom decision tree, and sequence-code computation are shared. zstdx code is in `crates/zstdx/src/encoding/block_enc/compressed.rs:select_from_counts` and `crates/zstdx/src/encoding/seq_codes.rs:pack_seq`. C code is in `lib/compress/zstd_compress_sequences.c:ZSTD_selectEncodingType` and `lib/compress/zstd_compress_internal.h:ZSTD_LLcode` and `ZSTD_MLcode`.
- Three ports landed more recently. The gear-hash long-distance matcher sits in `crates/zstdx/src/encoding/ldm.rs` against `lib/compress/zstd_ldm.c:ZSTD_ldm_blockCompress`. The post-parse block splitter sits in `crates/zstdx/src/encoding/block_enc/split.rs` against `lib/compress/zstd_compress.c:ZSTD_deriveBlockSplits`. The pre-parse content-adaptive splitter sits in `crates/zstdx/src/encoding/pre_split.rs` against `lib/compress/zstd_preSplit.c:ZSTD_splitBlock`.

### Converged design

- Both sides use 4-lane position-mod-4 histograms recombined at the end, chosen for out-of-order friendliness. zstdx code is `crates/zstdx/src/encoding/block_enc/compressed.rs:histogram_literals`, and C code is `lib/compress/hist.c:HIST_count_parallel_wksp`.
- Both sides share the MT job invariants: the first block of every job is self-describing with an entropy reset, repcodes are gated until three literal-offset sequences rewrite history, the overlap strip is indexed into the search tables, job size is floored at 1 MiB and capped at 1 GiB, per-worker state is pooled warm, worker failures are deferred to ordered assembly, and MT auto-engages only with more than one usable core. zstdx code is in `crates/zstdx/src/encoding/match_generator/mod.rs:gate_repcodes` and `prefill_window`, `crates/zstdx/src/encoding/mt.rs:MAX_JOB_SIZE`, `MIN_JOB_SIZE` and `poison`, and `crates/zstdx/src/encoding/frame_compressor.rs:take_slice_state`. C code is in `lib/compress/zstdmt_compress.c:ZSTDMT_compressionJob`, `ZSTDMT_JOBSIZE_MAX`, `ZSTDMT_getCCtx` and `JOB_ERROR`, and `lib/compress/zstd_compress.c:ZSTD_invalidateRepCodes`.
- Both sides use a pull decoder core with Read and Write wrappers, a pledged size written into the frame header, a decode output buffer sized at window plus two blocks plus overlength, and BMI2 runtime CPU-feature dispatch. zstdx code is in `crates/zstdx/src/stream/write.rs:Encoder::auto_finish`, `crates/zstdx/src/encoding/frame_header.rs:FrameHeader.frame_content_size`, `crates/zstdx/src/decoding/flat_buffer.rs:ensure_block_space` and `crates/zstdx/src/decoding/sequence_section_decoder.rs:decode_sequences`. C code is in `lib/compress/zstd_compress.c:ZSTD_compressStream2` and `ZSTD_CCtx_setPledgedSrcSize`, and `lib/decompress/zstd_decompress.c:ZSTD_decodingBufferSize_internal`.

## Encoder front-end

### Encoder front-end: own approach

- Dictionary trainer estimator. zstdx runs a deterministic fastCover-style scheme of its own: shuffled samples, an 8-byte k-mer frequency table capped at 2^21 entries with strided sampling, per-epoch sliding-window scoring by summed distinct k-mer frequency with selected-segment zeroing, and a k-sweep scored on a held-out split. The code is `crates/zstdx/src/dict/cover.rs:select_segment` and `crates/zstdx/src/dict/mod.rs:build_dict`. Official fastcover computes exact whole-corpus d-mer frequencies into a 2^f bucket table with f=20, d=8, k=2000, splitPoint 0.75 and an accel table, at `lib/dictBuilder/fastcover.c:FASTCOVER_defaultAccelParameters`, over in-memory samples. Both finish with the `ZDICT_finalizeDictionary` layout of entropy tables plus a header. zstdx's finalize is a documented port in `crates/zstdx/src/dict/finalize.rs`, and its divergences, which skip the dead `repStartValue` analysis and still let raw-encoding blocks contribute their parse, are measured as irrelevant.
- 32-bit hash entries with positional reconstruction. zstdx stores `(pos & 0xffff_ffff)+1`, which keeps zero as a dead sentinel and rebuilds the high bits from the scan position, at `crates/zstdx/src/encoding/match_generator/tables.rs:pack_pos`. The scan loops resolve entries as distances inline, so only entry-roundtrip tests keep the explicit inverse. C keeps full U32 window indices validated against `window.lowLimit` and `minChain`, at `lib/compress/zstd_lazy.c:ZSTD_HcFindBestMatch`.
- Monotone-origin table entries. Every matcher table for fast, dfast, chain and opt stores u32 entries biased by a per-state origin coordinate that advances past each invalidated span. Stale entries then rebuild as out-of-window positions, so invalidation stays O(1) with no clears. zstdx code is `crates/zstdx/src/encoding/opt.rs:Finder::resolve` and `crates/zstdx/src/encoding/match_generator/tables.rs:pack_pos`. C validates against `windowLow`, `btLow` and `nextToUpdate`, and rewinds window limits for the btultra2 stat seed, at `lib/compress/zstd_opt.c:ZSTD_insertBtAndGetAllMatches` and `ZSTD_initStats_ultra`.
- Offset-gain store gate. zstdx's `pays_for_offset` at `crates/zstdx/src/encoding/match_generator/price.rs` uses `ml*4 >= ilog2(offset)+7` with reps exempt, and refuses hash-path candidates whose offset code outweighs the length. It derives from libzstd's lazy gain arithmetic at `lib/compress/zstd_lazy.c:ZSTD_compressBlock_lazy_generic`, but applies it as an emission gate, which C never does. The chain strategy's variant `pays_for_offset_lit` prices displaced bytes at the previous block's Huffman code lengths.
- Fast-tier acceptance bar. In dense blocks the single-probe tier declines far candidates whose displaced literals, priced at fed-back code lengths, do not cover the offset, at `crates/zstdx/src/encoding/match_generator/parse_fast.rs`. The bar folds to constant true outside dense mode. C's fast tier accepts every candidate at or above mls, at `lib/compress/zstd_fast.c:ZSTD_compressBlock_fast_noDict_generic`. Both are ratio and speed tuning of the same single-probe design.
- Miss-step curve. zstdx grows the probe step quadratically with the literal run as `1 + min(miss_count>>2, 255)`, with a dense-mode doubling of the pair advance. C grows linearly with `step++` per `kStepIncr=128` bytes, at `lib/compress/zstd_fast.c:_start`. Both solve the same problem, and zstdx's curve is justified against its denser tables.
- Zero-copy slice architecture. The match window borrows the caller's buffer through a raw pointer, at `crates/zstdx/src/encoding/match_generator/mod.rs:adopt_window` and `ExtWindow`, driven by `crates/zstdx/src/encoding/frame_compressor.rs:compress_slice_to_vec`. That removes the read pass, window compaction and window allocation. C always copies input into the internal window at `lib/compress/zstd_compress.c:ZSTD_window_update`. Byte identity between the streaming and slice paths is asserted in tests.
- Window policy. The frame window follows the per-level `LEVEL_PARAMS` row from W19 to W26, and LDM-carrying rows declare a wider frame window than the parser's search domain. `chain_reach` pins the tree and chain walk at the stock row window while LDM candidates carry the distance classes beyond it, at `crates/zstdx/src/encoding/match_generator/params.rs:LEVEL_PARAMS` and `chain_reach`. C couples windowLog and search domain, so it reaches farther only by widening the tables.
- Job prefill indexing appears under Architecture A as strip indexing style. The stride constant is shared with C's `fastHashFillStep`, but applied to a job-model need that C does not have.

### Encoder front-end: zstdx-only

- Job-start seed offset for periodic repeats. Prefill scans the strip tail for a position whose 8 bytes plus 48 backward bytes agree with the anchor, then installs its distance as a direct probe. The code is `crates/zstdx/src/encoding/match_generator/mod.rs:acquire_seed`, `seed_scan` and `SEED_AGREE`. Three seed emissions rotate `rep` onto the period, with an 8192-probe retirement budget through `SEED_MATCHES` and `SEED_BUDGET`. C has nothing analogous, and on clumped periodic data its single-probe slots are buried by recent same-hash recurrences.
- AVX-512 kernels inside the matcher. An occupancy-mask seed scan covers 8 overlapping 64-byte loads per 64-candidate block at `crates/zstdx/src/encoding/match_generator/gates.rs:seed_scan_avx512`. Non-temporal streaming table clears run above 4 MiB of slots at `crates/zstdx/src/encoding/match_generator/tables.rs:clear_table_avx512`. Official front-end SIMD is limited to the row-hash tag compare at `lib/compress/zstd_lazy.c:ZSTD_row_getMatchMask` with SSE, NEON and RVV, and `lib/compress` has no AVX-512 and no streaming stores.
- Packed single-stream sequence collection. zstdx emits one 24-byte `SeqWord` per sequence, holding LL, ML and OF codes, pre-merged add-bits and a width. Table selection, table description and the bitstream consume it without materializing raw triples. The code is `crates/zstdx/src/encoding/seq_codes.rs:pack_seq` and the fused histogram pass in `crates/zstdx/src/encoding/block_enc/compressed.rs:choose_tables_fast`. A 16-byte pack was measured and rejected, as recorded in [negative](negative.md). C's `SeqStore_t` stores raw offBase, ll and ml triples and recomputes codes later, at `lib/compress/zstd_compress_internal.h:ZSTD_storeSeq` and `lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences`.
- Zero-sequence block bypass. Literals stay in the window and the block encoder reads them directly, with an early Raw verdict from the sampled entropy gate before any encode-and-discard writes, at `crates/zstdx/src/encoding/block_enc/compressed.rs:compress_block`. C routes every block through the seqStore and literal buffer at `lib/compress/zstd_compress.c:ZSTD_buildSeqStore`.
- Sampled incompressibility gate. zstdx takes a strided sample of about 1024 literal points with Miller-Madow bias correction, a distinct-count prescreen above 208, and a sticky `gate_hold` across blocks. A dictionary-seeded stream drops the flat description weight from the reject floor because its candidate is treeless. The code is `crates/zstdx/src/encoding/block_enc/compressed.rs:sampled_gate_rejects`. C's only analogue is the `suspectUncompressible` hint at `lib/compress/zstd_compress.c:ZSTD_compressLiterals`, without sampling or an entropy-floor estimator.
- Fastest-tier table pressure as a first-class tuning axis. zstdx uses 2^15 entries on H15 rows, dual-anchor sparse indexing of long matches at `crates/zstdx/src/encoding/match_generator/tables.rs:TableEmit::emit` with at most 16 B dense and otherwise start+2 and end-2, and a newest-wins proximity bias. That is a measured redesign of C's fill policy at `lib/compress/zstd_fast.c:_match`, which uses mls=7 and a 2^14 to 2^16 table. The analysis is in [matchers](perf/matchers.md).
- Fused checksum absorption. The RLE uniformity scan runs XXH64 rounds inline, raw-block copies hash while copying, and a sidecar thread can take the work. The code is `crates/zstdx/src/encoding/levels/fastest.rs:compress_fastest` and `crates/zstdx/src/encoding/checksum.rs:BlockChecksum` and `SliceChecksum::Offload`. C hashes frame content in separate passes at `lib/compress/zstd_compress.c:XXH64_update`. The topology appears under Architecture A.

### Encoder front-end: gaps

- Row-hash matchfinder. C uses per-row byte tags, a head index, cached incremental hashing, salted epochs and SIMD tag masks, auto-selected for greedy, lazy and lazy2, at `lib/compress/zstd_lazy.c:ZSTD_RowFindBestMatch`, `ZSTD_row_getMatchMask` and `ZSTD_resolveRowMatchFinderMode`. zstdx's lazy band rows 5-12 run this crate's own tagged row matcher, and row 9 keeps the hash chain with a cold-start DUBT head.
- Content-adaptive pre-split coverage. C auto-enables the splitter across its lazy2 and btlazy2 band. zstdx's port runs it on the balanced chain row only. Every non-lazy row and every narrow-alphabet frame is exempt as a measured worse trade, and a throughput-class screen runs before the detector, at `crates/zstdx/src/encoding/pre_split.rs`. Data is in [encoding](perf/encoding.md).
- Input-size profile rows. C has 4 srcSize profiles per level in `lib/compress/clevels.h:ZSTD_defaultCParameters`, selected by `ZSTD_getCParams`, which can downgrade the strategy row and add negative levels. zstdx keeps one row per level with runtime shrinking of window, hash and chain logs for known sizes, at `crates/zstdx/src/encoding/match_generator/params.rs:adjust_params`. The strategy row never downgrades for large inputs. The small-source band at 128 KiB and below and the dictionary rows at 16 KiB and below do swap classes, as recorded in [matchers](perf/matchers.md). Negative levels clamp to Fastest.
- Dictionary-aware compression beyond the content load. C has noDict, dictMatchState, extDict and dedicatedDictSearch template modes for every strategy, at `lib/compress/zstd_fast.c:ZSTD_compressBlock_fast_dictMatchState_generic`, `lib/compress/zstd_lazy.c:ZSTD_dedicatedDictSearch_lazy_search` and the `ZSTD_count_2segments` plumbing. zstdx seeds match history and entropy tables on the single-threaded paths at `crates/zstdx/src/encoding/dictionary.rs:reset_with_dictionary` and on the MT job grid, where job zero seeds from the dictionary and the capture and reach classes arm on dictionary frames, without the dictionary-specialized matcher templates. The repeated-dictionary economics ride the seed-image cache instead, which is projection-keyed. See [encoding](perf/encoding.md).
- Greedy and lazy spectrum granularity. Official levels 5-12 sweep three parsers from greedy to lazy to lazy2 with searchLog 3-6 and targetLength 0-32. zstdx compresses the band into one chain parser at depths 4-32, where rows differ by depth only, and it lacks `lazySkipping` insert suppression at `lib/compress/zstd_lazy.c:ZSTD_insertAndFindFirstIndex_internal`. The miss-step growth partially supersedes that gap.

## Entropy coding

### Entropy coding: own approach

- NCount writer bookkeeping. zstdx assembles the description in a 64-bit register accumulator flushed as unaligned u64 stores, and tracks `threshold` and `nb_bits` incrementally through ilog2(remaining) instead of a per-symbol lzcnt, at `crates/zstdx/src/fse/fse_encoder.rs:FSETable::write_table`. Official threads the same ladder bit by bit through the BitStream at `lib/compress/fse_compress.c:FSE_writeNCount_generic`. The wire format is the same, and only the bookkeeping is vectorized.
- NCount reader. zstdx reads bit by bit through its forward `crates/zstdx/src/bit_io/bit_reader.rs:BitReader` and skips zero runs two bits at a time at `crates/zstdx/src/fse/fse_decoder.rs:read_probabilities`. Official parses a forward 32-bit LE window, decides the width with `(bitStream & (threshold-1)) < max`, and consumes zero runs up to 12 groups per iteration through `countTrailingZeros32` at `lib/common/entropy_common.c:FSE_readNCount_body`.
- Huffman encoder bit accumulation. zstdx inserts codes at the bottom of the accumulator, consumes input in reverse through `rchunks(4)`, and writes output forward, at `crates/zstdx/src/bit_io/bit_writer.rs:BitWriter::write_packed_codes_rev`. Official keeps code values in the top bits of a size_t container with per-tableLog unroll factors and two-container double-buffering through `HUF_zeroIndex1` and `HUF_mergeIndex1`, which breaks the dependency chain, at `lib/compress/huf_compress.c:HUF_addBits` and `HUF_compress1X_usingCTable_internal_body_loop`. zstdx instead batches 4 symbols per container fill.
- Huffman encoder table format. zstdx stores `packed: [u16; 256]` as `(code << 4) | num_bits` plus a `(u32, u8)` tuple vector at `crates/zstdx/src/huff0/huff0_encoder.rs:HuffmanTable`. Official stores one `HUF_CElt` size_t per symbol with the value pre-shifted to the container top, which makes `HUF_addBits` branch-free, at `lib/compress/huf_compress.c:HUF_setValue` and `HUF_getValueFast`.
- Literal incompressibility pre-check. zstdx computes the exact Shannon bound from one shared histogram and rejects when `entropy_bits + description + total*0.02 >= total*8`, with a distinct-symbol bound short-circuiting the log2 loop. A dictionary-seeded table drops the description term because its leading candidate is treeless. The code is `crates/zstdx/src/encoding/block_enc/compressed.rs:compress_literals` and `entropy_bound_bits`. Official uses a max-count heuristic of `largest <= (srcSize >> 7)+4` and `ZSTD_minGain`, at `lib/compress/huf_compress.c:HUF_compress_internal` and `lib/compress/zstd_compress_internal.h:ZSTD_minGain`.
- X1 DTable shape and lifetime. zstdx sizes the table naturally at `1 << max_bits` for any log from 1 to 11 and keeps a packed u16 mirror `(symbol<<8)|num_bits` for single-load decode, at `crates/zstdx/src/huff0/huff0_decoder.rs:HuffmanTable.packed`. Official rescales weights up to `HUF_DECODER_FAST_TABLELOG=11` and fills 2-byte `HUF_DEltX1` entries with U64 quad stores, at `lib/decompress/huf_decompress.c:HUF_rescaleStats` and `HUF_DEltX1_set4`.
- Fast-loop applicability. zstdx's ported loops run at any tableLog with `index = bits >> (64-tl)`, with per-iteration bound re-checks and a scalar tail that shares reader state, at `crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved` and `finish_streams`. Official requires `dtLog == 11` and at least 8 bytes per stream, and otherwise falls back to the generic body, at `lib/decompress/huf_decompress.c:HUF_DecompressFastArgs_init`.
- Sequence-code precomputation locus. zstdx computes all three codes and add-bit payloads once at match-emission time into packed `SeqWord`s at `crates/zstdx/src/encoding/seq_codes.rs:pack_seq`. Official stores raw llBase, mlBase and offBase in `SeqDef` and computes codes per sequence inside the encode loop at `lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body`.

### Entropy coding: zstdx-only

- Batched literal-code writer. It groups 4 symbols per container fill and flushes below 8 pending bits, so four codes of at most 12 bits always fit. Each flush is one unaligned u64 store, and overshoot is snapped by `set_len`. The code is `crates/zstdx/src/bit_io/bit_writer.rs:write_packed_codes_rev` with the BMI2 dual variant `write_packed_codes_dual_bmi2`, and bit identity is covered by the `packed_codes_rev_matches_write_bits` test. Official encodes strictly one `HUF_addBits` per symbol.
- Flat-alphabet fast path. Uniform code-length detection enables a two-symbols-per-byte bulk packer with an AVX-512VBMI kernel, which packs 64 symbols per iteration through a 256-entry LUT with a `permutex2var_epi8` pair and a bit-7 `mask_blend`. The code is `crates/zstdx/src/bit_io/bit_writer.rs:write_uniform4_bulk` and `uniform4_pack_avx512`. The measurements are 48% fewer instructions on skewed and 43% more throughput. Official has no SIMD on the encode side beyond the BMI2 attribute.
- AVX-512 exact histogram for alphabets of 16 symbols or fewer. It uses 16 slot broadcasts with `cmpeq_epi8_mask` plus popcnt, and the popcount coverage sum doubles as a detector for a 17th symbol, with a cold scalar fallback. The code is `crates/zstdx/src/encoding/block_enc/compressed.rs:histogram_small_alpha_avx512`. Official's non-SVE path is purely scalar 4-lane at `lib/compress/hist.c:HIST_count_parallel_wksp`.
- The strided Miller-Madow sampling gate from Encoder B also drives the literals path. It takes about 1024 stride samples, estimates entropy with bias correction, and rejects only near 8 bits per byte or above, at `crates/zstdx/src/encoding/block_enc/compressed.rs:sampled_gate_rejects`. Official samples only the first and last 4096 bytes with a largest-count test at `lib/compress/huf_compress.c:HUF_compress_internal`.
- Fused three-histogram single pass. LL, ML and OF counts are filled in one traversal of the packed code words at `crates/zstdx/src/encoding/block_enc/compressed.rs:choose_tables_fast`. Official runs three separate `HIST_countFast_wksp` passes in `lib/compress/zstd_compress.c`.
- Combined bit pushes in the sequence encoder. Three state-transition groups are concatenated into one value of at most 36 bits, then transitions and add-bits are merged into a single push of at most 56 bits, with the accumulator held in locals through `writer.hot_state()`. The code is `crates/zstdx/src/encoding/block_enc/compressed.rs:encode_sequences` and `hot_push_raw`, measured at 0.4% fewer json instructions. Official issues up to six separate `BIT_addBits` calls per sequence at `lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body`.
- Decode-side merged table arena. All three packed FSE tables share one allocation at fixed slot offsets, `LL_SLOT=0`, `ML_SLOT=1<<LL_MAX_LOG` and `OF_SLOT=...`, addressed through a single base pointer. A pre-shifted bit window `win = bits << consumed` costs two shifts per read, and the whole loop uses BMI2 runtime dispatch. The code is `crates/zstdx/src/decoding/sequence_section_decoder.rs:pack_tables` and `decode_sequences_impl_bmi2`. Official keeps three independent `ZSTD_seqSymbol*` pointers at `lib/decompress/zstd_decompress_block.c:ZSTD_decodeSequence`.
- X2 pairability gate. The double-symbol table is built only when the pairable share of code space reaches about 80%. The test `eligible_slots * 5 < 4 << 11` keeps X1, at `crates/zstdx/src/huff0/huff0_decoder.rs:build_x2_table`. The measurement is 43% better on skewed.zst1 by avoiding X2 on unpairable tables. Official always builds whatever `HUF_selectDecoder` picked, at `lib/decompress/huf_decompress.c:HUF_readDTableX2_wksp`.
- No-std log2. A linear-mantissa approximation with error below 0.086 serves every entropy and cost estimate at `crates/zstdx/src/fse/fse_encoder.rs:approx_log2`, and margin-based comparisons tolerate it. Official uses integer fixed-point cost models only at `lib/compress/zstd_compress_sequences.c:kInverseProbabilityLog256`.
- Float Shannon cost models. Repeat-mode cost is priced exactly through the previous table's per-symbol bits via `repeat_bit_cost` and `FSETable::symbol_bit_cost`. Fresh-table cost is estimated as the Shannon bound plus a description term through `entropy_bound_bits` and `description_bits`. Official compares basic, repeat and fresh with accuracy-8 fixed point through `ZSTD_entropyCost`, `ZSTD_fseBitCost` and `ZSTD_crossEntropyCost`. The float and fixed split has no counterpart on the other side.
- Compile-time table generation. `const fn`-generated LUTs and metadata arrays surface encoding errors at compile time through `ll_meta`, `ml_meta`, `ll_code_lut` and `ml_code_lut` at `crates/zstdx/src/encoding/seq_codes.rs`. Official uses hand-written static arrays at `lib/common/zstd_internal.h:LL_bits` and `lib/compress/zstd_compress_internal.h:LL_Code` and `ML_Code`.

### Entropy coding: gaps

- Huffman depth probing. `HUF_flags_optimalDepth`, enabled at strategy at or above `HUF_OPTIMAL_DEPTH_THRESHOLD`, estimates `HUF_estimateCompressedSize + hSize` for every candidate tableLog and picks the best, at `lib/compress/huf_compress.c:HUF_optimalTableLog` and `lib/compress/zstd_compress_literals.c`. zstdx builds once at the format maximum of 11 at `crates/zstdx/src/huff0/huff0_encoder.rs:build_lengths_into`.
- Strategy-scaled literal thresholds. C uses `ZSTD_minLiteralsToCompress` from 8 to 64 bytes by strategy and `ZSTD_minGain = (srcSize >> minlog) + 2` with minlog 6 or 7, at `lib/compress/zstd_compress_literals.c`. zstdx uses a fixed 1024-byte gate floor and flat 2% margins at `crates/zstdx/src/encoding/block_enc/compressed.rs:compress_literals`.
- ctz-accelerated NCount parsing, described under A. zstdx's per-bit reader is tolerable only because table headers are small, at `crates/zstdx/src/fse/fse_decoder.rs:read_probabilities` against `lib/common/entropy_common.c:FSE_readNCount_body`.
- Hand-written x86-64 asm Huffman decode loop. `lib/decompress/huf_decompress_amd64.S` is about 766 lines and dispatched under `ZSTD_ENABLE_ASM_X86_64_BMI2`. zstdx has no asm, and its Rust loop does one table load and two shifts against the asm's three dtable loads, with claimed memport and ALU-bound parity in [decoding](perf/decoding.md). That parity claim is unverified here.
- X2 fast-loop register scheduling. Official splits into a 3-way variant on x86 and a 4-way variant on aarch64 through `HUF_4X2_3WAY` and `HUF_4X2_4WAY` at `lib/decompress/huf_decompress.c`. zstdx always decodes column-major 4 streams with 5 lookups at `crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved_x2`.
- SVE2 histogram. `lib/compress/hist.c:HIST_count_6_sve2` uses `svhistseg_u8` for per-16-byte segment histograms on aarch64. zstdx's SIMD histogram is x86 AVX-512 only with scalar fallback elsewhere, at `crates/zstdx/src/encoding/block_enc/compressed.rs:histogram_literals`.
- Predefined versus dynamic cross-entropy at high strategies. C prices the predefined distribution against the normalized counts with `ZSTD_crossEntropyCost` for strategy at or above lazy, at `lib/compress/zstd_compress_sequences.c:ZSTD_selectEncodingType`. zstdx keeps the fast-strategy heuristic gate outside dictionary-seeded streams, and its fresh-table side is a Shannon bound rather than a through-the-table cost, at `crates/zstdx/src/encoding/block_enc/compressed.rs:select_from_counts`.
- Superblock re-entropy coding. C re-emits multiple blocks as one superblock with entropy tables shared or rewritten across sub-blocks, at `lib/compress/zstd_compress_superblock.c`. zstdx has nothing comparable, and Architecture C records the gap.
- longOffsets two-part offset emission for offsets above the accumulator budget, at the `ZSTD_encodeSequences_body` longOffsets branch in `lib/compress/zstd_compress_sequences.c`. zstdx relies on its 56-bit-capped combined push, which is equivalent wire for its W26 windows, and the explicit long-offset mode is absent.

## Decoder

### Decoder: own approach

- Ring-buffer execution path from the ruzstd heritage. It is a hand-written ring with modulo-free `wrap_add` and four layout cases, now confined to dictionary frames. `repeat_in_chunks` doubles matches with libzstd's semantics but not its code. zstdx code is `crates/zstdx/src/decoding/ringbuffer.rs:RingBuffer`, `crates/zstdx/src/decoding/decode_buffer.rs:repeat_pre_reserved` and `repeat_in_chunks`, and `crates/zstdx/src/decoding/frame_decoder.rs:decode_blocks`. C code is `lib/decompress/zstd_decompress_block.c:ZSTD_execSequence` and `ZSTD_safecopy`. Libzstd never uses a ring and always runs linear `dst` with a 3-pointer extDict.
- Window continuity as a two-generation virtual address space. `crates/zstdx/src/decoding/flat_buffer.rs:FlatOut` and `FlatView` with `origin`, `prev_origin` and `seg_a_end` make virtual distances equal physical ones inside the active segment, so `dst - offset` is the whole match algebra in `exec_one_flat`, and straddling sources go to a `#[cold] copy_wrapped_match`. Libzstd remaps per sequence at runtime through `ZSTD_checkContinuity` and splits matches across extDict and prefix, at `lib/decompress/zstd_decompress_block.c:ZSTD_checkContinuity`.
- Monomorphized wrap and headroom instantiations. `crates/zstdx/src/decoding/sequence_execution.rs:execute_decoded_flat_inner::<NOWRAP, HEADROOM>` compiles the never-wrapped and guaranteed-slack cases into loops with no mapping branches and no per-sequence wildcopy gates. Libzstd has one runtime-checked `ZSTD_execSequence`.
- Pre-shifted bit window. `win = bits << consumed` costs two shifts per read, and `bits` is never carried across sequences, at `crates/zstdx/src/decoding/sequence_section_decoder.rs:read` and `reload`. Official carries `ptr`, `bitContainer` and `bitsConsumed` at `lib/common/bitstream.h:BIT_lookBitsFast`.
- Batched field extraction. All three add-bit fields are read in one window read when the sum is at most 31, which needs no mid-sequence reload, and larger sums take the cold fallback. All three state transitions come from one 26-bit read, split by shifts and bzhi, at `crates/zstdx/src/decoding/sequence_section_decoder.rs:decode_step`. Official reads OF, ML and LL bits with separate `BIT_readBitsFast` calls and conditional reload guards at `lib/decompress/zstd_decompress_block.c:ZSTD_decodeSequence`.
- Branch-free repcode resolution. The slot index is `code-1+ll0`, the garbage slot load is masked, and rotation uses selects, at `crates/zstdx/src/decoding/sequence_execution.rs:do_offset_history`. C uses a branch tree with `ofBits > 1`, `LIKELY(ofBits == 0)` and `temp -= !temp`. The aarch64 variant of `ZSTD_decodeSequence` is closer but still branches on `ofBits`.
- Fused-loop state promotion. `SeqDecoder` is destructured into loop locals in `execute_decoded_flat_inner` through SROA, and fields are written back only on success. C passes `seqState_t` by pointer into `ZSTD_decodeSequence`, so state is stored through memory on each call.
- Inline fixed-width copies. Unaligned u64 and u128 load-store copies are motivated by measured libc PLT overhead on variable-length memmove, at `crates/zstdx/src/decoding/sequence_execution.rs:copy8` and `copy16`. C uses `lib/common/zstd_internal.h:ZSTD_copy16`, and C compilers resolve memcpy inline with no PLT.
- Predefined-table caching. zstdx builds the tables once and only repacks them when they change, at `crates/zstdx/src/decoding/scratch.rs:FSEScratch::{ll,ml,of}_predefined`. Official keeps static const `LL_defaultDTable` and friends and never builds them, at `lib/decompress/zstd_decompress_block.c`.
- X1 fast loop indexed by the table's real log at `crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved` with tl in 1 to 11. Official pads the table to log 11 and refuses the fast loop otherwise, as described under Entropy A. The X2 gate refinement is shared with Entropy B.
- Multi-frame stream plumbing. zstdx peeks a 4-byte magic, replays the prefix, distinguishes clean EOF from first-frame EOF, and resets a reusable `FrameDecoder` per frame, at `crates/zstdx/src/decoding/frame_source.rs:start_frame` and `PrefixedReader`. `ZSTD_decompressStream` uses a stage machine that handles skippable frames inline, at `lib/decompress/zstd_decompress.c`.

### Decoder: zstdx-only

- Parallel decode. Libzstd has no decode-side MT, which was verified by finding no thread, pool, parallel or worker references under `lib/decompress/`, and `lib/common/pool.c` serves only compress-side zstdmt. zstdx runs a header-only prescan that cuts the input at restart points, which are blocks whose literals are not Treeless and whose FSE streams are not all Repeat mode, at `crates/zstdx/src/decoding/mt.rs:scan` and `restart_point`. A stage A worker pool decodes literals and sequences into staging buffers with tables rebuilt fresh per segment at `mt.rs:decode_segment` and per-worker `SegmentScratch`. Stage B executes matches on the calling thread in input order and carries `offset_hist` across segments at `mt.rs:execute_segment`, with a piece-parallel variant that splits stage B on the encoder's MT job grid for ramp-guaranteed frames at `crates/zstdx/src/decoding/mt_pieces.rs`. Staging is bounded by a `consumed` atomic, worker panics are captured through `catch_unwind` and a poison mutex, and the decoder falls back to sequential for dictionaries, small inputs and frames without a second restart point.
- HEADROOM specialization. When the allocation provably holds block-max plus 16 bytes beyond the cursor, with `crates/zstdx/src/decoding/flat_buffer.rs:WILDCOPY_SLACK` guaranteed by `ensure_block_space`, literal and match copies wildcopy unconditionally with no per-sequence bounds work at `crates/zstdx/src/decoding/sequence_execution.rs:exec_one_flat`. Libzstd always keeps the `oMatchEnd > oend_w` gate in `ZSTD_execSequence`.
- Bulk retry contract. zstdx doubles capacity on `TargetTooSmall` with a 64 KiB minimum hint at `crates/zstdx/src/bulk.rs:decompress` and `decompress_with`. Libzstd's one-shot model requires the caller to size `dst`, aided by `ZSTD_getFrameHeader` and `ZSTD_decompressBound`. This is a convenience layer, listed for completeness.
- No-std decoding core. The whole pipeline, ring and flat paths included, builds without std, and MT and BMI2 dispatch sit behind `#[cfg(feature = "std")]` in `crates/zstdx/src/decoding/` and `crates/zstdx/src/io_nostd.rs`.

### Decoder: gaps

- Literals stored inside the destination buffer. In one-shot mode C puts literals after the current block in `dst`, and otherwise splits them with a tail in `litExtraBuffer`, consumed split-buffer-first so output never catches the literal buffer, at `lib/decompress/zstd_decompress_block.c:ZSTD_allocateLiteralsBuffer` and `ZSTD_decompressSequences_bodySplitLitBuffer`. zstdx always decodes literals into a separate scratch `Vec` through `crates/zstdx/src/decoding/block_decoder.rs:parse_sections` and `literals_buffer`.
- Long-offset and prefetch sequence decoder. `ZSTD_decompressSequencesLong_body`, selected by long-offset share and `ddictIsCold`, prefetches future match data and splits 32-bit long-offset bits, at `lib/decompress/zstd_decompress_block.c` with `LONG_OFFSETS_MAX_EXTRA_BITS_32`. zstdx has one fused loop, no prefetch variant, and a 64-bit `usize` assumption, so the `sum <= 31` batching and the u64 window are 64-bit only.
- Hand-written Huffman asm, described under Entropy C. Decoder-side SIMD reach in zstdx is 16-byte u128 copies from SSE movdq codegen plus BMI2 runtime dispatch at `crates/zstdx/src/decoding/sequence_section_decoder.rs:decode_sequences`, the same pattern as C's `DYNAMIC_BMI2`. The zstdx decoder has no AVX-512 anywhere, verified by grep.
- DSB loop alignment. `ZSTD_decompressSequences_body` and its SplitLitBuffer form embed `.p2align` directives that tune the decode loop's DSB and MITE behavior. zstdx has no alignment directives.
- In-place and caller-managed-window decode. `ZSTD_decompressFrame` clamps `oBlockEnd` when `ip >= op`, `ZSTD_checkContinuity` lets each call present a fresh disjoint output buffer serving as extDict, and `ZSTD_d_stableOutBuffer` keeps one output buffer across streaming calls, at `lib/decompress/zstd_decompress.c`. zstdx assumes source and target are distinct buffers.
- Checksum opt-out knob. Verification itself matches C's default on every decode path: the digest is compared with the stored word and a mismatch reports `FrameDecoderError::ChecksumMismatch`. ST folds the compare into the trailer read in `crates/zstdx/src/decoding/frame_decoder.rs:verify_frame_checksum`, and MT post-passes over the assembled output in `crates/zstdx/src/decoding/frame_checksum.rs`. What C still has exclusively is `ZSTD_d_validateChecksum` to disable verification.
- Zero-copy DDict. `ZSTD_copyDDictParameters` points prefix, virtual and dict pointers straight at the dictionary bytes and table pointers at prebuilt tables inside the `ZSTD_DDict`, plus a multiple-DDict hash set, at `lib/decompress/zstd_ddict.c` and `lib/decompress/zstd_decompress.c:ZSTD_DDictHashSet`. zstdx copies entropy tables and content into the scratch per frame at `crates/zstdx/src/decoding/scratch.rs:DecoderScratch::init_from_dict`, keys dictionaries in a `BTreeMap<u32, Dictionary>` at `crates/zstdx/src/decoding/frame_decoder.rs:dicts`, and dictionary frames forfeit the flat fast path.
- aarch64-specific tuning. C uses a single-load `ZSTD_seqSymbol` through memcpy and local prevOffset registers in `ZSTD_decodeSequence`, plus `PREFETCH_L1(match)` in `ZSTD_execSequence`. zstdx has no arch-specific sequence-path tuning beyond BMI2.
- Streaming input buffering. Libzstd's streaming decoder copies input into an internal `inBuff` for header atomicity. zstdx reads straight from the `Read` impl and rewinds parsed but unconsumed block headers at the `before_header` restore in `crates/zstdx/src/decoding/frame_decoder.rs:decode_from_to`.

## Architecture and systems

### Architecture and systems: own approach

- Job scheduler. Bulk MT runs fresh scoped threads per call with an atomic-counter work queue over a fixed slot array and condvar-ordered assembly on the calling thread. The code is `crates/zstdx/src/encoding/mt.rs:compress_slice_mt`, with `std::thread::scope`, `next_job: AtomicUsize`, `slots: Vec<Mutex<Option<Vec<u8>>>>` and `ready: Condvar`, and `crates/zstdx/src/stream/encoder_mt.rs` drives the streaming queues. Libzstd uses a long-lived worker pool created once per mtctx with a circular job queue and blocking pops, at `lib/common/pool.c:POOL_create` and `POOL_thread`, `lib/compress/zstdmt_compress.c:ZSTDMT_createJobsTable`, and `nbJobs = nbWorkers+2`.
- Warm state pooling. A thread-local bulk pool at `crates/zstdx/src/encoding/frame_compressor.rs:SLICE_STATE` survives across calls on the same thread. Streaming workers lease persistent threads from a global pool that carry their `CompressState` across encoders and bursts, at `crates/zstdx/src/stream/mt_pool.rs:THREAD_POOL` and `STATE_POOL`, with a depth cap and idle retirement. Libzstd has one always-warm arrangement through a persistent factory and cctxPool.
- Streaming-MT driving policy. zstdx buffers into one contiguous `[history strip][pending]` buffer and fires a burst only once `max(workers,2)` job-sized slices have accumulated, then encodes the whole burst in parallel, at `crates/zstdx/src/stream/encoder_mt.rs:burst_jobs` and `write`. Libzstd creates a job as soon as `inBuff.filled >= targetSectionSize` and flushes completed-job output incrementally with per-job progress, where `job->dstFlushed` and a condvar are signaled mid-job every 4 blocks, at `lib/compress/zstdmt_compress.c:ZSTDMT_compressStream_generic`.
- Job sizing. zstdx divides the known input evenly targeting twice the worker count with `len.div_ceil(workers*2)`, a floor of `max(1 MiB, overlap)` and a cap of 1 GiB, at `crates/zstdx/src/encoding/mt.rs:job_size_for`. Libzstd uses a fixed streaming section size of `1 << max(20, windowLog+2)` clamped to 512 KB and 1 GB, independent of input length, with a user-facing `ZSTD_c_jobSize` knob that zstdx lacks, at `lib/compress/zstdmt_compress.c:ZSTDMT_computeTargetJobLog`.
- Overlap policy. zstdx sizes the strip at the row's search reach, or the whole window on LDM-capture frames where the LDM state spans it, because it fully indexes what the row actually reads, at `crates/zstdx/src/encoding/mt.rs:compress_slice_mt` and `crates/zstdx/src/stream/encoder_mt.rs:overlap`. Libzstd defaults to a fraction through overlapLog, window/8 for fast through lazy and up to the full window only for btultra2, overridable through `ZSTD_c_overlapLog` at `lib/compress/zstdmt_compress.c:ZSTDMT_computeOverlapSize`.
- Strip indexing style. Fast and dfast prefilled on a stride-3 sparse grid, where the stride constant is libzstd's `fastHashFillStep` from `lib/compress/zstd_fast.c`, and chain fills run under the offset-gain store gate. That is an explicit deviation from libzstd's dense `ZSTD_loadDictionaryContent` fill, justified because zstdx strips are the full window. The code is `crates/zstdx/src/encoding/match_generator/mod.rs:prefill_window` and `FillGrid`, against `lib/compress/zstd_compress.c:ZSTD_fillHashTable` and `ZSTD_updateTree`.
- Determinism by construction for pooled state. Per-job head tables are cleared and the opt tables' origin coordinate is advanced precisely because pooled states carry residue that would make output depend on worker scheduling, at `crates/zstdx/src/encoding/match_generator/mod.rs:fill_window_grid`. Whether libzstd performs equivalent targeted clears per job is unverified, and its `ZSTD_compressBegin_*` re-inits match state.
- Checksum topology. zstdx selects among inline, offloaded and off backends behind one `BlockChecksum` trait, with a 256 KiB threshold for the sidecar thread, at `crates/zstdx/src/encoding/checksum.rs:SliceChecksum::new` and `ASYNC_MIN_INPUT`. In MT the whole input is hashed on the calling thread while workers compress in bulk, or interleaved during burst assembly in streaming, at `crates/zstdx/src/encoding/mt.rs:compress_slice_mt` and `crates/zstdx/src/stream/encoder_mt.rs:encode_jobs`. Libzstd serializes absorption in job order through the SerialState at `lib/compress/zstdmt_compress.c:ZSTDMT_serialState_genSequences` and zeroes the checksum flag for `jobID != 0`. The fused absorb into raw-block copies and RLE scans appears under Encoder B.
- Streaming-encode state machine. Input is staged into a fixed buffer, whole blocks are encoded as they fill, and encoded bytes are handed out from one output Vec, at `crates/zstdx/src/stream/encoder_core.rs:FrameEncoderCoreSt::write`, `finish` and `split_output`. Libzstd uses a stage machine with input buffering, a block loop and stable-in and stable-out bookkeeping at `lib/compress/zstd_compress.c:ZSTD_compressStream2` and `cctx->streamStage`.
- Streaming-decode framing on the write side. zstdx pre-parses the 3-byte block header to compute exactly how many staged bytes the next block plus trailer needs, because the inner `FrameDecoder` poisons itself on starved reads, at `crates/zstdx/src/stream/write.rs:Decoder::next_block_need` and `pump`. Libzstd copies into an internal `inBuff` decoded across explicit stages at `lib/decompress/zstd_decompress_internal.h:ZSTD_dStreamStage`.
- Parameter and level architecture. zstdx uses a closed enum of five strategy forms with a const 23-row `LEVEL_PARAMS` ladder indexed by numeric level, and shrinks window, hash and chain logs to a known source length at runtime, at `crates/zstdx/src/level.rs:Level::approximate_zstd` and `crates/zstdx/src/encoding/match_generator/params.rs:LEVEL_PARAMS` and `adjust_params`. C uses 22 numeric levels times 4 input-size classes of full cParam tuples with the same shrinking done in `lib/compress/zstd_compress.c:ZSTD_adjustCParams_internal`, at `lib/compress/clevels.h:ZSTD_defaultCParameters`.
- MT engagement demotion. zstdx silently falls back to the single-thread path for inputs below 2 MiB, `workers < 2`, `Level::Uncompressed` and single-core machines, byte-identical to the ST entry point, at `crates/zstdx/src/encoding/mt.rs:compress_slice_mt` and the `small_inputs_fall_back_identically` test. Libzstd honors `nbWorkers` as configured, and only the CLI decides between `-T1` and `--single-thread`.
- Error model. zstdx uses Rust `Result` with `#[non_exhaustive]` thiserror enums, an umbrella `Error` over Frame, Dictionary, Io, Unsupported and Parameter that converts into io::Error for std and no_std, and an "API ahead of implementation" case encoded as a `Feature` enum value, at `crates/zstdx/src/error.rs:Error`, `Feature` and `into_io`. C uses `size_t` error codes with `ZSTD_isError`, `ZSTD_getErrorName` and `RETURN_ERROR_IF` macros at `lib/zstd.h:ZSTD_getErrorCode`.
- No-std support. A minimal io module with Read and Write traits and `ErrorKind` lets the whole library build without std, with MT gated off entirely, at `crates/zstdx/src/io_nostd.rs` and `crates/zstdx/src/stream/encoder_core.rs:FrameEncoderCore::new`, which returns `Error::Unsupported`. Libzstd has no io layer at all, reading and writing caller-supplied buffers, with `lib/common/zstd_deps.h` for allocation only.

### Architecture and systems: zstdx-only

- Parallel decompression by restart-point segmentation. The design appears under Decoder B, and the systems entry point is `crates/zstdx/src/bulk.rs:decompress_to_buffer_with` through `DecoderOptions::threads`. It relies on exactly the block shape that MT and job encoders emit at job boundaries.
- Offloaded frame-checksum thread. A dedicated "zstdx-xxh64" worker consumes an SPSC ring of posted byte ranges with 512 slots, using spin-then-park handoff with a 32768-iteration budget so no post is missed. Multiple concurrent frames multiplex by state ids over one ring, and Drop drains pending posts before the input can die. The code is `crates/zstdx/src/encoding/async_checksum.rs:AsyncChecksum`, `Producer::post` and `run`. Nothing similar exists in `lib/`, where the checksum is always inline as described under A.
- Burst-deterministic streaming job grid. Streaming MT jobs are cut on boundaries derived from absolute stream offsets alone. A pledged stream uses `job k = job_start + k*job_size`, and an unpledged stream uses a growing schedule that sizes the job at offset `o` for an input of `4o` bytes. Without explicit flushes, the frame bytes are therefore independent of how writes were chunked. Flush is the documented exception that re-grids, at `crates/zstdx/src/stream/encoder_mt.rs:JobGrid`, `job_end` and `flush_block`. Libzstd's streaming MT output depends on how `ZSTD_compressStream2` calls arrive, at `lib/compress/zstdmt_compress.c:ZSTDMT_compressStream_generic`.
- Pledged-stream and bulk byte identity. The streaming MT core shares `job_size_for` with the bulk path and holds back the final pledged-grid job until `finish()`, so a stream written exactly to its pledge is byte-identical to bulk MT output. The hold-back lapses on pledge overshoot through the `pos <= n` guard, at `crates/zstdx/src/stream/encoder_mt.rs:pending` and [mt-stream](perf/mt-stream.md). No equivalent guarantee exists in `lib/`, which has no shared sizing between `ZSTDMT_initCStream_internal` and one-shot compression.
- Periodic-repeat seed at job start. The mechanics appear under Encoder B. From the systems side it fixes periodic corpora whose period exceeds what table-only matching reaches, where libzstd relies on dense dictionary or table fill. `lib/compress/` has no counterpart.
- AVX-512 micro-kernels with runtime dispatch inside the codec. The matcher seed scan and non-temporal table clears appear under Encoder B, and the histogram and bit-writer kernels appear under Entropy B. A hand-written whole-loop asm gear scan sits at `crates/zstdx/src/encoding/ldm.rs:gear_run`. Libzstd's own kernels use SSE and AVX2-era intrinsics with compile-time gating, and the only AVX-512 in `lib/` is the vendored `lib/common/xxhash.h` accumulate variant gated by compile-time `__AVX512F__`.
- Borrowed-window zero-copy slice path. The mechanics appear under Encoder A, driven by `crates/zstdx/src/encoding/frame_compressor.rs:compress_slice_to_vec`. It eliminates the window copy, compaction and staging buffer of the classic design at `lib/compress/zstd_compress.c:ZSTD_window_update` into roundBuff.
- Output-shape regression contracts as infrastructure. Byte identity between slice and streaming paths, MT versus ST ratio-loss bounds, cross-run determinism, dump-based cross-build snapshots, and a corruption smoke tool where flipped bytes must error and never panic. The code is in `crates/zstdx/src/encoding/mt.rs` tests `mt_output_is_deterministic` and `mt_ratio_stays_close_to_single_thread`, `crates/zstdx/src/encoding/frame_compressor.rs:level_ladder_roundtrips`, `crates/zstdx-bench/src/cmd/dump.rs` and `crates/zstdx-bench/src/cmd/corrupt.rs`. Libzstd tests through zstreamtest and fuzzers and does not pin encoder byte determinism as a contract, since its MT output depends on the job schedule.
- Compat shim that mirrors the Rust `zstd` crate API, the libzstd bindings, on top of the native engine. It provides numeric levels, `io::Result`, the `zstd::bulk` and `zstd::stream` module shapes, and `set_pledged_src_size`, `include_checksum`, `multithread` and dictionary constructors applied until stream start, at `crates/zstdx/src/compat/mod.rs`, `bulk.rs` and `stream.rs:EncoderState`. The C library is itself the native API, so it has no analogous layer.
- Executor-agnostic streaming core. Single-threaded and burst-MT frame encoders sit behind one enum with identical interfaces, so the read and write wrappers never know which one runs. The code is `crates/zstdx/src/stream/encoder_core.rs:FrameEncoderCore` with `Single` and `Mt`. Libzstd switches between `ZSTD_compressStream_generic` and `ZSTDMT_compressStream_generic` inside one function with different buffering layers.

### Architecture and systems: gaps

- Superblocks and target compressed block size. C re-encodes a group of blocks as sub-blocks sharing one entropy frame, exposed as `ZSTD_c_targetCBlockSize` and CLI `--target-compressed-block-size=`, at `lib/compress/zstd_compress_superblock.c:ZSTD_compressSuperBlock`, `lib/zstd.h` and `programs/zstdcli.c:usage_advanced`. zstdx carries the layout half that pays on this engine, because small known-length frames emit their Huffman literals sections as one stream through `LitStreams` in `crates/zstdx/src/encoding/block_enc/compressed.rs`. The wholesale sub-block re-entropy machinery is falsified for ratio and stays out, as recorded in [negative](negative/entropy.md)'s `ZSTD_compressSuperBlock` entry and under Entropy C.
- LDM window scale. Libzstd's `--long` reaches windowLog 27 and above. zstdx's auto LDM tops out at W26, and the explicit enable through `LdmMode::Enable` and FFI `ZSTD_c_enableLongDistanceMatching` raises the window to 27. Cross-job LDM history exists on both sides: libzstd serializes the rolling state through the job stream at `lib/compress/zstdmt_compress.c:ZSTDMT_serialState_reset`, and zstdx's capture bands fill or adopt per-job window spans through a snapshot ring or a cold self-fill at `crates/zstdx/src/encoding/ldm.rs`, with the mechanism in [matchers](perf/matchers.md).
- Rsyncable job boundaries. C uses rolling-hash synchronization points so compressed output stays stable under insertions, at `lib/compress/zstdmt_compress.c:RSyncState_t` and `findSynchronizationPoint` and CLI `--rsyncable`. zstdx job boundaries are purely size-derived at `crates/zstdx/src/encoding/mt.rs:job_size_for`.
- Mid-stream parameter adaptation. C can change cParams while compressing, applied to the next job, with adaptive level driven by I/O rate and stable in and out buffer modes that avoid copies, at `lib/compress/zstdmt_compress.c:ZSTDMT_updateCParams_whileCompressing` and `lib/compress/zstd_compress.c:ZSTD_compressStream2`. zstdx options are fixed at construction, and mutation after start reports `ParameterError::AlreadyStreaming` at `crates/zstdx/src/options.rs:EncoderOptions`, `crates/zstdx/src/error.rs:ParameterError` and `crates/zstdx/src/compat/stream.rs:EncoderState`. The CLI's `--adapt` walks the level per 8 MiB chunk frame instead, as concatenated frames with the reference's thresholds and 1/6 s refresh, at `crates/zstdx-cli/src/adapt.rs`, so history does not carry across chunk boundaries and streams under one chunk never step. `--patch-from` is a construction-time prefix, not a mid-stream one.
- Strategy-row selection by source size. C's srcSize profiles can pick a cheaper strategy row, and `ZSTD_CParamMode_e` differentiates dictionary attach from standalone, at `lib/compress/zstd_compress.c:ZSTD_adjustCParams_internal` and `ZSTD_CCtx_init_compressStream2` and CLI `--stream-size` and `--size-hint`. zstdx shrinks only window and table logs from the pledge at `crates/zstdx/src/encoding/match_generator/params.rs:adjust_params`, as recorded under Encoder C.
- Encode-side dictionary API breadth. C has attach and load-prefix modes, per-job dictionary reload in MT, and `dedicatedDictSearch`, at `lib/compress/zstd_compress.c:ZSTD_CCtx_refCDict`, `ZSTD_CCtx_refPrefix` and `ZSTD_CCtx_loadDictionary`, and `ZSTDMT_initCStream_internal`. zstdx carries the attach paths through `crates/zstdx/src/options.rs:EncoderOptions::dictionary`, `parsed_dictionary` and `with_ref_prefix`, the parsed `EncoderDictionary`, FFI CDict and CLI `-D`, with MT dictionary on both job paths. What stays absent are the matcher-side dictionary template modes from Encoder C and libzstd's cross-thread shared CDict match state, because the seed images here ride per-thread pooled states.
- Block and frame splitter controls. C exposes `ZSTD_c_blockSplitterLevel` and `ZSTD_c_splitAfterSequences`, experimental params 20 and 21 in `lib/zstd.h`. zstdx's splitter runs auto on the opt rows with no knobs, and the machinery itself is ported as described under Similarities.
- Incremental job output progress. C flushes compressed bytes before a job finishes, with `dstFlushed` advanced mid-job, `ZSTDMT_toFlushNow` and `ZSTDMT_getFrameProgression` at `lib/compress/zstdmt_compress.c`. zstdx emits output only per completed job at `crates/zstdx/src/encoding/mt.rs:slots`, which trades latency granularity for simplicity.
- User-facing shared thread pool. C creates a pool once, shares it across CCtxs and resizes it at runtime, at `lib/common/pool.c:POOL_resize` and `lib/zstd.h:ZSTD_createThreadPool`. zstdx's pools are internal at `crates/zstdx/src/stream/mt_pool.rs`, with worker leases and states that idle-retire after 5 s, and there is no create, share or resize API. The bulk path still spawns threads per call.
- CLI tail. C covers format conversion for gzip, xz and lz4, memory limits, sparse and pass-through, async IO, and full `--zstd=` pass-through, at `programs/zstdcli.c:usage` and `usage_advanced`. The zstdx CLI covers zstd 1.5.7's non-experimental argument surface with clap and tracing and indicatif progress: multi-file, recursive and stdin-stdout modes, `-t` test, `-c`, `-o`, `-k`, `-rm` and `-f`, `-T`, levels 1-22, `--fast`, `--ultra`, `-D` dictionaries, `--long`, `--no-check`, `--stream-size`, `--size-hint`, `-M`, `--filelist`, `--single-thread`, `-l` listing, `--train`, `-b#` benchmarks, `--patch-from` and `--adapt`, at `crates/zstdx-cli/src/main.rs`.
- Test and bench infrastructure. C has decoder corpus generation, stream, CLI and fuzz suites including `dictionary_round_trip` and an external_matchfinder plug-in harness, a regression framework, and benchfn-based benchzstd with datagen, at `tests/decodecorpus.c`, `tests/zstreamtest.c`, `tests/fuzz/`, `tests/regression/` and `programs/benchzstd.c`. zstdx relies on in-crate Rust tests that cross-check against libzstd itself, through dev-dependency interop assertions and fuzz-artifact replay in `crates/zstdx/src/encoding/frame_compressor.rs:fuzz_targets`. It has ten cargo-fuzz targets in `crates/zstdx-fuzz/fuzz_targets/`: `encode`, `encode_stream`, `decode`, `decode_dict`, `decode_mt`, `fse`, `huff0`, `interop`, `dict_pooled` and `ldm_mt_parity`. Its bench crate provides correctness-gated subcommands including an interleaved A/B matrix against the zstd crate, at `crates/zstdx-bench/src/main.rs:Command`.
- Partial-output streaming control. C offers caller-owned in and out buffers with per-call pos and size advancement and three end directives, which allow flush throttling and zero-copy stable buffers, at `lib/compress/zstd_compress.c:ZSTD_compressStream2` with `ZSTD_inBuffer`, `ZSTD_outBuffer` and `ZSTD_EndDirective`, and decode-side `ZSTD_d_stableOutBuffer`. zstdx's io-trait wrappers own the buffering at `crates/zstdx/src/stream/write.rs:Encoder::drain` and expose only write, flush and finish boundaries.
- Recommended input-size and buffer-expectation protocol. C has `ZSTD_CStream_InSize` and `OutSize` plus runtime `ZSTD_setBufferExpectations` checks per stage. zstdx exposes only static constants, with `crates/zstdx/src/stream/write.rs:Encoder::recommended_input_size` at one block, and enforces no expectations.

## Summary

- zstdx's structural wins are throughput-shaped: MT decode, which upstream lacks, fused and packed encode pipelines, borrowed windows, pooled-state determinism, and encoder-side AVX-512. All of them work without changing the wire format. The 2026-10-18 release snapshot puts the encoder geo-mean at 8.69% denser over 120 cells, decode ST bulk winning 17 of 18 cells, and decode ST streaming 1.04x to 1.34x behind on compressible shapes, at [snapshot](bench/snapshot.md).
- The matcher and splitter side now runs ported or home-grown equivalents with measured deviations: the tagged row matcher on rows 5-12, the gap-parse LDM consumers, and the screened pre-splitter. The remaining ratio risk concentrates in the entropy-decision margins, where float Shannon bounds on the fresh-table pre-comparisons cap small-payload decisions against zstd's exact fixed-point costs.
- The decode gap is narrow. zstdx's Rust fast loops sit within about 10% of libzstd's hand-written asm per [decoding](perf/decoding.md), while literals-in-dst, prefetch variants, DDict zero-copy and DSB alignment remain unported. The dll-class binary payload is where zstdx's density lead is largest, at 12.8% to 16.5% smaller output from best up and 49.6% and 31.7% smaller at fastest and fast.
- Feature-completeness gaps are mostly API-level rather than format-level: superblocks, rsyncable boundaries, mid-stream parameter changes, the dictionary matcher modes, and the CLI and FFI tail. All are additive work on an already format-complete codec.
