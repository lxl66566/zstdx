# zstdx vs. official zstd

This document compares **zstdx** — this repo's pure-Rust zstd implementation, a fork of KillingSpark/zstd-rs (ruzstd) with a from-scratch encoder added (`crates/zstdx/src`, CLI `crates/zstdx-cli`, bench `crates/zstdx-bench`) — against **official zstd v1.6.0**, the C reference implementation (`/root/programs/fork/zstd`, library `lib/`, CLI `programs/`), across four domains: encoder front-end, entropy coding, decoder, and systems architecture; citations use `crates/zstdx/src/...:symbol` vs `lib/...:symbol`.

## How to read this document

Differences come in three categories, used as sub-section markers in every domain: **A** — zstdx solves a problem both sides share with its own approach (includes documented ports that deviate); **B** — zstdx-only techniques with no counterpart in official zstd; **C** — official-zstd techniques zstdx lacks (gaps). Machinery the zstd format mandates (wire layout, FSE spread, repcode semantics, block framing, ...) is excluded from "differences" and only appears under Similarities.

Every claim below was code-verified against both trees with the cited symbols; "unverified" is kept where verification was out of scope. Two corrections made during analysis are reflected throughout: the AVX-512 VBMI kernels are **encoder-side only** (`crates/zstdx/src/encoding/blocks/compressed.rs:histogram_small_alpha_avx512`, `crates/zstdx/src/bit_io/bit_writer.rs:uniform4_pack_avx512`) — the zstdx decoder contains no SIMD at all, just 16-byte u128 copies and BMI2 dispatch; and zstdx's whole-window MT overlap (see Architecture A) is *larger* than libzstd's default `overlapLog` fraction, a deliberate deviation, not an oversight.

## Similarities

### Format-mandated

- Frame/block framing: header descriptor, window descriptor (10+exp), dictID/FCS widths, skippable magic 0x184d2a50..=5f, 3-byte block headers with Raw/RLE/Compressed types and the 128 KiB cap, default 128 MiB window limit — `crates/zstdx/src/decoding/frame.rs:read_frame_header`/`is_skippable_magic`, `crates/zstdx/src/decoding/block_decoder.rs:read_block_header`, `crates/zstdx/src/decoding/frame_decoder.rs:DEFAULT_MAX_WINDOW_SIZE` vs `lib/decompress/zstd_decompress.c:ZSTD_getFrameHeader_advanced`/`readSkippableFrameSize`/`ZSTD_getcBlockSize`, `lib/zstd.h:ZSTD_WINDOWLOG_LIMIT_DEFAULT`.
- FSE: spread step `p += (ts>>1)+(ts>>3)+3`, low-probability (−1) symbols at table top, decode-entry recurrence, NCount wire format, predefined LL/ML/OF distributions (logs 6/6/5), RLE routed through a degenerate one-cell table — `crates/zstdx/src/fse/fse_decoder.rs:build_decoding_table`/`read_probabilities`, `crates/zstdx/src/decoding/sequence_section_decoder.rs:pack_rle_entry`, `crates/zstdx/src/fse/fse_encoder.rs:LL_DIST/ML_DIST/OF_DIST` vs `lib/common/fse.h:FSE_TABLESTEP`, `lib/common/fse_decompress.c:FSE_buildDTable_internal`, `lib/common/entropy_common.c:FSE_readNCount_body`, `lib/common/zstd_internal.h:LL_defaultNorm`, `lib/decompress/zstd_decompress_block.c:ZSTD_buildSeqTable_rle`.
- Sequence coding: LL/ML/OF code ladders with dense LUTs below 64/131, table-modes byte (ll:6|of:4|ml:2), backward encoding with initial states from the last sequence and ML→OF→LL flush, repcode semantics incl. the ll0 swap — `crates/zstdx/src/encoding/seq_codes.rs:LL_META/ML_META`, `crates/zstdx/src/encoding/blocks/compressed.rs:encode_sequences`, `crates/zstdx/src/decoding/sequence_execution.rs:do_offset_history` vs `lib/common/zstd_internal.h:LL_bits/ML_bits`, `lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body`, `lib/decompress/zstd_decompress_block.c:ZSTD_decodeSequence`.
- Huffman wire format: weight-list description (raw 4-bit or FSE-compressed, weight-FSE tableLog ≤ 6, interleaved states), weights→table math, 4-stream literals with 6-byte LE16 jump table and `(n+3)/4` split, all size formats, X1/X2 entry layouts — `crates/zstdx/src/huff0/huff0_encoder.rs:HuffmanEncoder::write_table`, `crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_literals`, `crates/zstdx/src/huff0/huff0_decoder.rs:build_x2_table` vs `lib/compress/huf_compress.c:HUF_writeCTable_wksp`/`HUF_compressWeights`, `lib/common/entropy_common.c:HUF_readStats_body`, `lib/decompress/huf_decompress.c:HUF_DEltX1`/`HUF_DEltX2`.
- Bit-IO directions: LSB-first writer with whole-byte flush; reversed readers keep an LE u64 window consumed from the MSB — `crates/zstdx/src/bit_io/bit_writer.rs:BitWriter::write_bits_64`, `crates/zstdx/src/bit_io/bit_reader_reverse.rs:BitReaderReversed::refill` vs `lib/common/bitstream.h:BIT_addBits`/`BIT_initDStream`/`BIT_reloadDStream`.
- Checksum, dictionaries, budgets: XXH64 truncated to 32 bits and computed only when the flag is set, dict content reachable only until output exceeds the window, per-sequence output-overrun rejection, trailing empty last block on empty/exact-multiple input — `crates/zstdx/src/decoding/decode_buffer.rs:set_checksum_enabled`/`repeat_from_dict`, `crates/zstdx/src/encoding/frame_compressor.rs:trailing_empty` vs `lib/decompress/zstd_decompress.c:ZSTD_decompressBegin`, `lib/compress/zstdmt_compress.c:ZSTDMT_writeLastEmptyBlock`, `lib/decompress/zstd_decompress_block.c:ZSTD_execSequenceEnd`.

### Ported machinery

- Matcher family and optimal parser are per-tier ports: single-probe fast with ip0/ip1 pipeline, 8-byte/5-byte dfast double hash, head+chain lazy search, and the full `zstd_opt.c` port (bt1 insertion, all-matches collection, price algebra ×256, rescale/scale/update stats, btultra2 two-pass first block) — `crates/zstdx/src/encoding/match_generator.rs:start_matching_fast`/`start_matching_dfast`/`start_matching_chain`, `crates/zstdx/src/encoding/opt.rs:Finder::insert_bt1`/`get_all_matches`/`bit_weight`/`rescale_freqs` vs `lib/compress/zstd_fast.c:ZSTD_compressBlock_fast_noDict_generic`, `lib/compress/zstd_double_fast.c:ZSTD_compressBlock_doubleFast_noDict_generic`, `lib/compress/zstd_lazy.c:ZSTD_HcFindBestMatch`, `lib/compress/zstd_opt.c:ZSTD_insertBtAndGetAllMatches`/`ZSTD_rescaleFreqs`/`ZSTD_initStats_ultra`.
- FSE normalization and NCount writing are documented ports (`normalize_count`/`normalize_m2`/`optimal_table_log`/`RTB_TABLE` vs `lib/compress/fse_compress.c:FSE_normalizeCount`/`FSE_normalizeM2`/`FSE_optimalTableLog`, same rtbTable constants); Huffman X1/X2 decode fast loops and the X1/X2 choice are explicit ports incl. the `algoTime` cost table — `crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved[_x2]`/`select_x2_table` vs `lib/decompress/huf_decompress.c:HUF_decompress4X1_usingDTable_internal_fast_c_loop`/`HUF_selectDecoder`.
- Decode-execute fusion ("the libzstd model" per its doc) with the wildcopy copy stack (dec32/dec64 overlap tables) — `crates/zstdx/src/decoding/block_decoder.rs:decompress_block_flat`, `crates/zstdx/src/decoding/sequence_execution.rs:wildcopy_literals`/`overlap_copy8` vs `lib/decompress/zstd_decompress_block.c:ZSTD_decompressSequences_body`, `lib/common/zstd_internal.h:ZSTD_wildcopy`, `ZSTD_overlapCopy8`.
- Dictionary training descends from the same cover/fastcover paper (epoch partitioning, per-epoch best segment, epochs function ported verbatim) — `crates/zstdx/src/dict/cover.rs:pick_best_segment`/`compute_epoch_info` vs `lib/dictBuilder/cover.c:COVER_selectSegment`, `fastcover.c:FASTCOVER_selectSegment`/`COVER_computeEpochs`.
- Per-stream entropy mode selection (RLE/predefined/repeat/custom decision tree with fast-strategy threshold constants) and sequence-code computation — `crates/zstdx/src/encoding/blocks/compressed.rs:select_from_counts`, `crates/zstdx/src/encoding/seq_codes.rs:pack_seq` vs `lib/compress/zstd_compress_sequences.c:ZSTD_selectEncodingType`, `lib/compress/zstd_compress_internal.h:ZSTD_LLcode`/`ZSTD_MLcode`.

### Converged design

- 4-lane position-mod-4 histograms recombined at the end, chosen for OoO friendliness on both sides — `crates/zstdx/src/encoding/blocks/compressed.rs:histogram_literals` vs `lib/compress/hist.c:HIST_count_parallel_wksp`.
- MT job invariants: first block of every job is self-describing (entropy reset), repcodes gated until three literal-offset sequences rewrite history, overlap strip indexed into the search tables, job size floored/capped (1 MiB / 1 GiB), warm per-worker state pooled, worker failures deferred to ordered assembly, MT auto-engages only with >1 usable core — `crates/zstdx/src/encoding/match_generator.rs:gate_repcodes`/`prefill_window`, `crates/zstdx/src/encoding/mt.rs:MAX_JOB_SIZE`/`MIN_JOB_SIZE`/`poison`, `crates/zstdx/src/encoding/frame_compressor.rs:take_slice_state` vs `lib/compress/zstdmt_compress.c:ZSTDMT_compressionJob`/`ZSTDMT_JOBSIZE_MAX`/`ZSTDMT_getCCtx`/`JOB_ERROR`, `lib/compress/zstd_compress.c:ZSTD_invalidateRepCodes`.
- Streaming architecture: pull decoder core + Read/Write wrappers, pledged size written into the frame header, decode output buffer sized window + 2·block + overlength, BMI2 runtime CPU-feature dispatch — `crates/zstdx/src/stream/write.rs:Encoder::auto_finish`, `crates/zstdx/src/encoding/frame_header.rs:FrameHeader.frame_content_size`, `crates/zstdx/src/decoding/flat_buffer.rs:ensure_block_space`, `crates/zstdx/src/decoding/sequence_section_decoder.rs:decode_sequences` vs `lib/compress/zstd_compress.c:ZSTD_compressStream2`/`ZSTD_CCtx_setPledgedSrcSize`, `lib/decompress/zstd_decompress.c:ZSTD_decodingBufferSize_internal`.

## Encoder front-end

### A. Own approach to a shared problem

- Dictionary trainer estimator: reservoir-sampled collection (Algorithm L, `crates/zstdx/src/dict/reservoir.rs:Reservoir::fill`) with rolling Karp-Rabin k-mer frequency (`crates/zstdx/src/dict/frequency.rs:estimate_frequency`), segments fixed at 2 KiB, k=16, streaming-friendly (`crates/zstdx/src/dict/mod.rs:create_raw_dict_from_source`); official fastcover computes exact whole-corpus d-mer frequencies into a 2^f bucket table (f=20, d=8, k=2000, splitPoint 0.75, accel table — `lib/dictBuilder/fastcover.c:FASTCOVER_defaultAccelParameters`) over in-memory samples and finishes with `ZDICT_finalizeDictionary` (entropy tables + header); zstdx emits raw content dictionaries only, with no encode-time dictionary loading path (unverified whether any high-level API accepts one).
- 32-bit hash entries with positional reconstruction: `(pos & 0xffff_ffff)+1` keeps zero as dead sentinel and rebuilds high bits from the scan position (`crates/zstdx/src/encoding/match_generator.rs:pack_pos`/`unpack_pos`), halving the hot table working set (Balanced 16→8 MiB); C keeps full U32 window indices validated against `window.lowLimit`/`minChain` (`lib/compress/zstd_lazy.c:ZSTD_HcFindBestMatch`).
- Epoch-tagged opt tables: `(epoch<<48)|pos` u64 entries invalidated by bumping a 16-bit epoch instead of clearing (`crates/zstdx/src/encoding/match_generator.rs:MatchGeneratorDriver::reset`, `crates/zstdx/src/encoding/opt.rs:Finder::resolve`); C validates against `windowLow`/`btLow`/`nextToUpdate` and rewinds window limits for the btultra2 stat seed (`lib/compress/zstd_opt.c:ZSTD_insertBtAndGetAllMatches`/`ZSTD_initStats_ultra`).
- Offset-gain store gate: `crates/zstdx/src/encoding/match_generator.rs:pays_for_offset` (`ml*4 >= ilog2(offset)+7`, reps exempt) refuses hash-path candidates whose offset code outweighs the length — derived from libzstd's lazy gain arithmetic (`lib/compress/zstd_lazy.c:ZSTD_compressBlock_lazy_generic`) but applied as an emission gate, which C never does; the +7 margin is zstdx-tuned.
- Fast-tier acceptance threshold: matches below 6 bytes found via the 5-byte hash are rejected (`crates/zstdx/src/encoding/match_generator:start_matching_fast`), with a 2^15-slot table; C's fast accepts every ≥mls candidate (`lib/compress/zstd_fast.c:_offset`) — ratio/speed tuning of the same single-probe design.
- Miss-step curve: zstdx grows the probe step quadratically with the literal run, `1 + min(miss_count>>2, 255)`; C grows linearly (`step++` per `kStepIncr=128` bytes, `lib/compress/zstd_fast.c:_start`) — same problem, zstdx-chosen curve justified against its denser tables.
- Zero-copy slice architecture: the match window borrows the caller's buffer via raw pointer (`crates/zstdx/src/encoding/match_generator.rs:adopt_window`/`ExtWindow`, driven by `crates/zstdx/src/encoding/frame_compressor.rs:compress_slice_to_vec`), eliminating the read pass, window compaction and window allocation; C always copies input into the internal window (`lib/compress/zstd_compress.c:ZSTD_window_update`); byte-identity between streaming and slice paths is asserted in tests.
- Window policy: fixed 768 KiB at Fastest, 1 MiB above (`crates/zstdx/src/encoding/match_generator.rs:MAX_WINDOW`/`FAST_PARAMS`/`BALANCED_PARAMS`), independent of level and input size — deliberately below clevels.h W21-W27, an A/B-measured decision (wider windows without LDM only find farther, not longer, matches).
- Job prefill indexing is covered under Architecture A (strip indexing style) — the stride constant is shared with C's `fastHashFillStep` but applied to a job-model need C does not have.

### B. zstdx-only

- Job-start seed offset for periodic repeats: prefill scans the strip tail for a position whose 8 bytes plus 48 backward bytes agree with the anchor (`crates/zstdx/src/encoding/match_generator.rs:acquire_seed`/`seed_scan`/`SEED_AGREE`) and installs its distance as a direct probe; three seed emissions rotate `rep` onto the period, with an 8192-probe retirement budget (`SEED_MATCHES`/`SEED_BUDGET`); C has nothing analogous — on clumped periodic data its single-probe slots are buried by recent same-hash recurrences.
- AVX-512 kernels inside the matcher: occupancy-mask seed scan over 8 overlapping 64-byte loads per 64-candidate block (`crates/zstdx/src/encoding/match_generator.rs:seed_scan_avx512`) and non-temporal streaming table clears above 4 MiB of slots (`clear_table_avx512`); official front-end SIMD is limited to the row-hash tag compare (`lib/compress/zstd_lazy.c:ZSTD_row_getMatchMask`, SSE/NEON/RVV) — no AVX-512, no streaming stores anywhere in `lib/compress`.
- Packed single-stream sequence collection: one 24-byte `SeqWord` per sequence (ll/ml/of codes + pre-merged add-bits + width; a 16-byte pack was measured and rejected — see negative.md), consumed by table selection, table description and bitstream without materializing raw triples (`crates/zstdx/src/encoding/seq_codes.rs:pack_seq`, fused histogram pass in `crates/zstdx/src/encoding/blocks/compressed.rs:choose_tables_fast`); C's `SeqStore_t` stores raw (offBase, ll, ml) triples and recomputes codes later (`lib/compress/zstd_compress_internal.h:ZSTD_storeSeq`, `lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences`).
- Zero-sequence block bypass: literals stay in the window and the block encoder reads them directly, with an early Raw verdict from the sampled entropy gate before any encode-and-discard writes (`crates/zstdx/src/encoding/blocks/compressed.rs:compress_block`); C routes every block through the seqStore/literal buffer (`lib/compress/zstd_compress.c:ZSTD_buildSeqStore`).
- Sampled incompressibility gate: strided ~1024-point literal sample with Miller-Madow bias correction, distinct>208 prescreen, sticky `gate_hold` across blocks (`crates/zstdx/src/encoding/blocks/compressed.rs:sampled_gate_rejects`); C's only analogue is the `suspectUncompressible` hint (`lib/compress/zstd_compress.c:ZSTD_compressLiterals`), without sampling or an entropy-floor estimator.
- Fastest-tier table pressure as a first-class tuning axis: 2^15 entries, ml≥6 acceptance, dual-anchor sparse indexing of long matches (`TableEmit::emit`, ≤16 B dense / else start+2 & end-2), newest-wins proximity bias — a measured redesign of C's fill policy (`lib/compress/zstd_fast.c:_match`, mls=7, 2^14-2^16 table); analysis in `docs/src/dev/perf/matchers.md`.
- Fused checksum absorption: the RLE uniformity scan runs XXH64 rounds inline, raw-block copies hash while copying, with a sidecar-thread offload (`crates/zstdx/src/encoding/levels/fastest.rs:compress_fastest`, `crates/zstdx/src/encoding/frame_compressor.rs:BlockChecksum`/`SliceChecksum::Offload`); C hashes frame content in separate passes (`lib/compress/zstd_compress.c:XXH64_update`) — topology details under Architecture A.

### C. Gaps vs. official zstd

- Long-distance matching: gear-hash rolling matcher with bucketed entries and sequence splitting, auto-enabled for btopt+ at windowLog≥27 (`lib/compress/zstd_ldm.c:ZSTD_ldm_blockCompress`, `lib/compress/zstd_compress.c:ZSTD_resolveEnableLdm`); zstdx has none — with its 1 MiB ceiling this is the main large-input ratio gap at high tiers.
- Block splitting: 2-byte Knuth-hash fingerprint splitter plus the sequence-aware re-splitter, auto-enabled for btopt+ W≥17 (`lib/compress/zstd_preSplit.c:ZSTD_splitBlock`, `lib/compress/zstd_compress.c:ZSTD_resolveBlockSplitterMode`/`ZSTD_compressBlock_splitBlock_internal`); zstdx always emits 128 KiB blocks (only RLE/raw fallback exist).
- Row-hash matchfinder: per-row byte tags + head index, cached incremental hashing, salted epochs, SIMD tag masks, auto-selected for greedy/lazy/lazy2 (`lib/compress/zstd_lazy.c:ZSTD_RowFindBestMatch`/`ZSTD_row_getMatchMask`/`ZSTD_resolveRowMatchFinderMode`); zstdx's Balanced tier uses plain hash chains only.
- btlazy2: binary-tree search over hash chains for official levels 13-15 (`lib/compress/zstd_lazy.c:ZSTD_insertDUBT1`/`ZSTD_DUBT_findBestMatch`); zstdx substituted a cheap opt parser for this tier (`BEST_KNOBS`) and never implements DUBT — an explicit quality-tier substitution.
- Input-size adaptive parameters: 4 srcSize profiles in `lib/compress/clevels.h:ZSTD_defaultCParameters` selected by `ZSTD_getCParams`, negative levels, per-level knobs (searchLog/chainLog/targetLength/minMatch); zstdx has one fixed param set per tier with compile-time window/`hash_log` (`crates/zstdx/src/encoding/match_generator.rs:LevelParams`).
- Dictionary-aware compression: noDict/dictMatchState/extDict/dedicatedDictSearch template modes for every strategy (`lib/compress/zstd_fast.c:ZSTD_compressBlock_fast_dictMatchState_generic`, `lib/compress/zstd_lazy.c:ZSTD_dedicatedDictSearch_lazy_search`, `ZSTD_count_2segments` plumbing); zstdx encodes noDict only — prefix/extDict matching, attached dicts and trained-dict loading at encode time are absent (its `dict/` module only trains raw content for external consumers).
- Greedy/lazy spectrum granularity: official levels 5-12 sweep greedy→lazy→lazy2 with searchLog 3-6 and targetLength 0-32; zstdx compresses this band into one Balanced config (depth 8, lazy_depth 2, H20, 1 MiB window); also absent: `lazySkipping` insert suppression (`lib/compress/zstd_lazy.c:ZSTD_insertAndFindFirstIndex_internal`), superseded by the miss-step growth.
- Cost-exact entropy mode selection at high strategies: C compares exact FSE costs (`ZSTD_crossEntropyCost` vs `ZSTD_fseBitCost` vs `ZSTD_NCountCost`, `lib/compress/zstd_compress_sequences.c:ZSTD_selectEncodingType`); zstdx always uses the fast-strategy thresholds plus an approximate repeat comparison — see Entropy A/B/C.

## Entropy coding

### A. Own approach to a shared problem

- FSE encoder table representation: zstdx keeps a flat per-(symbol,state) array of packed u32 entries `(next_index << 16) | (num_bits << 12) | baseline` with power-of-two row stride (`crates/zstdx/src/fse/fse_encoder.rs:FSETable::transition`, acc_log ≤ 12); official's CTable stores no baseline — a u16 `stateTable` of next states plus `symbolTT{deltaNbBits, deltaFindState}` from which nbBits is derived on the fly (`lib/compress/fse_compress.c:FSE_buildCTable_wksp`, `lib/common/fse.h:FSE_encodeSymbol`); zstdx trades a bigger table for one load per transition, official trades two small arrays for shifts/adds.
- FSE encode loop mechanics follow from the table choice: zstdx writes `state_index − precomputed_baseline` in precomputed `num_bits` (`crates/zstdx/src/fse/fse_encoder.rs:FSEEncoder::encode_interleaved`); official writes bits derived from the scaled delta fields at encode time (`lib/compress/fse_compress.c:FSE_compress_usingCTable_generic`) — wire-identical.
- NCount writer: zstdx recomputes each field width from `2^acc − counter + 1` with a low-threshold nibble test (`crates/zstdx/src/fse/fse_encoder.rs:FSETable::write_table`); official threads a `remaining`/`threshold`/`nbBits` ladder with a `count >= threshold → count += max` correction (`lib/compress/fse_compress.c:FSE_writeNCount_generic`) — same wire, independently derived bookkeeping.
- NCount reader: zstdx reads bit-at-a-time through its forward `crates/zstdx/src/bit_io/bit_reader.rs:BitReader`, skipping zero runs 2 bits at a time (`crates/zstdx/src/fse/fse_decoder.rs:read_probabilities`); official parses a forward 32-bit LE window, decides width with `(bitStream & (threshold-1)) < max`, and consumes zero runs up to 12 groups per iteration via `countTrailingZeros32` (`lib/common/entropy_common.c:FSE_readNCount_body`).
- Huffman code construction: zstdx computes optimal length-limited code lengths with boundary package-merge (Larmore–Hirschberg), Kraft-exact and capped at 11 (`crates/zstdx/src/huff0/huff0_encoder.rs:package_merge_lengths`; docs note json Ultra ratio 7.33→7.52 vs the replaced rank ladder); official builds an unlimited-depth tree then repairs depth with the heuristic `HUF_setMaxHeight` (`lib/compress/huf_compress.c:HUF_buildTree`/`HUF_setMaxHeight`/`HUF_buildCTableFromTree`), sorting with a 192-bucket count sort + per-bucket quicksort where zstdx sorts leaves once inside package-merge.
- Huffman encoder bit accumulation: zstdx inserts codes at the bottom of the accumulator and consumes input in reverse via `rchunks(4)`, writing output forward (`crates/zstdx/src/bit_io/bit_writer.rs:BitWriter::write_packed_codes_rev`); official keeps code values in the top bits of a size_t container with per-tableLog unroll factors and two-container double-buffering (`HUF_zeroIndex1`/`HUF_mergeIndex1`) breaking the dependency chain; zstdx instead batches 4 symbols per container fill (`lib/compress/huf_compress.c:HUF_addBits`/`HUF_compress1X_usingCTable_internal_body_loop`).
- Huffman encoder table format: zstdx stores `packed: [u16; 256]` as `(code << 4) | num_bits` plus a `(u32,u8)` tuple vector (`crates/zstdx/src/huff0/huff0_encoder.rs:HuffmanTable`); official stores one `HUF_CElt` size_t per symbol, value pre-shifted to the container top, enabling branch-free `HUF_addBits` (`lib/compress/huf_compress.c:HUF_setValue`/`HUF_getValueFast`).
- Treeless/repeat decision: zstdx reuses the previous table when `Σ|nbBits_new − nbBits_old| ≤ 5` over the alphabet (`crates/zstdx/src/huff0/huff0_encoder.rs:HuffmanTable::can_encode`); official maintains a `HUF_repeat` state machine with `HUF_validateCTable` and size comparisons, plus `HUF_flags_preferRepeat` for fast strategies on ≤1024-byte literals (`lib/compress/huf_compress.c:HUF_compress_internal`, `lib/compress/zstd_compress_literals.c:ZSTD_compressLiterals`).
- Literal incompressibility pre-check: zstdx computes the exact Shannon bound from one shared histogram and rejects when `entropy_bits + header_estimate + total*0.08 >= total*8` (`crates/zstdx/src/encoding/blocks/compressed.rs:compress_literals`/`entropy_bound_bits`); official uses a max-count heuristic `largest <= (srcSize >> 7)+4` and `ZSTD_minGain` (`lib/compress/huf_compress.c:HUF_compress_internal`, `lib/compress/zstd_compress_internal.h:ZSTD_minGain`).
- X1 DTable shape and lifetime: zstdx sizes the table naturally at `1 << max_bits` (any log 1..=11) and keeps a packed u16 mirror `(symbol<<8)|num_bits` for single-load decode (`crates/zstdx/src/huff0/huff0_decoder.rs:HuffmanTable.packed`); official rescales weights up to `HUF_DECODER_FAST_TABLELOG=11` and fills 2-byte `HUF_DEltX1` entries with U64 quad stores (`lib/decompress/huf_decompress.c:HUF_rescaleStats`/`HUF_DEltX1_set4`).
- Fast-loop applicability: zstdx's ported loops run at any tableLog (`index = bits >> (64−tl)`) with per-iteration bound re-checks and a scalar tail sharing reader state (`crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved`/`finish_streams`); official requires `dtLog == 11` and ≥8 bytes per stream else falls back to the generic body (`lib/decompress/huf_decompress.c:HUF_DecompressFastArgs_init`).
- Sequence-code precomputation locus: zstdx computes all three codes + add-bit payloads once at match-emission time into packed `SeqWord`s (`crates/zstdx/src/encoding/seq_codes.rs:pack_seq`); official stores raw (llBase, mlBase, offBase) in `SeqDef` and computes codes per sequence inside the encode loop (`lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body`).

### B. zstdx-only

- Batched literal-code writer: groups of 4 symbols per container fill, flushed below 8 pending bits so four ≤12-bit codes always fit, one unaligned u64 store per flush, overshoot snapped by `set_len` (`crates/zstdx/src/bit_io/bit_writer.rs:write_packed_codes_rev`, bit-identity covered by the `packed_codes_rev_matches_write_bits` test); official encodes strictly one `HUF_addBits` per symbol.
- Flat-alphabet fast path: uniform code-length detection enables a two-symbols-per-byte bulk packer with an AVX-512VBMI kernel — 64 symbols/iteration via a 256-entry LUT (`permutex2var_epi8` pair) + bit-7 `mask_blend` (`crates/zstdx/src/bit_io/bit_writer.rs:write_uniform4_bulk`/`uniform4_pack_avx512`; docs: skewed instructions −48%, throughput +43%); official has no SIMD on the encode side (BMI2 attribute only).
- AVX-512 exact histogram for ≤16-symbol alphabets: 16 slot broadcasts × `cmpeq_epi8_mask`+popcnt, the popcount coverage sum doubling as a 17th-symbol detector with cold scalar fallback (`crates/zstdx/src/encoding/blocks/compressed.rs:histogram_small_alpha_avx512`); official's non-SVE path is purely scalar 4-lane (`lib/compress/hist.c:HIST_count_parallel_wksp`).
- Strided Miller-Madow sampling gate (see Encoder B) also drives the literals path: ~1024 stride samples, entropy estimate + bias correction, rejects only near ≥8 bits/byte (`crates/zstdx/src/encoding/blocks/compressed.rs:sampled_gate_rejects`); official samples only first+last 4096 bytes with a largest-count test (`lib/compress/huf_compress.c:HUF_compress_internal`).
- Fused three-histogram single pass: ll/ml/of counts filled in one traversal of the packed code words (`crates/zstdx/src/encoding/blocks/compressed.rs:choose_tables_fast`; docs `6690a05`); official runs three separate `HIST_countFast_wksp` passes (`lib/compress/zstd_compress.c`).
- Combined bit pushes in the sequence encoder: three state-transition groups concatenated into one ≤36-bit value, then transitions+add-bits merged into a single ≤56-bit push, accumulator held in locals via `writer.hot_state()` (`crates/zstdx/src/encoding/blocks/compressed.rs:encode_sequences`/`hot_push`; docs: json −0.4% instructions); official issues up to six separate `BIT_addBits` calls per sequence (`lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body`).
- Decode-side merged table arena: all three packed FSE tables in one allocation at fixed slot offsets (`LL_SLOT=0`, `ML_SLOT=1<<LL_MAX_LOG`, `OF_SLOT=...`), addressed through a single base pointer, plus a pre-shifted bit window (`win = bits << consumed`, two shifts per read) and whole-loop BMI2 runtime dispatch (`crates/zstdx/src/decoding/sequence_section_decoder.rs:pack_tables`/`decode_sequences_impl_bmi2`); official keeps three independent `ZSTD_seqSymbol*` pointers (`lib/decompress/zstd_decompress_block.c:ZSTD_decodeSequence`).
- X2 pairability gate: the double-symbol table is built only when the pairable share of code space is ≥ ~80% (`eligible_slots * 5 < 4 << 11` keeps X1, `crates/zstdx/src/huff0/huff0_decoder.rs:build_x2_table`; docs: skewed.zst1 +43% by avoiding X2 on unpairable tables); official always builds whatever `HUF_selectDecoder` picked (`lib/decompress/huf_decompress.c:HUF_readDTableX2_wksp`).
- no-std log2: linear-mantissa approximation (error < 0.086) for every entropy/cost estimate (`crates/zstdx/src/fse/fse_encoder.rs:approx_log2`), tolerated by margin-based comparisons; official uses integer fixed-point cost models only (`lib/compress/zstd_compress_sequences.c:kInverseProbabilityLog256`).
- Float Shannon cost model for repeat/FSE selection: bound + estimated 6-bits-per-live-symbol description term (`crates/zstdx/src/encoding/blocks/compressed.rs:repeat_bit_cost`/`description_bits`, `crates/zstdx/src/fse/fse_encoder.rs:FSETable::symbol_bit_cost`); official compares basic/repeat/fresh with accuracy-8 fixed point (`ZSTD_entropyCost`/`ZSTD_fseBitCost`/`ZSTD_crossEntropyCost`) — each model has no counterpart on the other side.
- Compile-time table generation: `const fn`-generated LUTs and metadata arrays surface encoding errors at compile time (`crates/zstdx/src/encoding/seq_codes.rs:ll_meta`/`ml_meta`/`ll_code_lut`/`ml_code_lut`); official uses hand-written static arrays (`lib/common/zstd_internal.h:LL_bits`, `lib/compress/zstd_compress_internal.h:LL_Code`/`ML_Code`).

### C. Gaps vs. official zstd

- Huffman depth probing: `HUF_flags_optimalDepth` estimates `HUF_estimateCompressedSize + hSize` for every candidate tableLog and picks the best (`lib/compress/huf_compress.c:HUF_optimalTableLog`); zstdx runs package-merge once at the format maximum 11 (`crates/zstdx/src/huff0/huff0_encoder.rs:build_from_counts`).
- Single-stream literals for small inputs: official picks `singleStream = srcSize < 256` (`lib/compress/zstd_compress_literals.c:ZSTD_compressLiterals`); zstdx's compressible path only ever emits 4 streams for >1024-byte literals — its 1-stream branch is reachable only for <6-byte literals via size_format 0 (`crates/zstdx/src/encoding/blocks/compressed.rs:compress_literals`).
- Strategy-scaled thresholds: `ZSTD_minLiteralsToCompress` (8..64 bytes by strategy) and `ZSTD_minGain = (srcSize >> minlog) + 2` with minlog 6..7 (`lib/compress/zstd_compress_literals.c`) vs zstdx's fixed 1024-byte floor and flat margins (`crates/zstdx/src/encoding/blocks/compressed.rs:compress_literals`).
- Weight-compression guard: official FSE-compresses the weight list only if `1 < hSize < maxSymbolValue/2` (`lib/compress/huf_compress.c:HUF_writeCTable_wksp`); zstdx switches purely on `weights.len() > 16` and asserts the FSE form stays <128 bytes (`crates/zstdx/src/huff0/huff0_encoder.rs:HuffmanEncoder::write_table`).
- U64 scatter for the FSE spread: both sides could lay symbols 8 bytes at a time and scatter with a 2-unrolled walk when no −1 symbols exist; official does (`lib/compress/fse_compress.c:FSE_buildCTable_wksp`, `lib/common/fse_decompress.c:FSE_buildDTable_internal`), zstdx always uses the classic per-symbol walk (`crates/zstdx/src/fse/fse_encoder.rs:build_table_from_probabilities`, `crates/zstdx/src/fse/fse_decoder.rs:build_decoding_table`).
- ctz-accelerated NCount parsing — see A; zstdx's per-bit reader is tolerable only because table headers are small (`crates/zstdx/src/fse/fse_decoder.rs:read_probabilities` vs `lib/common/entropy_common.c:FSE_readNCount_body`).
- Hand-written x86-64 asm Huffman decode loop: `lib/decompress/huf_decompress_amd64.S` (~766 lines) dispatched under `ZSTD_ENABLE_ASM_X86_64_BMI2`; zstdx has no asm — its Rust loop does 1 table load + 2 shifts vs the asm's 3 dtable loads, with claimed memport/ALU-bound parity (`docs/src/dev/perf/decoding.md` `5be5f88`; perf claim unverified here).
- X2 fast-loop register scheduling: official splits into a 3-way variant on x86 and 4-way on aarch64 (`lib/decompress/huf_decompress.c:HUF_4X2_3WAY`/`HUF_4X2_4WAY`); zstdx always decodes column-major 4 streams × 5 lookups (`crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved_x2`).
- SVE2 histogram: `lib/compress/hist.c:HIST_count_6_sve2` uses `svhistseg_u8` per-16-byte segment histograms on aarch64; zstdx's SIMD histogram is x86-AVX-512 only with scalar fallback elsewhere (`crates/zstdx/src/encoding/blocks/compressed.rs:histogram_literals`).
- Three-way fixed-point table-cost comparison (basic/repeat/compressed) for strategy ≥ lazy (`lib/compress/zstd_compress_sequences.c:ZSTD_selectEncodingType`); zstdx's predefined-vs-dynamic decision is the fast-strategy heuristic only, with no cross-entropy comparison against the predefined table (`crates/zstdx/src/encoding/blocks/compressed.rs:select_from_counts`).
- Encoder-side BMI2 compilation of hot loops (`lib/compress/huf_compress.c:HUF_compress1X_usingCTable_internal_bmi2`, DYNAMIC_BMI2 templates in `lib/compress/fse_compress.c`); zstdx uses BMI2 only on the sequence decode loop (`crates/zstdx/src/decoding/sequence_section_decoder.rs:decode_sequences_impl_bmi2`).
- Superblock re-entropy coding: multiple blocks re-emitted as one superblock with entropy tables shared/rewritten across sub-blocks (`lib/compress/zstd_compress_superblock.c`) — nothing comparable in zstdx; see Architecture C.
- Dictionary-seeded entropy: official can load HUF/FSE tables from compressed dictionaries so repeat/treeless engage from the first block (`ZSTD_loadDEntropy` in `lib/decompress/zstd_decompress.c`; encoder side feeds `prevCTable`/`oldHufTable` from the cdict — unverified exact symbols); zstdx's repeat path takes previous tables only from prior blocks (`crates/zstdx/src/encoding/blocks/compressed.rs:compress_block`; dict-table seeding unverified).
- longOffsets two-part offset emission for offsets larger than the accumulator budget (`lib/compress/zstd_compress_sequences.c:ZSTD_encodeSequences_body` longOffsets branch); zstdx relies on its 56-bit-capped combined push — equivalent wire for all supported windows, explicit long-offset mode absent (practical impact unverified).

## Decoder

### A. Own approach to a shared problem

- Ring-buffer execution path (ruzstd heritage): hand-written ring with modulo-free `wrap_add` and four layout cases, now confined to dictionary frames; `repeat_in_chunks` doubling matches libzstd's semantics but not its code (`crates/zstdx/src/decoding/ringbuffer.rs:RingBuffer`, `crates/zstdx/src/decoding/decode_buffer.rs:repeat_pre_reserved`/`repeat_in_chunks`, `crates/zstdx/src/decoding/frame_decoder.rs:decode_blocks` vs `lib/decompress/zstd_decompress_block.c:ZSTD_execSequence`/`ZSTD_safecopy` — libzstd never uses a ring, always linear `dst` + 3-pointer extDict).
- Window continuity as two-generation virtual address space: `crates/zstdx/src/decoding/flat_buffer.rs:FlatOut`/`FlatView` (`origin/prev_origin/seg_a_end`) makes virtual distances equal physical ones inside the active segment (`dst - offset` is the whole match algebra in `exec_one_flat`), straddling sources pushed to a `#[cold] copy_wrapped_match`; libzstd remaps per sequence at runtime via `ZSTD_checkContinuity` and splits matches across extDict/prefix (`lib/decompress/zstd_decompress_block.c:ZSTD_checkContinuity`).
- Monomorphized wrap/headroom instantiations: `crates/zstdx/src/decoding/sequence_execution.rs:execute_decoded_flat_inner::<NOWRAP, HEADROOM>` compiles the never-wrapped and guaranteed-slack cases to loops without mapping branches or per-sequence wildcopy gates; libzstd has one runtime-checked `ZSTD_execSequence`.
- Pre-shifted bit window: `win = bits << consumed` costs two shifts per read and `bits` is never carried across sequences (`crates/zstdx/src/decoding/sequence_section_decoder.rs:read`/`reload`); official carries `ptr`, `bitContainer`, `bitsConsumed` (`lib/common/bitstream.h:BIT_lookBitsFast`).
- Batched field extraction: all three add-bit fields read in ONE window read (`sum ≤ 31` ⇒ no mid-sequence reload; larger sums take the cold fallback) and all three state transitions in one 26-bit read, split by shifts+bzhi (`crates/zstdx/src/decoding/sequence_section_decoder.rs:decode_step`); official reads of/ml/ll bits with separate `BIT_readBitsFast` calls and conditional reload guards (`lib/decompress/zstd_decompress_block.c:ZSTD_decodeSequence`).
- Branch-free repcode resolution: slot index `code-1+ll0`, masked garbage slot load, rotation as selects (`crates/zstdx/src/decoding/sequence_execution.rs:do_offset_history`) vs C's branch tree (`ofBits > 1` / `LIKELY(ofBits == 0)` / `temp -= !temp`); the aarch64 variant of `ZSTD_decodeSequence` is closer but still branches on `ofBits`.
- Fused-loop state promotion: `SeqDecoder` destructured into loop locals in `execute_decoded_flat_inner` (SROA; fields written back only on success) vs `seqState_t` passed by pointer into `ZSTD_decodeSequence` (state stored through memory each call).
- Inline fixed-width copies: unaligned u64/u128 load-store motivated by measured libc PLT overhead of variable-length memmove (`crates/zstdx/src/decoding/sequence_execution.rs:copy8`/`copy16`) vs `lib/common/zstd_internal.h:ZSTD_copy16` (C compilers resolve memcpy inline, no PLT).
- Predefined-table caching: built once, then only repacked when changed (`crates/zstdx/src/decoding/scratch.rs:FSEScratch::{ll,ml,of}_predefined`) vs official's static const `LL_defaultDTable` etc., never built (`lib/decompress/zstd_decompress_block.c`).
- X1 fast loop indexed by the table's real log (`crates/zstdx/src/decoding/literals_section_decoder.rs:decompress_4streams_interleaved`, tl ∈ 1..=11) vs official padding the table to log 11 and refusing the fast loop otherwise (see Entropy A); the X2 gate refinement is shared with Entropy B.
- Multi-frame stream plumbing: peek 4-byte magic, replay prefix, clean-EOF vs first-frame-EOF distinction, reusable `FrameDecoder` reset per frame (`crates/zstdx/src/decoding/frame_source.rs:start_frame`/`PrefixedReader`) vs `ZSTD_decompressStream`'s stage machine handling skippable frames inline (`lib/decompress/zstd_decompress.c`).

### B. zstdx-only

- Parallel decode — libzstd has NO decode-side MT (verified: no thread/pool/parallel/worker references under `lib/decompress/`; `lib/common/pool.c` serves only compress-side zstdmt). Design: header-only prescan cuts the input at restart points (blocks whose literals are not Treeless and no FSE stream is Repeat mode — `crates/zstdx/src/decoding/mt.rs:scan`/`restart_point`); stage A worker pool decodes literals+sequences into staging buffers with tables rebuilt fresh per segment (`mt.rs:decode_segment`, per-worker `SegmentScratch`); stage B executes matches on the calling thread in input order, carrying `offset_hist` across segments (`mt.rs:execute_segment`); staging bounded by a `consumed` atomic, worker panics captured via `catch_unwind` + poison mutex; falls back to sequential for dictionaries/small inputs/no second restart point; segment sizes discovered in stage A ⇒ output placed via a `place(start,end)` callback (`decode_all_mt` checks, `decode_to_vec_mt` grows).
- HEADROOM specialization: when the allocation provably holds block-max + 16 beyond the cursor (`crates/zstdx/src/decoding/flat_buffer.rs:WILDCOPY_SLACK` guaranteed by `ensure_block_space`), literal and match copies wildcopy unconditionally with zero per-sequence bounds work (`crates/zstdx/src/decoding/sequence_execution.rs:exec_one_flat`); libzstd always keeps the `oMatchEnd > oend_w` gate in `ZSTD_execSequence`.
- Bulk retry contract: capacity doubling on `TargetTooSmall` with a 64 KiB min hint (`crates/zstdx/src/bulk.rs:decompress`/`decompress_with`) vs libzstd's one-shot model where the caller must size `dst` (aided by `ZSTD_getFrameHeader`/`ZSTD_decompressBound`) — convenience layer, listed for completeness.
- no_std decoding core: the whole pipeline (ring + flat paths) builds without std, MT and BMI2 dispatch behind `#[cfg(feature = "std")]` (`crates/zstdx/src/decoding/`, `crates/zstdx/src/io_nostd.rs`); unverified how far this is exercised beyond the cfg gates.

### C. Gaps vs. official zstd

- Literals stored inside the destination buffer: in one-shot mode literals land after the current block in `dst`, else split with a tail in `litExtraBuffer`, consumed split-buffer-first so output never catches the literal buffer (`lib/decompress/zstd_decompress_block.c:ZSTD_allocateLiteralsBuffer`/`ZSTD_decompressSequences_bodySplitLitBuffer`); zstdx always decodes literals into a separate scratch `Vec` (`crates/zstdx/src/decoding/block_decoder.rs:parse_sections` → `literals_buffer`).
- Long-offset / prefetch sequence decoder: `ZSTD_decompressSequencesLong_body` (selected by long-offset share and `ddictIsCold`) prefetches future match data, plus 32-bit long-offset bit splitting (`lib/decompress/zstd_decompress_block.c`, `LONG_OFFSETS_MAX_EXTRA_BITS_32`); zstdx has a single fused loop, no prefetch variant, and assumes a 64-bit `usize` (the `sum ≤ 31` batching and u64 window are 64-bit-only).
- Hand-written Huffman asm — see Entropy C; decoder-side SIMD reach in zstdx is 16-byte u128 copies (SSE movdq codegen) + BMI2 runtime dispatch (`crates/zstdx/src/decoding/sequence_section_decoder.rs:decode_sequences`, same pattern as C's `DYNAMIC_BMI2`); no AVX-512 anywhere in the zstdx decoder (verified by grep).
- DSB loop alignment: `ZSTD_decompressSequences_body(SplitLitBuffer)` embeds `.p2align` directives tuning the decode loop's DSB/MITE behavior; zstdx has no alignment directives (unverified whether LLVM placement suffices).
- In-place / caller-managed-window decode: `ZSTD_decompressFrame` clamps `oBlockEnd` when `ip ≥ op` (in-place), `ZSTD_checkContinuity` lets each call present a fresh disjoint output buffer serving as extDict, and `ZSTD_d_stableOutputBuffer` keeps one output buffer across streaming calls (`lib/decompress/zstd_decompress.c`); zstdx assumes source/target are distinct buffers (no in-place clamp anywhere; overlap support unverified).
- Checksum opt-out knob: verification itself now matches C's default on every decode path (compared digest vs stored word, `FrameDecoderError::ChecksumMismatch` — ST folds the compare into the trailer read in `crates/zstdx/src/decoding/frame_decoder.rs:verify_frame_checksum`, MT post-passes over the assembled output in `crates/zstdx/src/decoding/frame_checksum.rs`); what C still has exclusively is `ZSTD_d_validateChecksum` to disable it.
- Zero-copy DDict: `ZSTD_copyDDictParameters` points prefix/virtual/dict pointers straight at the dictionary bytes and table pointers at prebuilt tables inside the `ZSTD_DDict`, plus a multiple-DDict hash set (`lib/decompress/zstd_ddict.c`, `lib/decompress/zstd_decompress.c:ZSTD_DDictHashSet`); zstdx copies entropy tables and content into the scratch per frame (`crates/zstdx/src/decoding/scratch.rs:DecoderScratch::init_from_dict`), keys dictionaries in a `BTreeMap<u32, Dictionary>` (`crates/zstdx/src/decoding/frame_decoder.rs:dicts`), and dictionary frames forfeit the flat fast path.
- aarch64-specific tuning: single-load `ZSTD_seqSymbol` via memcpy + local prevOffset registers in `ZSTD_decodeSequence`, `PREFETCH_L1(match)` in `ZSTD_execSequence`; zstdx has no arch-specific sequence-path tuning beyond BMI2 (unverified whether LLVM emits the equivalent single-load).
- Small structural differences: libzstd's streaming decoder copies input into an internal `inBuff` for header atomicity while zstdx reads straight from the `Read` impl and rewinds parsed-but-unconsumed block headers (`crates/zstdx/src/decoding/frame_decoder.rs:decode_from_to` `before_header` restore); libzstd clamps `blockSizeMax` to the frame window, zstdx checks only `MAX_BLOCK_SIZE` (`crates/zstdx/src/decoding/block_decoder.rs:block_content_size`).

## Architecture and systems

### A. Own approach to a shared problem

- Job scheduler: fresh scoped threads per call/burst with an atomic-counter work queue over a fixed slot array plus condvar-ordered assembly on the calling thread (`crates/zstdx/src/encoding/mt.rs:compress_slice_mt` — `std::thread::scope`, `next_job: AtomicUsize`, `slots: Vec<Mutex<Option<Vec<u8>>>>`, `ready: Condvar`; `crates/zstdx/src/stream/encoder_mt.rs:encode_jobs`) vs libzstd's long-lived worker pool created once per mtctx with a circular job queue and blocking pops (`lib/common/pool.c:POOL_create`/`POOL_thread`, `lib/compress/zstdmt_compress.c:ZSTDMT_createJobsTable`, `nbJobs = nbWorkers+2`).
- Cold vs warm pool generations: a warm thread-local bulk pool (`crates/zstdx/src/encoding/frame_compressor.rs:SLICE_STATE`) survives across calls on the same thread, while streaming bursts spawn fresh threads every burst (thread-local pool always misses) so an encoder-owned `Mutex<Vec<Box<CompressState>>>` pool carries states across bursts (`crates/zstdx/src/stream/encoder_mt.rs:pool`/`take_pooled_state`); libzstd has one always-warm arrangement (persistent factory + cctxPool).
- Streaming-MT driving policy: zstdx buffers into one contiguous `[history strip][pending]` buffer and fires a burst only once `max(workers,2)` job-sized slices accumulated, encoding the whole burst in parallel (`crates/zstdx/src/stream/encoder_mt.rs:burst_jobs`/`write`); libzstd creates a job as soon as `inBuff.filled >= targetSectionSize` and flushes completed-job output incrementally with per-job progress (`job->dstFlushed`, condvar signaled mid-job every 4 blocks — `lib/compress/zstdmt_compress.c:ZSTDMT_compressStream_generic`).
- Job sizing: zstdx divides the known input evenly targeting 2× workers (`len.div_ceil(workers*2)`, floor `max(1 MiB, overlap)`, cap 1 GiB — `crates/zstdx/src/encoding/mt.rs:job_size_for`); libzstd uses a fixed streaming section size `1 << max(20, windowLog+2)` clamped to [512 KB, 1 GB], independent of input length, with a user-facing `ZSTD_c_jobSize` knob zstdx lacks (`lib/compress/zstdmt_compress.c:ZSTDMT_computeTargetJobLog`).
- Overlap policy: zstdx uses the level's whole window as the overlap strip, justified by fully indexing it (periodic corpora with ~800K period collapsed MT ratio until the strip was indexed — `crates/zstdx/src/encoding/mt.rs:compress_slice_mt`, `crates/zstdx/src/stream/encoder_mt.rs:overlap`); libzstd defaults to a fraction via overlapLog (window/8 for fast..lazy, up to full window only for btultra2), overridable via `ZSTD_c_overlapLog` (`lib/compress/zstdmt_compress.c:ZSTDMT_computeOverlapSize`).
- Strip indexing style: fast/dfast prefilled on a stride-3 sparse grid (the stride constant is libzstd's `fastHashFillStep`, `lib/compress/zstd_fast.c`) and chain fills run under the offset-gain store gate — an explicit deviation from libzstd's dense `ZSTD_loadDictionaryContent` fill, justified because zstdx strips are the full window (`crates/zstdx/src/encoding/match_generator.rs:prefill_window`/`PREFILL_STRIDE` vs `lib/compress/zstd_compress.c:ZSTD_fillHashTable`/`ZSTD_updateTree`).
- Determinism-by-construction for pooled state: per-job head tables are cleared (u32 entries, epoch bump for opt tables) precisely because pooled states carry residue that would make output depend on worker scheduling (`crates/zstdx/src/encoding/match_generator.rs:prefill_window`/`clear_table`); whether libzstd performs equivalent targeted clears per job is unverified (its `ZSTD_compressBegin_*` re-inits match state).
- Checksum topology: zstdx selects among inline / offloaded / off backends behind one `BlockChecksum` trait with a 256 KiB threshold for the sidecar thread (`crates/zstdx/src/encoding/frame_compressor.rs:SliceChecksum::new`, `ASYNC_MIN_INPUT`); in MT the whole input is hashed on the calling thread while workers compress (bulk) or interleaved during burst assembly (streaming) (`crates/zstdx/src/encoding/mt.rs:compress_slice_mt`, `crates/zstdx/src/stream/encoder_mt.rs:encode_jobs`) vs libzstd serializing absorption in job order through the SerialState (`lib/compress/zstdmt_compress.c:ZSTDMT_serialState_genSequences`) and zeroing the checksum flag for `jobID != 0`; the fused absorb into raw-block copies and RLE scans is covered under Encoder B.
- Streaming-encode state machine: input staged into a fixed buffer, whole blocks encoded as they fill, encoded bytes handed out from one output Vec (`crates/zstdx/src/stream/encoder_core.rs:FrameEncoderCoreSt::write`/`finish`/`split_output`) vs libzstd's stage machine with input buffering, block loop and stable-in/out bookkeeping (`lib/compress/zstd_compress.c:ZSTD_compressStream2`, `cctx->streamStage`).
- Streaming-decode framing on the write side: zstdx pre-parses the 3-byte block header to compute exactly how many staged bytes the next block plus trailer needs, because the inner `FrameDecoder` poisons itself on starved reads (`crates/zstdx/src/stream/write.rs:Decoder::next_block_need`/`pump`) vs libzstd copying into an internal `inBuff` decoded across explicit stages (`lib/decompress/zstd_decompress_internal.h:ZSTD_dStreamStage`).
- Parameter/level architecture: a closed enum of seven implemented strategies with a const fn mapping from numeric zstd levels (`crates/zstdx/src/level.rs:Level::approximate_zstd`) vs 22 numeric levels × 4 input-size classes of full cParam tuples with runtime shrinking of window/chain/hash logs to the source size (`lib/compress/clevels.h:ZSTD_defaultCParameters`, `lib/compress/zstd_compress.c:ZSTD_adjustCParams_internal`); zstdx does not reshape window/table logs from pledged size at all (`crates/zstdx/src/encoding/match_generator.rs:window_for_level`).
- MT engagement demotion: zstdx silently falls back to the single-thread path for small inputs (<2 MiB), `workers < 2`, `Level::Uncompressed`, or single-core, byte-identical to the ST entry point (`crates/zstdx/src/encoding/mt.rs:compress_slice_mt`, test `small_inputs_fall_back_identically`); libzstd honors `nbWorkers` as configured (only the CLI decides `-T1` vs `--single-thread`).
- Error model: Rust `Result` + `#[non_exhaustive]` thiserror enums, an umbrella `Error` (Frame/Dictionary/Io/Unsupported/Parameter) convertible into io::Error for std and no_std, with "API ahead of implementation" encoded as a `Feature` enum value (`crates/zstdx/src/error.rs:Error`/`Feature`/`into_io`) vs C `size_t` error codes with `ZSTD_isError`/`ZSTD_getErrorName` and `RETURN_ERROR_IF` macros (`lib/zstd.h:ZSTD_getErrorCode`).
- no_std support: a minimal io module (Read/Write traits, `ErrorKind`) lets the whole library build without std, MT gated off entirely (`crates/zstdx/src/io_nostd.rs`, `crates/zstdx/src/stream/encoder_core.rs:FrameEncoderCore::new` returns `Error::Unsupported`) vs libzstd having no io layer at all (caller-supplied buffers, `lib/common/zstd_deps.h` for allocation only).

### B. zstdx-only

- Parallel decompression by restart-point segmentation — the decode-side design is described under Decoder B; from the systems side it is engaged via `crates/zstdx/src/bulk.rs:decompress_to_buffer_with` (`DecoderOptions::threads`) and relies on exactly the block shape MT/job encoders emit at job boundaries.
- Offloaded frame-checksum thread: a dedicated "zstdx-xxh64" worker consuming an SPSC ring of posted byte ranges (512 slots), spin-then-park handoff with a 32768-iteration budget so no post is missed, multiple concurrent frames multiplexed by state ids over one ring, Drop drains pending posts before the input can die (`crates/zstdx/src/encoding/async_checksum.rs:AsyncChecksum`/`Producer::post`/`run`); nothing similar exists in `lib/` (checksum always inline, see A).
- Burst-deterministic streaming job grid: streaming MT jobs are cut on boundaries derived from absolute stream offsets alone (pledged: fixed `job k = job_start + k*job_size`; unpledged: a growing schedule sizing the job at offset `o` for a `4o`-byte input), so without explicit flushes the frame bytes are independent of how writes were chunked; flush is the documented exception that re-grids (`crates/zstdx/src/stream/encoder_mt.rs:JobGrid`/`job_end`/`flush_block`/`trim_buf`); libzstd's streaming MT output inherently depends on how `ZSTD_compressStream2` calls arrive (`lib/compress/zstdmt_compress.c:ZSTDMT_compressStream_generic`).
- Pledged-stream/bulk byte identity: the streaming MT core shares `job_size_for` with the bulk path and holds back the last job until `finish()`, so a stream written exactly to its pledge is byte-identical to bulk MT output (hold-back lapses on pledge overshoot via the `pos <= n` guard) (`crates/zstdx/src/stream/encoder_mt.rs:pending_jobs`; `docs/src/dev/perf/mt-stream.md`); no equivalent guarantee exists in `lib/` (no shared-sizing mechanism between `ZSTDMT_initCStream_internal` and one-shot compression; unverified as a stated goal there).
- Periodic-repeat seed at job start — mechanics under Encoder B; systems relevance: fixes periodic corpora whose period exceeds what table-only matching reaches, where libzstd relies on dense dict/table fill (no counterpart in `lib/compress/`).
- AVX-512 micro-kernels with runtime dispatch inside the codec — matcher seed scan and NT table clears under Encoder B, histogram and bit-writer kernels under Entropy B; libzstd's own kernels use SSE/AVX2-era intrinsics with compile-time gating (the only AVX-512 in `lib/` is the vendored `lib/common/xxhash.h` accumulate variant, compile-time `__AVX512F__`).
- Borrowed-window zero-copy slice path — mechanics under Encoder A; driven by `crates/zstdx/src/encoding/frame_compressor.rs:compress_slice_to_vec`, eliminating the window copy, compaction and staging buffer of the classic design (`lib/compress/zstd_compress.c:ZSTD_window_update` into roundBuff).
- Output-shape regression contracts as infrastructure: byte-identity between slice and streaming paths, MT vs ST ratio-loss bounds, cross-run determinism, dump-based cross-build snapshots, and a corruption smoke tool (flipped bytes must error, never panic) (`crates/zstdx/src/encoding/mt.rs:tests` `mt_output_is_deterministic`/`mt_ratio_stays_close_to_single_thread`, `crates/zstdx/src/encoding/frame_compressor.rs:level_ladder_roundtrips`, `crates/zstdx-bench/src/cmd/dump.rs`, `crates/zstdx-bench/src/cmd/corrupt.rs`); libzstd tests via zstreamtest/fuzzers and does not pin encoder byte-determinism as a contract (its MT output is job-schedule dependent).
- Compat shim mirroring the Rust `zstd` crate (libzstd bindings) API on top of the native engine: numeric levels, `io::Result`, `zstd::bulk`/`zstd::stream` module shapes, `set_pledged_src_size`/`include_checksum`/`multithread` mutators applied until stream start (`crates/zstdx/src/compat/mod.rs`/`bulk.rs`/`stream.rs:EncoderState`); the C library is itself the native API so no analogous layer exists.
- Executor-agnostic streaming core: single-threaded and burst-MT frame encoders behind one enum with identical interfaces, so read/write wrappers never know which runs (`crates/zstdx/src/stream/encoder_core.rs:FrameEncoderCore` — `Single | Mt`); libzstd switches between `ZSTD_compressStream_generic` and `ZSTDMT_compressStream_generic` inside one function with different buffering layers.

### C. Gaps vs. official zstd

- Superblocks / target compressed block size: re-encoding a group of blocks as sub-blocks sharing one entropy frame, exposed as `ZSTD_c_targetCBlockSize` and CLI `--target-compressed-block-size=` (`lib/compress/zstd_compress_superblock.c:ZSTD_compressSuperBlock`, `lib/zstd.h`, `programs/zstdcli.c:usage_advanced`); no superblock/sub-block machinery anywhere in `crates/zstdx/src/encoding/` (also noted under Entropy C).
- Long-distance matching with a serial-state window shared across jobs (`lib/compress/zstdmt_compress.c:ZSTDMT_serialState_reset`/`ZSTD_ldm_generateSequences`, `ZSTD_c_enableLongDistanceMatching`, CLI `--long`); zstdx window is hard-capped by level with no LDM pass — see Encoder C.
- Rsyncable job boundaries: rolling-hash synchronization points so compressed output stays stable under insertions (`lib/compress/zstdmt_compress.c:RSyncState_t`/`findSynchronizationPoint`, CLI `--rsyncable`); zstdx job boundaries are purely size-derived (`crates/zstdx/src/encoding/mt.rs:job_size_for`).
- Mid-stream parameter adaptation: changing cParams while compressing (applied to the next job), adaptive level driven by I/O rate, stable in/out buffer modes avoiding copies, `--patch-from` reference prefix compression (`lib/compress/zstdmt_compress.c:ZSTDMT_updateCParams_whileCompressing`, `lib/compress/zstd_compress.c:ZSTD_compressStream2`, CLI `--adapt`/`--patch-from`); zstdx options are fixed at construction — mutation after start is `ParameterError::AlreadyStreaming` (`crates/zstdx/src/options.rs:EncoderOptions`, `crates/zstdx/src/error.rs:ParameterError`, `crates/zstdx/src/compat/stream.rs:EncoderState::set_started`).
- Pledged-size-driven parameter downshift: source size shrinks windowLog/chainLog/hashLog and can select a cheaper strategy row, and `ZSTD_CParamMode_e` differentiates dict-attach vs standalone (`lib/compress/zstd_compress.c:ZSTD_adjustCParams_internal`/`ZSTD_CCtx_init_compressStream2`, CLI `--stream-size`/`--size-hint`); zstdx pledges the size into the header but never derives parameters from it (static-profile side of this is also under Encoder C).
- Encode-side dictionaries: CDict objects, attach/load-prefix modes, dictID writing, per-job dict reload in MT, `dedicatedDictSearch` (`lib/compress/zstd_compress.c:ZSTD_CCtx_refCDict`/`ZSTD_CCtx_refPrefix`/`ZSTD_CCtx_loadDictionary`, `ZSTDMT_initCStream_internal`); zstdx returns `Error::Unsupported(Feature::DictionaryEncoding)` for every encoding-with-dictionary entry point (`crates/zstdx/src/compat/bulk.rs:Compressor::with_dictionary`, `crates/zstdx/src/compat/stream.rs:write::Encoder::with_dictionary`) — matcher-side dict modes under Encoder C.
- Entropy-dictionary training: cover/fastcover/legacy trainers optimizing entropy tables + segment selection with `ZDICT_finalizeDictionary` (`lib/dictBuilder/zdict.c`/`cover.c`/`fastcover.c`, CLI `--train*`); zstdx has only the raw-content dict builder — estimator comparison under Encoder A.
- Block/frame splitter controls (`ZSTD_c_blockSplitterLevel`/`ZSTD_c_splitAfterSequences`, experimental params 20/21 in `lib/zstd.h`); zstdx block = fixed 128 KiB — splitter machinery under Encoder C.
- Incremental job output progress: compressed bytes flushed before a job finishes (`dstFlushed` advanced mid-job, `ZSTDMT_toFlushNow`, `ZSTDMT_getFrameProgression` — `lib/compress/zstdmt_compress.c`); zstdx emits output only per completed job (`crates/zstdx/src/encoding/mt.rs:slots`), trading latency granularity for simplicity.
- Persistent shared thread pool: created once, shared across CCtxs, resizable at runtime (`lib/common/pool.c:POOL_resize`, `lib/zstd.h:ZSTD_createThreadPool`); zstdx spawns per call/burst and keeps no threads — an acknowledged cost (`docs/src/dev/perf/mt-stream.md`: 8 threads per burst ≈ 0.5-2 ms; persistent pool is an out-of-scope redesign).
- CLI surface: multi-file/recursive operation, stdin/stdout, `-D` dictionaries, format conversion (gzip/xz/lz4), `-l` listing, `--test`, memory limits, sparse/pass-through, async IO, `-b/-e/-i` benchmarks, full `--zstd=` pass-through (`programs/zstdcli.c:usage`/`usage_advanced`); zstdx CLI has exactly two subcommands (compress/decompress one file) with clap + tracing/indicatif progress and an explicit TODO for dictionary creation and benchmarking (`crates/zstdx-cli/src/main.rs:Commands`, `crates/zstdx-cli/src/progress.rs:ProgressMonitor`).
- Test/bench infrastructure: decoder corpus generation, stream/CLI/fuzz suites incl. dictionary_round_trip and an external_matchfinder plug-in harness, a regression framework, benchfn-based benchzstd with datagen (`tests/decodecorpus.c`, `tests/zstreamtest.c`, `tests/fuzz/`, `tests/regression/`, `programs/benchzstd.c`); zstdx relies on in-crate Rust tests cross-checking against libzstd itself (dev-dependency interop assertions, fuzz-artifact replay in `crates/zstdx/src/encoding/frame_compressor.rs:fuzz_targets`), seven cargo-fuzz targets (`crates/zstdx-fuzz/fuzz_targets/{encode,encode_stream,interop,...}.rs`), and a bench crate with nine correctness-gated subcommands incl. an interleaved A/B matrix vs the zstd crate (`crates/zstdx-bench/src/main.rs:Command`).
- Partial-output streaming control: caller-owned in/out buffers with per-call pos/size advancement and three end directives allow flush throttling and zero-copy stable buffers (`lib/compress/zstd_compress.c:ZSTD_compressStream2` — `ZSTD_inBuffer`/`ZSTD_outBuffer`/`ZSTD_EndDirective`, decode `ZSTD_d_stableOutBuffer`); zstdx's io-trait wrappers own the buffering (`crates/zstdx/src/stream/write.rs:Encoder::drain`) and expose only write/flush/finish boundaries.
- Recommended-input-size and buffer-expectation protocol: `ZSTD_CStream_InSize`/`OutSize` plus runtime `ZSTD_setBufferExpectations` checks per stage; zstdx exposes only static constants (`crates/zstdx/src/stream/write.rs:Encoder::recommended_input_size` = one block) with no expectation enforcement.

## Summary

| Dimension | zstdx | official zstd | Winner / lever |
|---|---|---|---|
| MT encode | Scoped-thread bursts, whole-window overlap, seed offsets, byte-deterministic | Persistent pool, overlapLog fraction, incremental job flush, rsyncable | zstdx for throughput + determinism; zstd for latency + knobs |
| MT decode | Restart-point parallel decode, two-stage pipeline | None (single-threaded only) | zstdx |
| SIMD / asm | AVX-512 encoder kernels (histogram, VBMI bit pack, seed scan, NT clears), no decoder SIMD/asm | SSE/NEON/RVV row masks, SVE2 histogram, hand-written x86-64 Huffman asm | zstdx encoder-side; zstd decoder-side |
| LDM | Absent (1 MiB window ceiling) | Gear-hash LDM, auto at windowLog≥27 | zstd (large-input high-tier ratio) |
| Block splitting | Absent (fixed 128 KiB) | Fingerprint splitter + sequence-aware re-splitter | zstd (high-tier ratio) |
| Dictionaries | Raw-content dicts only; encode-time loading = `Unsupported` | CDict/refPrefix/dictMatchState/dedicatedDictSearch, MT dict reload, entropy-seeded decode tables | zstd |
| Superblocks | Absent | Shared-entropy superblocks, `ZSTD_c_targetCBlockSize` | zstd |
| Matchfinder portfolio | fast/dfast/chain/opt (DUBT replaced by cheap opt) | fast/dfast/row-hash/btlazy2/btopt/btultra + LDM | zstd (breadth); zstdx (per-tier tuning depth) |
| Hash/index representation | 32-bit packed positions, epoch-tagged opt tables, zero-copy borrowed window | Full U32 window indices, per-job re-init, copied window | zstdx (working set + copy elimination) |
| Entropy cost model | Float Shannon bounds + margins, fast-strategy thresholds only | Exact fixed-point cross-entropy comparison at high strategies | zstd (ratio at high tiers) |
| Sequence pipeline | Packed SeqWord, fused histograms, single ≤56-bit pushes | SeqStore triples, separate passes, up to six pushes/seq | zstdx (encode speed) |
| Decode loop | Pre-shifted window, batched field reads, branch-free reps, HEADROOM, natural-size tables | Split literal buffers, prefetch variant, asm loop, log-11 padded tables, DSB alignment | zstd (tuned asm); zstdx (specialized Rust, within ~10%) |
| Checksum | Fused into block scan, offloadable sidecar thread, deterministic MT absorption | Inline separate pass, SerialState-ordered in MT, verified on decode | zstdx encode topology; zstd decode completeness |
| Determinism contract | Byte-deterministic ST+MT output, regression-tested | Not pinned (MT output schedule-dependent) | zstdx |
| Parameter adaptation | Fixed per-tier params, 7-level enum | 22 levels × 4 srcSize profiles, runtime shrinking, mid-stream updates | zstd |
| no_std | Full library builds without std | Freestanding C, no io layer | zstdx (Rust no_std) |
| CLI / tooling | 2 subcommands, bench crate with correctness gates, 7 fuzz targets, interop tests vs libzstd | Full-featured CLI, corpus/fuzz/regression suites, benchzstd + datagen | zstd |

- zstdx's structural wins are throughput-shaped: MT decode (absent upstream), fused/packed encode pipelines, borrowed windows, pooled-state determinism, and encoder-side AVX-512 — all leveraged without changing the wire format.
- Its ratio risks concentrate where adaptivity lives upstream: no LDM, no block splitting, no row-hash matchfinder, no per-srcSize parameter profiles, and approximate (float, fast-strategy-only) entropy cost decisions cap high-tier compression vs zstd 16-22.
- The decode gap is narrow but real: zstdx's Rust fast loops sit within ~10% of libzstd's hand-written asm per `docs/src/dev/perf/decoding.md`, while literals-in-dst, prefetch variants, DDict zero-copy and DSB alignment remain unported.
- Feature-completeness gaps are mostly API-level, not format-level: encode-side dictionaries, entropy-table seeding from dicts, mid-stream parameter changes, rsyncable boundaries, superblocks, and the long CLI tail are all additive work on an already format-complete codec.
- Two correctness/completeness debts stand out from the code comparison: zstdx never verifies decoded checksums (left to the caller), and dictionary training exists but only as a raw-content builder outside the frame format.
