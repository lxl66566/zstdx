# C FFI (`crates/zstdx-ffi`)

A C-ABI layer over the zstdx codec targeting drop-in libzstd compatibility. The crate's lib target is named `zstd`, so `cargo build -p zstdx-ffi --release` produces `target/release/libzstd.so` (cdylib) and `libzstd.a` (staticlib) directly. The `.so` carries no SONAME; to satisfy binaries linked against a versioned soname, copy it (`cp libzstd.so libzstd.so.1`). All entry points are `#[no_mangle] extern "C"`; contexts own the Rust-side state (the streaming encoder over its delivered-cursor sink, a `FrameDecoder` with staged input; the one-shot entries call the bulk slice core) and the codec core is untouched — everything adapts at the boundary.

The claimed version surface is that of the reference tree this repo tracks (1.6.0 / 10600): `ZSTD_versionNumber/String/Major/Minor/Release`, `ZSTD_MAX_CLEVEL=22`, `ZSTD_minCLevel=-131072`, `ZSTD_defaultCLevel=3`, `ZSTD_compressBound` verbatim (`bound(0)=64`, `bound(128K)=131584`, `MAX_INPUT_SIZE` overflow → 0), stream size helpers (`CStreamIn=128K`, `CStreamOut=131591`, `DStreamIn=131075`, `DStreamOut=128K`) — all verified against the reference `libzstd.a` on this host.

## Symbol coverage

Implemented (62 exports):

- Version/metadata: `ZSTD_versionNumber/versionString/versionMajor/versionMinor/versionRelease`, `ZSTD_maxCLevel/minCLevel/defaultCLevel`, `ZSTD_compressBound`, `ZSTD_getFrameContentSize`, `ZSTD_getDecompressedSize`, `ZSTD_findDecompressedSize`, `ZSTD_findFrameCompressedSize`, `ZSTD_frameHeaderSize`, `ZSTD_getFrameHeader`, `ZSTD_isFrame`
- One-shot: `ZSTD_compress`, `ZSTD_decompress`
- Errors: `ZSTD_isError`, `ZSTD_getErrorName`, `ZSTD_getErrorCode` (enum mirrors `zstd_errors.h`; names are `ERR_getErrorString`'s strings). Recognition is `ERR_isError`'s strict bound — the value `-(maxCode)` itself is not an error — and `getErrorCode` keeps the raw negated number for gap values (inside the range, outside the enum), exactly `ERR_getErrorCode`
- Contexts: `ZSTD_createCCtx/freeCCtx`, `ZSTD_createDCtx/freeDCtx`, `ZSTD_compressCCtx`, `ZSTD_decompressDCtx`, `ZSTD_compress_usingDict`, `ZSTD_decompress_usingDict`, `ZSTD_CCtx_setParameter`, `ZSTD_DCtx_setParameter`, `ZSTD_CCtx_setPledgedSrcSize`, `ZSTD_CCtx_reset`, `ZSTD_DCtx_reset`, `ZSTD_compress2`, `ZSTD_CCtx_loadDictionary`, `ZSTD_DCtx_loadDictionary`
- Dictionaries: `ZSTD_createCDict/freeCDict`, `ZSTD_getDictID_fromCDict`, `ZSTD_compress_usingCDict`, `ZSTD_createDDict/freeDDict`, `ZSTD_getDictID_fromDDict`, `ZSTD_decompress_usingDDict`, `ZSTD_getDictID_fromDict`, `ZSTD_getDictID_fromFrame`
- Streaming: `ZSTD_createCStream/freeCStream`, `ZSTD_createDStream/freeDStream`, `ZSTD_initCStream/initDStream`, `ZSTD_compressStream2`, `ZSTD_compressStream` (deprecated alias), `ZSTD_flushStream`, `ZSTD_endStream`, `ZSTD_decompressStream`, `ZSTD_CStreamInSize/OutSize`, `ZSTD_DStreamInSize/OutSize`, `ZSTD_inBuffer`/`ZSTD_outBuffer`

Parameters: `ZSTD_c_compressionLevel`, `ZSTD_c_windowLog`, `ZSTD_c_contentSizeFlag`, `ZSTD_c_checksumFlag`, `ZSTD_c_dictIDFlag` (R55: suppresses the frame header's Dictionary_ID while the dictionary stays in effect), `ZSTD_c_enableLongDistanceMatching` (R55: the ParamSwitch tri-state over `EncoderOptions::long_distance_matching`), `ZSTD_c_nbWorkers`, `ZSTD_d_windowLogMax`. Everything else returns `ZSTD_error_parameter_unsupported` (libzstd's own answer for parameters it does not know).

Semantics pinned against the reference tree: `ZSTD_CCtx_setParameter` returns the applied value on success (levels clamp to [-131072, 22] with 0 meaning/returning the default 3, boolean flags clamp to 0/1, windowLog validates 0 or 10..=31 — the 64-bit range; `ZSTD_DCtx_setParameter` returns 0 as it does there). `ZSTD_CCtx_reset`/`ZSTD_DCtx_reset` mirror the directive enum: session resets never fail, parameter resets fail with `stage_wrong` while a frame is open, unknown directive values are no-ops returning 0. `ZSTD_compress2` is sticky settings + the loaded dictionary over a fresh, source-size-pledged frame. `ZSTD_CCtx_setPledgedSrcSize` applies to the next frame only (`ZSTD_CONTENTSIZE_UNKNOWN` means no pledge) and is consumed when that frame completes; a frame opened by an `e_end` call overrides the pledge with that call's input size (libzstd's single-round rule, which is also why `ZSTD_compress2` writes the content size automatically). `ZSTD_getFrameHeader` fills the `ZSTD_FrameHeader` struct for both frame types (short valid prefixes return the wanted size, mismatching magic prefixes return `prefix_unknown`, the reserved descriptor bit returns `frameParameter_unsupported`, an oversized window descriptor returns `frameParameter_windowTooLarge`). Its short-input contract is the reference's exactly (R67, differential-probe pinned): below `ZSTD_FRAMEHEADERSIZE_PREFIX` (5) the visible magic bytes are validated under the skippable-variant mask — any first byte 0x50..=0x5F qualifies, and a complete 4-byte magic of either family still wants 5, never the family own header size — and the struct is left untouched; from 5 bytes on the struct is zeroed first (whole, tail padding included: a Rust struct assignment would skip the padding bytes, so the entry zeroes memory explicitly) and incomplete headers want their descriptor-formula size; a null `src` with a positive size answers `generic` (the reference entry check), size 0 still wants 5; `ZSTD_frameHeaderSize` is the reference's pure descriptor arithmetic — no magic validation, so a skippable frame is measured through its own size field's first byte. `ZSTD_getDictID_fromFrame` returns the skippable magic variant for skippable frames, as the reference's struct field does.

CDict/DDict caching is honest but partial: the handles digest once (`ZSTD_createCDict` fails with NULL for an unloadable dictionary, an empty one stays a valid level-only handle as libzstd documents) and every compression/decompression reuses the parsed tables. Compression through the handle rides the pooled single-threaded dict state, whose seed-image cache (R57/R58, keyed to the payload size's seeding projection since R60) restores the filled match state across same-key calls — the CDict attach economics, size-varying records included; a key change (dictionary, level, LDM mode, or a decision-flipping size band) re-seeds fully. Decode still builds a fresh decoder state per call. `ZSTD_compress_usingCDict` takes the level and dictionary from the handle with libzstd's hardcoded frame parameters (contentSize=yes, checksum=no, dictID=yes); a NULL handle is `dictionary_wrong`. `ZSTD_decompress_usingDDict` uses the handle's dictionary exclusively (a NULL handle decodes plain, ignoring the context dictionary, as libzstd's `decompressBegin_usingDDict(NULL)` clears). `ZSTD_CCtx_loadDictionary` defers the digest error to the next frame (libzstd's lazy CDict build); `ZSTD_DCtx_loadDictionary` parses eagerly and answers `dictionary_corrupted` at the load (libzstd answers `memory_allocation` there — the closer code wins). A loaded dictionary applies to every frame regardless of the header's dictID field (libzstd's rule): both the one-shot paths (through `DecoderOptions`) and, since R56, the streaming decoder register it under the null id as well — a `ZSTD_c_dictIDFlag=0` frame decodes with the dictionary attached (`suppressed_dictid_stream_decodes_with_loaded_dict`).

Not implemented (deliberately): the whole experimental/static-only surface beyond `ZSTD_getFrameHeader`/`frameHeaderSize`/`findDecompressedSize` — `ZSTD_getBlockSize`/`ZSTD_compressBlock`, `ZSTD_compress_advanced` (deprecated), the `zstdmt`, inspect, `refPrefix`, `ZSTD_decompressBound`/`decompressionMargin` and estimate entries. Language bindings, `-l` list mode and benchmark/train CLI modes remain open.

## Semantic deviations from zstd.h

- **Negative levels clamp to 1.** zstdx has no accelerated levels; `ZSTD_minCLevel` still reports -131072 so consumer-side range checks see the reference range.
- **windowLog above 27 is accepted but engine-capped at 27** (`ZSTD_c_windowLog` validates 10..=31, the reference's 64-bit range; the codec's own window ceiling is 2^27). Frames asking 28..=31 are produced with the capped window.
- **nbWorkers: 0/1 single-threaded, ≥2 engages the MT job paths**; a dictionary forces the single-threaded core (engine limit — mirrors libzstd's no-mt-without-ZSTD_MULTITHREAD behavior rather than erroring). The reference `libzstd.a` on this host is built without ZSTD_MULTITHREAD, so it answers `parameter_unsupported` for nbWorkers ≥ 1 where this layer accepts and uses the value.
- **CDict caches the parse and, on the compression side, the re-armed match state per seeding key**: the handle holds the dictionary digested once (parse + encoder entropy tables, shared by every job), and its compressions ride the pooled single-threaded dict state's seed-image cache — a same-key call (dictionary, level, LDM mode, payload size inside one seeding projection class) restores the filled matcher tables, a key change re-seeds (R57/R58/R60; see the deviations note above). The DDict side still builds a fresh decoder state per call. libzstd's CDict additionally shares the match state across threads; the image here rides per-thread pooled states.
- **The one-shot variants run on fresh level-only settings**: `ZSTD_compressCCtx`/`ZSTD_compress_usingDict` ignore the context's sticky parameters and dictionaries, as `zstd.h` documents ("sticky parameters ... do not apply to one-shot variants"); `ZSTD_compress2` and the streaming entries are where stickiness applies. `ZSTD_decompressDCtx`, by contrast, does see the context dictionary (sticky per `zstd.h`).
- **One-shot compression rides the zero-copy bulk slice core with the source size declared** (2026-10-16): `ZSTD_compress` output stays byte-identical to `ZSTD_compressStream2(…, e_end)` over the same bytes — the equivalence is now structural (`bulk::compress_with` threads the pledged size into every slice-path header with the streaming core's exact shape, pinned by `pledged_stream_matches_declared_bulk_st` across both header forms, checksum/window-log variants, the reach-probe donated path and dictionary frames). Measured C-harness A/B/A (json/text/dll32 32 MiB and 4K-1M payloads, l1/3/9 + compress2 w8): every output byte-identical, ST cells wall-neutral — a single whole-source `write_all` through the stream core already runs at the slice core's speed, so the stream tax the pull-shaped bench cells carry (T5's text.fastest stream at half of bulk) is a property of the chunked feed shape, not a cost the one-shot shared; json compress2 w8 l1 +5-8% is the one reproduced win. The single cell the slice core cannot express: `nbWorkers >= 2` with the content-size flag off keeps the streaming core (the MT slice path always declares its size — the decoder's piece-partition policy). `ZSTD_compress2` rides the same entry (sticky settings, pledged single round).
- **Sub-8-byte dictionaries mean "no dictionary" on both sides** (the compress rule, `ZSTD_loadDictionary`'s), while the reference's decode side (`ZSTD_decompressBegin_usingDict`) refs <8 bytes as raw content — only reachable by a frame whose matches land inside an ≤7-byte dictionary, recorded here rather than forked per side (R46).
- **Bad-magic input reports `prefix_unknown` on both paths**, as the reference does for a single frame (its `srcSize_wrong` remap needs a completed frame in front of the garbage). Truncated input anywhere → `srcSize_wrong`; checksum mismatch → `checksum_wrong`; undersized destination → `dstSize_tooSmall`.
- **A failed context is sticky, not undefined**: libzstd documents a failed `ZSTD_decompressStream` context as UB-until-reset; this layer replays the recorded error code until `ZSTD_initCStream`/`ZSTD_initDStream` reset it.
- **`ZSTD_CCtx_setParameter` mid-frame returns `stage_wrong`** (libzstd rejects most parameters once a frame is open; parameters unlock again after the frame closes or a reset).
- **`ZSTD_initCStream`/`ZSTD_initDStream` clear the context dictionary** per their doc contract; `ZSTD_decompress_usingDict` leaves its dictionary loaded on the DCtx until then (libzstd's decompose-segment does not retain it across calls).
- **NULL hygiene is defensive, not UB**: null `src` with positive length → `srcBuffer_wrong`, null `dst` with positive capacity → `dstBuffer_null` (libzstd would read/write them); `free*(NULL)` → 0; empty one-shot input decodes to 0 bytes (libzstd's multi-frame loop treats it as no frames).
- **`ZSTD_isFrame` is the reference's pure magic check** (≥4 bytes, either magic family; no descriptor validation).
- **Streaming frames carry no pledged content size unless one is pledged**: `setPledgedSrcSize` is honored for the next frame; frames opened by chunked `e_continue` calls declare nothing, frames opened by an `e_end` call carry their input size — the same split as libzstd.
- **Streaming decode is single-threaded**, as in libzstd's stable API (decode threads are an engine capability without a stable libzstd knob).

Buffer-advance and flush contracts match zstd.h exactly and are pinned by tests: both `pos` fields advance monotonically, input may be left unconsumed when the output fills, `ZSTD_e_flush`/`ZSTD_e_end` return 0 only when everything is flushed (driven through 1-byte output buffers in both the Rust and C suites), `ZSTD_decompressStream` returns 0 only when a frame is fully decoded and flushed with all input consumed, and a hint of one block otherwise. Streaming output is deterministic across buffer chunkings (the encoder never sees them); multi-frame streams with skippable frames decode transparently.

## Harness

`crates/zstdx-ffi/tests/ffi.rs` drives the exported ABI from Rust (levels 0..22, tiny-buffer streaming, flush-to-zero, multi-frame + skippable decode, error-code mapping, dictionary roundtrip, parameter bounds, the reset family, compress2, pledged sizes, CDict/DDict reuse and equivalence with usingDict, loadDictionary stickiness, getDictID flows over a real trained dictionary when the tree carries one, and the metadata size entries). `tests/run-c.sh` compiles `tests/harness.c` twice — once against the reference `libzstd.a`, once against the built `libzstd.so` — runs the self-tests on **both** (the reference run is a parity gate: harness expectations that drift from libzstd fail there first), then the interop matrix (ref→self and self→ref at levels 1/9/19 on json/text corpus slices, plus the zstd CLI decoding a self-produced frame and vice versa). Both suites were green on landing (2026-10-01, 62 symbols).

LD_PRELOAD drop-in smoke (stretch): the dynamically linked system `zstd` CLI (1.5.7) resolves our preloaded `libzstd.so` cleanly, but refuses to operate — its build-time version guard rejects any library not matching its own version string ("expecting 1.5.7; actual 1.6.0"). The claimed 1.6.0 version is the tracked reference tree's; a consumer without that guard is the drop-in target.
