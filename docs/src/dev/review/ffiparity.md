# R67 review — FFI parity (`crates/zstdx-ffi`)

Scope: the whole exported C ABI against the tracked reference tree (libzstd 1.6.0 at `/root/programs/fork/zstd`, `libzstd.a` built on this host). Method: differential C probes compiled once against the reference and once against the built `libzstd.so`, byte-diffed outputs; every pinned expectation first verified on the reference (`tests/run-c.sh` runs the same harness against `libzstd.a` as a parity gate). Landed commits: 4fdc4872, 68395088, 136a2758 (round 1, prior agents) and b28e8b68 (round 2, this agent).

## Symbol coverage

65 of the 152 `ZSTDLIB_API`/`ZSTDLIB_STATIC_API` symbols the reference header declares (probed: `nm` on both builds, diffed against the `ZSTDLIB_*_API` declarations in `zstd.h`). Coverage per behavior group:

- **Version/metadata** — complete for what consumers call: `versionNumber/String/Major/Minor/Release`, `maxCLevel/minCLevel/defaultCLevel`, `compressBound`, `getFrameContentSize`, `getDecompressedSize`, `findDecompressedSize`, `findFrameCompressedSize`, `frameHeaderSize`, `getFrameHeader`, `isFrame`.
- **One-shot** — `compress`, `decompress`, plus the context/dictionary variants (`compressCCtx`, `decompressDCtx`, `compress_usingDict/decompress_usingDict`, `compress_usingCDict/decompress_usingDDict`, `compress2`).
- **Errors** — `isError`, `getErrorName`, `getErrorCode`. Error-code fidelity is reference-exact: the enum mirrors `zstd_errors.h`, `isError` is `ERR_isError`'s strict bound (`-(maxCode)` itself is not an error), `getErrorCode` keeps raw negated gap codes (68395088).
- **Contexts/parameters** — create/free/reset both sides, `setParameter`/`loadDictionary`/`setPledgedSrcSize` both sides, the `ZSTD_dParameter` bounds.
- **Dictionaries** — CDict/DDict create/free, the four `getDictID_from*` entries, `createCDict`/`createDDict`.
- **Streaming** — create/free/init both sides (deprecated init family included since b28e8b68), `compressStream2`, `compressStream`/`flushStream`/`endStream`, `decompressStream`, the four size helpers.

Deliberately uncovered: `estimate*` (14 entries), `initStatic*` (6), `*_advanced`/`*_byReference` context and dictionary constructors, `refPrefix`/`refCDict`/`refDDict`/`refThreadPool`, the block-level API (`compressBlock`/`decompressBlock`/`insertBlock`/`getcBlockSize`), `decompressContinue`/`decompressBegin` (the legacy push API), `copyCCtx`/`copyDCtx`, `writeSkippableFrame`/`readSkippableFrame`, `decompressStream_simpleArgs`/`compressStream2_simpleArgs`, thread-pool and inspect entries, `ZSTD_getCParams`/`getParams`/`adjustCParams`/`checkCParams`. Each family is its own parity round if a consumer needs it; none is reachable through the stable `zstd` crate bindings.

## Divergences fixed this round (reference-exact now, probe-pinned)

1. **One-shot bad-magic gating** (b28e8b68). The reference's `ZSTD_decompressMultiFrame` enters `ZSTD_decompressFrame` only above the 5-byte prefix, and believes a garbage magic only after the precondition *descriptor-formula header size + block header* (9 bytes bare, 17 with an 8-byte FCS); `ZSTD_frameHeaderSize_internal` does not validate the magic — the magic is judged in `ZSTD_decodeFrameHeader`, after both gates. A real decoded frame in front promotes even a passing tail to `srcSize_wrong` (the `moreThan1Frame` rule); skippable frames `continue` past that flag and never promote. Full matrix (garbage-only / frame+garbage / skippable+garbage, two descriptor shapes, tail lengths 0..19): probe-identical; pinned in `harness.c` (runs on `libzstd.a` first) and `tests/ffi.rs`.
2. **Null and truncated buffers on the decode entries** (b28e8b68). Null `dst` reads as zero capacity (`dstSize_tooSmall` for real output, success for an empty frame — probed on the reference, which never touches `dst` on those paths); null or short `src` below the prefix is the no-deref `srcSize_wrong`; the engine's `MagicNumberReadError` on a walk tail under 5 bytes is the same leftover-input rule.
3. **`ZSTD_initDStream` return** (b28e8b68): `ZSTD_startingInputLength` (5), not `ZSTD_DStreamInSize` — an existing stale pin asserted the wrong value and was corrected.
4. **Deprecated DStream init family** (b28e8b68): `initDStream_usingDict` (reset + load; the load error is the return), `initDStream_usingDDict` (attach the parsed handle dictionary), `resetDStream` (bare session reset, dictionary survives). All return 5, as the reference does.
5. **No-forward-progress guard** (b28e8b68): 16 consecutive no-progress `decompressStream` calls answer `noForwardProgress_destFull` (80) with a full output, else `noForwardProgress_inputEmpty` (82); progress or any session reset restarts the count (a `ZSTD_DStream` *is* its `ZSTD_DCtx`; the reference's `ZSTD_decompressBegin` under session resets clears the counter — the WIP missed this on `initDStream`). The between-frames state is exempt exactly as the reference's `loadHeader` shortcut (its hint return sits before the guard); after the completion 0 went out, further calls ask 9 (`max(FRAMEHEADERSIZE_MIN, hSize) − staged + blockHeaderSize`). `compressStream2` has no guard on either side (probed, not assumed).
6. Earlier round 1 (prior agents): `getFrameHeader` short-input and struct-write contract incl. the 48-byte struct's tail padding (4fdc4872); strict maxCode bound and raw gap codes (68395088); parameter bounds — `d_windowLogMax` is `{0}` ∪ 10..=31 with 32..=41 answering `parameter_outOfBound` (probed identical on both libs; no deviation remains) — mid-frame `stage_wrong` gates, wild-cursor checks, and the mid-frame cParam whitelist (136a2758).

## Recorded deviations (kept deliberately)

- **Corrupt formatted dictionary at load answers `dictionary_corrupted` (30); the reference answers `memory_allocation` (64)** — probed on `ZSTD_DCtx_loadDictionary` and on `ZSTD_CCtx_loadDictionary` + first frame. The reference's code is an allocation artifact of its CDict/DDict build path; the semantically honest code wins.
- **NULL-pointer defense where the reference is UB.** A null `src` with ≥5 claimed bytes on a decode entry answers `srcSize_wrong` (the reference derefs); null buffers on compress entries answer `srcBuffer_wrong`/`dstBuffer_null` (the reference writes). Documented in `ffi.md`.
- **One-shot compress exact-fit capacity.** The reference's `ZSTD_compress` refuses `dstCapacity` in `[used, used+8)` with `dstSize_tooSmall` even though the output fits (probed: used=276, first accepted capacity 284 — an internal workspace-margin artifact); this layer accepts the exact fit. The earlier "noise-cap anomaly" is this, now boundary-pinned — no longer unprobed.
- **Wild-cursor clamp history** (136a2758): `compressStream2`/`decompressStream` now answer `dstSize_tooSmall`/`srcSize_wrong` for `pos > size` in the reference's check order — fixed, listed here because the pre-R67 behavior was a silent clamp.
- **Streaming staging is block-granular; the reference decodes ahead.** With an unwritable (zero-capacity) output this layer consumes no input and the guard fires on call 16, where the reference keeps consuming into internal buffers (hostage byte included — `inpos=272/273`) and fires on 17; mid-frame with partial input the reference can deliver a small first block's output where this layer waits for the block it can decode whole (`feed60: outpos=50` vs 0). Error codes, final output and the completion contract are identical; the divergence is confined to transient progress/hint shapes. Matching the reference here means an internal decode-ahead buffer — a redesign, not a fix.
- **Mid-frame hints are advisory, not byte-exact.** The reference returns its exact `nextSrcSizeHint`; this layer suggests one block (`DSTREAM_OUT_SIZE`). Both are documented hints; no caller contract distinguishes them.
- **`initDStream_usingDDict` lifetime strengthened**: the handle's dictionary is Arc-cloned into the context (the reference keeps a caller-owned pointer — dangling if freed early; ours cannot dangle).
- Pre-existing, documented in `ffi.md`: negative levels clamp to 1; windowLog >27 engine-capped; nbWorkers semantics; one-shot variants on fresh settings; sticky-failed-stream error replay instead of UB; `setParameter` level-mid-frame applies to the next frame (the reference retunes the running one); sub-8-byte dictionaries mean "no dictionary" on both sides.

## Unprobed remainder

- The deliberately uncovered symbol families above (estimate/static/advanced/ref*/block-level/push-API) — no behavior probes exist for them; coverage is a named gap, not a verified one.
- `ZSTD_decompressContinue`'s own no-forward-progress counter (`dctx->noForwardProgress`, distinct use of the same field) — moot while the push API is unimplemented.
- Legacy-format frames (`ZSTD_isLegacy` paths) — the reference tree carries legacy support; this codec does not, and no probe exercised legacy magic on the decode entries.
- The exactness of the between-frames hint when a partial (<5-byte) next-frame prefix is staged: the reference computes `max(6, hSize) − lhSize + 3`; this layer returns the same formula only in the nothing-staged shape (9), falling back to the block suggestion once ≥5 bytes arrive. Probed only in the nothing-staged shape.
