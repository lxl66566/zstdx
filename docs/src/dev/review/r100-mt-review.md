# R100 review: MT decode lanes and the stream encode/decode machinery

Scope: the MT and streaming machinery landed since the R98 record — the frame-granular stage-B lanes (`decoding/mt_frames.rs`, `9bb59e95`), the plan-time gated head ramp (`ceed6a4c`), the mid-epoch staging and frame-lane fuzz coverage (`341efa29`, `efc0c5fd`, `d618e7c5`), plus a fresh-context pass over the machinery R98 itself covered and its follow-up landings: the dispatcher and executor core (`decoding/mt.rs`), the piece executor (`decoding/mt_pieces.rs`), the leased pools (`decoding/mt_pool.rs`, `stream/mt_pool.rs`), the read-side pump and its feeds (`stream/read.rs`, `stream/encoder_core.rs`, `stream/encoder_mt.rs`) and the shared schedule helpers they consume (`encoding/mt.rs`). Each area was read against the encoder-invariants skill, the poison-wall protocol and the stage-A wake-fix round (`3010952c`, `810f4e2b`); every finding below was verified against the code before it was recorded, and the fix carries a regression test that was run red against the pre-fix tree first.

## Findings

### 1. Medium — the frame-lane driver resumed a worker's panic behind the success-path invariants (fixed)

`decode_frames` resumes the pool's poison only after `run` returns, but `run`'s outcome collection treated an aborted lane with no recorded failure as benign: the match arm's comment claimed both a recorded failure and a poison are "picked up below before anything observable", and the collection fell through to the `every lane completed` assert and `verify_frame_content_sizes`. An aborted lane publishes no frame starts and leaves `written` at zero (only the last lane's `Done` sets it), so the success-path invariants run on incomplete data:

- debug and paranoid builds fire `assertion failed: every lane completed` — asserting a false invariant on a path that is legal machinery, not a breach — which masks the worker's payload with an unrelated panic (the pinned red run below observed exactly this);
- release builds reach the pledge verification over the aborted lane's missing frame starts, where the `total - starts[i]` arithmetic runs wrong (`written` still zero, the missing lane's starts never collected); the mismatch error it produces — or `Ok(0)` on an all-None-pledge stream — is never observed because `decode_frames` resumes the payload over whatever `run` returned.

So plain release happened to surface the payload, but only after the collection had already run its invariants over incomplete data; in debug and paranoid — the profiles the poison-protocol tests run in — the payload was masked outright. The abort itself is only reachable through the poison (during `run` the abort flag stays down: `LeaseOut` drops after the collection), so the masked branch is exactly the lane-worker-panic path. The red test pinned it: `pool_lane_panic_surfaces_the_payload` (mt2, three pledged frames, lanes `[0]` and `[1, 2]`, a new pool-lane-only panic injection) observed `Some("assertion ... every lane completed ... left: 1 right: 3")` instead of the injected payload before the fix.

The fix returns the `NotYetInitialized` sentinel when an aborted lane had no recorded failure — the pattern `decode_pieces`' caller loop and `Place::resolve` already use for the same state — keeping the all-Done invariants on the every-lane-completed path. `decode_frames` resumes the payload after the leases leave, so the sentinel is never observed. The pool-lane panic arm was otherwise unpinned: the existing `LANE_PANIC_INPUT` fires in `run_lane` before anything lane-specific, so it always panics the caller's lane 0, whose payload unwinds directly and never exercises the driver's resume.

### 2. Low — `decode_all_mt`'s multi-frame fixed arm documented a `place` call that does not exist (fixed)

The arm's comments said "one place call covers every lane" and "The fixed-slice `place` accepts any end within the buffer, so one call with the full length covers every lane", but the fixed path hands `base, buf_limit` to `decode_frames_fixed` directly — the `place` callback belongs to the growing-vector arm (`Place::Deferred`). The stale text misdescribes the executor's placement model exactly where a future edit would consult it. Rewritten to the actual contract: the buffer is valid up front, lanes start immediately, a too-small target surfaces from the executor's own write-limit checks.

### 3. Low — the opt feed's arm switch was named and documented as a test-only override (fixed)

`FEED_TEST_OVERRIDE` defaulted to `true` and gates `opt_ldm_feed_band`, so the serial LDM feed runs armed in production and tests stand it *down* through `set_ldm_feed_for_tests` — the inverse of what the name and the "Test-only serial-feed override" doc assert. A reader auditing the band predicate would conclude the pledged opt-row feed never runs outside tests. Renamed `OPT_FEED_ARMED` with the doc stating the production default; `UNPLEDGED_DEEP_BAND` in `stream/encoder_mt.rs` carried the same "Test-only ... switch" mislabel for the same default-armed pattern and got the same doc correction (its name was accurate, so it stands). `RAMP_TEST_OVERRIDE` is a genuine sentinel override (`u64::MAX` = read the env) and needed nothing.

## Verified without action

- **Lane output-base computation**: staging publishes per-segment outcomes on `seg_sizes` (`out_size + 1`, `usize::MAX` on stage error) before the slot fill; a lane's base is the fold of its predecessors' published sizes, erroring lanes abort downstream lanes through the `usize::MAX` marker, and the deferred placement folds the bound only up to the first error in segment order — so no lane past a failing segment ever computes a base or writes.
- **The lane wildcopy discipline**: each lane passes its segment's own end as the wild cap; the hot path's single check `o_match_end > oend_w` with `oend_w = min(write_limit, wild_cap) - 16` keeps every 16-byte overshoot inside the lane's own range, and the cold path re-checks `budget_end = (start + cap).min(write_limit)` first, so a too-small caller buffer fails `TargetTooSmall` without an out-of-bounds write.
- **Error precedence**: the min-failing-segment rule reproduces the serial executor's error (`first_fail` over ascending ids); a checksum mismatch loses against any decode error and wins in frame order among checksum errors — the serial MT executor holds the same order (`decode_parallel` reports a checksum only after every segment executes), and the accept/reject symmetry with the sequential decoder is the pinned contract (R98's adjudication: variant equality was never part of it; `multiframe_grouped_error_precedence` and `multiframe_middle_frame_checksum_grouped` pin the shapes).
- **The mid-epoch fold**: the fold resets exactly at restart candidates, snapshots before `observe`, and carries `None` precisely where a restart cut starts fresh; `prime_tables` replays each axis's last describing block in ascending block order, skipping one block's repeated start, and the malformed-prime error ordering holds because every replayed description belongs to an earlier segment that stages through a superset parse (`subsegment_staging_matches_whole_epoch` pins the equivalence over every candidate boundary).
- **The cut planner**: the restart snap fires only within `r - target <= target / 2`, targets a snapped start already covers are skipped, mid-epoch cuts tie to the earlier boundary, and the ramp ladder (`advance_target`) doubles from `RAMP_HEAD_INPUT` to the target and strides after it — the pinned geometry (`plan_cuts_snap_to_restart_within_one_and_a_half`, `plan_cuts_ramp_doubles_head_until_target`) matches the ramp gate's four disarm terms (`ramp_gate_terms`).
- **The stage-A poison fill ordering**: every fill arm notifies `ready` before returning (the `810f4e2b` fix), the poisoned slot is filled so the ordered consumer runs to completion, the scratch is dropped and the thread retired. The monotone `next_job` claim counter guarantees the consumer always reaches the poisoned slot: a segment id is claimed only after every lower id was claimed, and a claimed segment always completes or fills its slot — no segment below the panicked id can go unstaged.
- **The lease pools** (`decoding/mt_pool.rs`, `stream/mt_pool.rs`): the pool mutex and a slot's state mutex are never held together; the idle-withdraw race is closed by `unpark_self` succeeding only on the side that removed the slot, with the state re-check catching the assigner that won; `wait_leave` and every sleep loop are bounded re-checks. The stage-A pool test pins retire-on-drain (`pool_threads_retire_after_decode`).
- **The staged executor's bounds**: stage A caps every block's output at `min(window, MAX_BLOCK_SIZE)` before sizing anything, saturates its sums on 32-bit targets, and its `Σll + Σml` cap bounds the executor's `op + ll` and `op + ll + ml` adds from wrapping; the hot path's combined check sends every edge to `exec_staged_end`, whose exact chunked copy re-checks both bounds in order; the staged literals' 16-byte zero tail keeps the unconditional 16-byte literal copies' source overread initialized.
- **The offset selector**: the inline repcode resolution matches `do_offset_history` over the full wire grid including the `rep0 - 1` saturation arm and the `u32::MAX` sentinel the piece validator seeds (`staged_selector_matches_offset_history`), so a piece that validates executes without hitting the sentinel.
- **The piece executor** (env-gated): `validate_piece` measures the deepest external read with the `+16` wildcopy read overshoot capped at the piece's own start — an upper bound, since `wildcopy_match` reads in 16-byte chunks past `ml` and the cold path copies exactly; a piece's `max_top` never exceeds its own start, so the watermark gate can never wait on a piece whose completion would advance it (the claimed piece is the first not-done one at that point, and its start equals the watermark); `refresh_grids` at completion kills every grid and withdraws a settled winner when the staged output diverges from the pledge, so a divergent stream falls to `run_serial`, which runs the same pledge and checksum tail checks as the serial executor.
- **The stepped finish drain**: `finish_step(true)` returns only on assembled output, the closing slice, or an error, so every read-pump call makes progress; the handoff re-arms the output wall the caller's next entry asserts; `close_empty` closes a nothing-fed frame through the same empty raw last block the ST path emits (`finish_step_hands_off_undelivered_output`, `empty_stream_closes_through_the_step_path` pin both).
- **The zero-copy feed's determinism**: `pump_owned` feeds the whole source in one step and walks the staging gates in the same fixed order over the same prefixes the Read pump walks, so every verdict lands identically; the owned view is pinned against the construction pointer and length in debug, and the byte-parity gates hold it against the Read pump across the armed bands (`owned_entry_matches_read_encoder_bytes`, `owned_entry_matches_read_encoder_deep_band`, `owned_entry_matches_read_encoder_opt_feed`).
- **The growing grid and reserves**: `growing_epoch` tiles from zero with per-epoch doublings to the buffer-scale cap, `post_ready` clamps a flush-regridded start's job to its epoch floor and `build_bounds` re-aligns the walk there, and `post_due` holds a pledged grid's final job for the finish plus the feed's covering block-lattice chunk (`feed_cover`). `reserve_decided` keys the exact pledged extent and the open-stream cap; `make_space`'s growth arm doubles below the cap at every recycle point by design, and at the all-live-at-cap corner it grows past `BUF_CAP_MAX` by `want + 64 KiB` per step — a bounded creep the wrap recycles at the same grid lines, not a leak.
- **The poison publish order** (`QueueShared::publish_poison`): payload under the lock, then the flag, then the job's abort — a flag reader always finds the payload, an aborted job is never observable ahead of the flag, and `surface_poison`'s `(true, None)` arm panics rather than shipping a frame missing the poisoned job's bytes; `serve_queue`'s panic arm drops the worker-local state and retires the thread.
- **The serial LDM feed**: `SerialLdmFeed::advance` publishes only on the multiples of `MAX_BLOCK_SIZE` from zero plus the frame end — the bulk gate's own `run_ldm_feed` chunk lattice — so the publication is bit-identical to the bulk feed thread's over the same input, and `span_for` re-bases the published splits into the job view's coordinates (the `98f7bc43` fix; `opt_serial_ldm_feed_pledged_stream_matches_bulk` and `..._past_the_window` pin both directions).
- **The fuzz drives** (`decode_mt`, `encode_stream`): the multiframe oracle's MT arm rides `decompress_with`, whose vec entry grows through the placing executor, so its `Ok/Err` oracle is well-formed against the growing sequential reference; the noise anchor and the engagement counters assert the lane path actually engages; the restart-poor `-9` frame parks once per process so every campaign re-decodes it through both entry points.
