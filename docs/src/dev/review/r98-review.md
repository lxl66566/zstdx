# R98 review: NT feed, owned source, stepped drain, mid-epoch staging

Scope: the encode and decode landings the R95 sprint reviews did not cover — `stream::read::NtSource` with the AVX-512/AVX-2 NT-store kernel (`common/nt_copy.rs`, `1076e9d2`), the zero-copy `OwnedEncoder`/`OwnedSource` feed (`f039a107`), the read path's stepped finish drain (`2a8597b0`) and the decode side's mid-epoch stage-A staging with the restart fold and table priming (`285e4dac`). The pledged feed's view re-base (`98f7bc43`) was checked alongside, since it is the same window's job-view coordinate discipline. Each area was read against the encoder-invariants skill, the poison-wall protocol and hardening.md's memory-safety classes.

## Findings

### 1. Medium — the fuzz campaign's stated targets were unreachable (coverage gap, fixed)

The encode_stream target's layout had no worker field and constructed neither `NtSource` nor `OwnedEncoder`: every chunk ran the single-threaded read core over a plain slice, so the mt read pump, the stepped finish drain and both zero-copy feed entries — the surfaces this round's campaign exists to cover — were dead code from the fuzzer's view. The drive now derives the worker count from the level byte's spare high bits (`1 + level / 23`: the ST core through mt 12) and picks the read core's feed entry off `rest`'s first byte and `ph` bits 5..6 (plain slice, NT reader, owned source) in both the chunked walk and structure mode; the input layout and the artifact walker's parse stay untouched, and the walker keeps replaying the shared layout through the bulk core only. `decode_mt` gains a committed libzstd -9 restart-poor seed class so the mid-epoch table priming runs on every campaign instead of only under the unit equivalence tests. Fixed in `3fbc57e6`.

### 2. Low — the NT kernels ran untested in-process outside the host's top tier (hardening gap, fixed)

The unit test went through the OnceLock dispatch, so it pinned exactly one kernel per machine — on AVX-512 hardware the AVX-2 body (a different alignment width: 32-byte head peeling against 64) never executed in-process, and its head/tail logic was covered only by the env-forced bench ladders, which check frame bytes rather than the kernel's own copy. The test now sweeps each compiled kernel directly over the misaligned head and tail shapes, including the sub-threshold and exact-threshold lengths. Fixed in `58957794`.

### 3. Low — the ST pull size was spelled as a duplicated literal (smell, fixed)

The read encoder's staging chunk and the owned feed's single-threaded demotion each spelled the 16 KiB pull size, and the demotion's closing shape depends on keeping the read encoder's cadence — a coupling that deserves one named constant, not two literals that can drift. Both sites now share `encoder_core::ST_PULL`. Fixed in `58957794`.

### 4. Low — smoke.sh held the bench lock exclusive (protocol gap, fixed)

The smoke script took `flock` without a tier, so an eight-worker smoke excluded every other fuzz, test and build on the box for its whole run while the two-tier protocol gives fuzz the shared tier (exclusive remains the matrix/ratio/wall benches'). The script now takes `flock -s`. Fixed in `3fbc57e6`.

## Verified without action

- **sfence completeness**: every exit from an NT kernel is fenced or strongly ordered — the streaming path ends in `_mm_sfence` before returning, the unaligned fallback (an unreachable `align_offset`, or `head >= len`) copies through temporal stores, which need no fence, and no panic site sits between the first streaming store and the fence (the intrinsics are non-panicking and every pointer step is bounded by `len`).
- **The span gate**: `copy` serves spans at or above `NT_MIN` only; the ST core's pulls are the 16 KiB staging chunk and the owned demotion's 16 KiB steps, the decoder's are bounded by one block, and only the mt read pump's 1 MiB `spare[..want]` reaches the kernel. The final partial pull of a source shorter than its remainder's floor stays temporal by its copied length.
- **Detection caching**: the kernel choice resolves once per process behind the SIMD clamp's own OnceLock; `is_x86_feature_detected!` runs exactly once.
- **No new un-walled slack under the owned feed**: the core's accumulate buffer stays empty (no pooled reserve is taken, `make_space` returns at the owned guard, `Drop`'s `set_len` is a no-op at length zero), and every crossing buffer rides the existing walls — `pump_owned` re-arms the output wall between its post pass and `finish_begin`'s entry assert (the boundary the Read pump gets for free from its per-pull exit fill), the handoff return re-arms, `finish_end` re-arms, and `finish_step` carries no entry assert precisely because every append site re-arms.
- **The owned view pin**: `pump_owned` debug-asserts the caller's slice against the construction view (pointer and length), so a moved or replaced source fails in debug rather than reading freed bytes; `OwnedEncoder` declares `core` before `source` so the core's `Drop` — which joins every lease — runs before the source frees.
- **The single-pass feed's determinism**: `pump_owned`'s one `post_ready` walk resolves the staging gates in the same fixed order over the same input prefixes the Read pump walks; a short source leaves the probe, fast-capture and deep-band gates pending exactly as a short Read stream does, and the `settle_probe`/`cancel_deep_staging` paths inside the finish tail cancel them to stock at the same shapes. The pledge mismatch surfaces at the first read in both directions, matching the read encoder's contract.
- **No unstamped state reuse across cores**: the ST core pool's `reinit` re-declares the stock arming and reach before the reset (the R87 residue class), worker lease states reset per job, the decode scratch resets per segment before its prime, and the accumulate-buffer pool carries only the ever-initialized extent, re-zeroed per region before a read can hand it out.
- **The stepped drain's wait discipline**: the quiescent-with-pending branch is unreachable without poison (a worker marks its job done before decrementing `n_incomplete`, so an Acquire read of zero implies the front's flag), the handoff returns whenever undelivered output exists, the write path still drains inside one call, and poison surfaces from the pull that observes it — an aborted job assembles empty and drains like a completion, so the frame never ships missing bytes silently.
- **The mid-epoch fold's semantics**: the fold resets exactly at the restart candidates (every full re-description), snapshots at a cut before observing the boundary's own block, and tracks the four axes independently; the `cut_ok` reverse pass keeps Raw/RLE-literal restarts legal only while no Treeless use precedes the next rebuild. A prime axis left `None` is exactly the axis the whole-epoch decode also lacks at that point, so a Repeat or Treeless use fails identically in both paths.
- **Prime error ordering**: every replayed description belongs to an earlier segment whose staging decodes the same bytes through a superset parse (`prepare_section_table` and `maybe_update_fse_tables` are the table-build halves of `decode_literals` and `decode_sequences_into` over the same slices and sizes), so a prime error implies an earlier-segment error, and `take_stage_error` surfaces the minimum segment id.
- **The Huffman prime's shape purity**: the X1/X2 selection reads the same `regenerated_size` and compressed-size pair the staging path hands `prepare_section_table`, so the replayed table reproduces the in-sequence state exactly.
- **The pledged feed re-base (`98f7bc43`)**: `span_for`'s `split - view_base` cannot underflow — every selected split lands at or above the job start, which is at or above the view base both call sites pass — and the bulk side's view base is zero, so its bytes are unchanged.

## Test gaps

- The read-pump finish stepping is pinned at the core level (handoff, `close_empty`) and end-to-end by the byte-parity suites, but no test drives a read that abandons mid-drain (drop with `finishing` set and jobs in flight); the Drop join covers it structurally.
- `NtSource`'s benefit is loaded-machine only; the test suite pins bytes, and no gate pins the kernel's engagement (a `perf stat`-class check would be flaky by design and was not attempted).

## Campaign

Run on merged main plus the fixes, `smoke.sh <target> 1200 8` (ASAN, eight workers, shared lock tier). A smoke seeds a scratch slice from the real corpus, replays the whole corpus once in parallel as a crash check, then fuzzes from the slice plus the committed artifacts dir, writing new units into the scratch that the cleanup deletes — the shared corpora stay byte-stable at 5138, 3093 and 750 seeds.

- `encode_stream`: the 3093-seed corpus replayed clean, then 112,219 units over the eight workers (mean 11 exec/s per worker, wall 1252 s) reached the mt read pump, the stepped finish drain and both zero-copy feed entries; 5885 new units parked in the scratch (largest single job 780), peak RSS 1177 MB, zero findings.
- `encode`: the 5138-seed corpus replayed clean, then 206,131 units at a mean 21.8 exec/s per worker; two workers took an external interrupt at ~1000 s (libFuzzer's "run interrupted" exit path, not a crash — their stats still count), peak RSS 748 MB, zero findings.
- `decode_mt`: the 750-seed corpus replayed clean, then 16,752 units over the eight workers (constructor-bound, ~1.7 exec/s per worker, wall 1293 s) with the parked -9 frame routing through primed mid-epoch segments in every worker; 1,359 new units parked in the scratch, peak RSS 399 MB, zero findings.

The mid-epoch class needed one amendment after the encode-family runs: the committed -9 seed built its frame per input from a 288 KiB payload, which compresses to about 30 KiB — far below the 512 KiB parallel floor, so the class could only burn -9 time inside the sequential fallback and never reached the mid-epoch staging it exists to probe. The frame now parks once per process (`OnceLock`) at an 8 MiB records payload (about 830 KiB compressed, three segments at the 4-worker target), and `libzstd_nine_records_route_through_primed_segments` pins in-process that the committed class actually routes through primed mid-epoch segments; the decode_mt smoke ran against the fixed drive. The parked frame's repeated decode is itself a probe — the staging pool's residue reuse across decodes is the class's own hazard.
