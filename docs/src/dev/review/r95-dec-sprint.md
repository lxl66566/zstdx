# R95 decode sprint review

Scope: the R93-R95 decode-side and FFI landings since 2026-10-31 — the zero-sequence direct decode (`64b84806`), the in-place one-shot block parse (`9b01a64e`), the FSE spread shift (`903cb57d`), the X1 rank fill (`0d42195d`), the stage-A worker pool with its poison wakeup and panic-injection serialization (`f2df78ca`, `810f4e2b`, `3010952c`), the FFI streaming stage machine with its transcript pins (`dd4df0ac`, `2caa7259`), the NonZero offset resolution (`883ce869`), the X2 asm loop (`d1b9f1aa`) and the in-dst literals staging (`a64c38c0`). Encode-side commits of the same window are covered in the [encode sprint review](r95-sprint.md). This was a quality round: four hygiene fixes landed (findings 1 through 4), everything else is recorded here for a later gate.

## Method

Each commit was read against the HEAD state. The in-dst placement's bounds were re-derived from the executor's store and over-read discipline. The asm stretch was translated instruction by instruction against the Rust body it replaces and against libzstd's own asm loop, including the segment-overshoot question. The pool's lease transitions were enumerated against its two mutexes, with the earlier decpool review as the baseline. The FFI stage machine was traced through its hostage, sticky and cursor-commit rules, and the transcript grid's coverage was inventoried against the machine's error paths. The perf, negative and review pages were checked item by item against the code.

## Findings

### 1. Low — the hot loop's literal over-read comment names the wrong tail (fixed)

The SAFETY comment above the fused loop's unconditional 16-byte literal copy (`sequence_execution.rs:458`) said the literal buffer's zeroed 16-byte tail covers the over-read past the literals end. Since `a64c38c0` the same loop also runs with literals carved out of the output buffer past the block's write limit, where the coverage is the output buffer's own bytes that the placement's tail gate keeps readable, not a zeroed tail. The reads stay defined on both placements, so the comment was the only defect. Rewritten to name both sources. Fixed in `200c619c`.

### 2. Low — the in-dst dispatch guard rests on an undocumented gate coupling (fixed)

The dispatch at `block_decoder.rs:394` runs the out-of-line twin only under `placement == InDst && seq_section.num_sequences != 0`. The zero-sequence half is load-bearing: the inline zero-sequence arm below copies `literals_buffer` under a length taken from the section header, and that buffer stayed empty for a non-Staged placement, so a zero-sequence block reaching the arm panics on the `copy_from_slice` length mismatch.

The guard is sound, but only through a nonlocal fact: the in-dst gate, `written + block_out_max + 32 + lit <= out.len()`, implies the direct-at-cursor fit `written + lit <= out.len()`, so a zero-sequence block that passes the in-dst gate always took the direct-at-cursor branch inside `parse_sections_body`, and a sequence section too short to encode a count errors in the header parse before the placement returns. Neither the guard nor the gate recorded the coupling, so a future widening of one side silently re-arms the panic. The coupling is now stated at the dispatch. [decloop](decloop.md) round 3's record of the same fact says a zero-sequence block "takes the direct-at-cursor decode", which holds only when the target fits, and the conclusion stands through the implication above. Fixed in `200c619c`.

### 3. Low — ffiparity's changelog cites a hash outside main's history (fixed)

[ffiparity](ffiparity.md)'s changelog credited `5047a631` for the stage-machine port. That hash is the landing on the `r92-ffi-destfull` branch, taken two minutes before the main-history commit `dd4df0ac` of the same change, so `git merge-base` cannot resolve it into HEAD and a reader verifying the changelog against the log hits a dead hash. The entry now cites `dd4df0ac`. Fixed in this commit.

### 4. Low — the streaming block-body arm bound a field to discard it (fixed)

The catch-all `Stage::BlockBody` arm in `dctx.rs` bound `wire` and then silenced it with `let _ = wire;`, because the wire type's only consumer, the RLE body-size reduction, already ran in the block-header stage. The binding is now `_` and the silencing statement is gone. Behavior and code shape are unchanged. Fixed in `200c619c`.

## Verified without action

- The in-dst placement's bound arithmetic closes. The gate's `checked_add` keeps the pad and the tail inside the caller's target, so the write limit is never clamped when the placement engaged, which the twin's `debug_assert` states and its `TargetTooSmall` reclassification relies on. The 16-byte pad sits above the executor's maximum store at one byte short of the block limit, the 16-byte tail covers the 15-byte literal over-read inside an initialized `&mut [u8]`, and the staging region sits strictly above every executor store while every match source stays below the write cursor in the one-shot whole-history path. The staged bytes beyond `written` are overwritten by later blocks or live past the frame's output where the caller never reads them.
- The placement's refusal set is complete. The only non-HEADROOM caller of the flat block decode is `decode_frame_flat`: both streaming flat loops and `decode_from_to` pass `headroom == true`, so every path that could carry a wrapped generation refuses the placement, mirroring libzstd's `not_streaming` gate.
- The X2 asm stretch is instruction-equivalent to the Rust body it replaces. The three entry loads match the u32 layout the table builder writes, the `>> 53` index, the `shlx` count and the reload's `bsf`-retreat-refill-marker-shift sequence agree with `reload_x2`, and the block runs exactly 20 lookups and 4 reloads per iteration. Every register the template touches is a declared operand, `nostack` holds, and the block keeps the default conservative memory effect. The stretch runs exactly `iters` iterations against the scalar form's at-most-`iters`, both inside the same per-stream 10-bytes-per-iteration reservation. The 2-byte store's segment overshoot closes the way libzstd's own asm loop closes it: a store can pass a segment end only past a length-1 lookup, whose extra byte lands on the stream's own next output byte and is rewritten by the next lookup or the scalar tail, and a stream can reach its exact segment end inside a stretch only when every lookup of that stretch produced two bytes, whose stores then end exactly at the segment end.
- The SIMD tier gate panics rather than executes an illegal instruction when `ZSTDX_DEC_SIMD_TIER=bmi2` is forced on a machine without BMI2, and the `OnceLock` resolves the override once per process.
- The pool round's fixes hold at HEAD. The panic arm of `serve_stagea` falls through to the single `ready` notify after the match, both panic-injection tests serialize their store-to-restore window on the module mutex, and the watchdog test shapes the last-segment geometry. The two open items, one condvar driven by both the slot mutexes and the poison mutex and the `Relaxed` abort load, are pre-existing and recorded in [decpool](decpool.md).
- The NonZero offset narrowing is sound at every site. `offset_value > 3` proves the subtracted offset nonzero behind the unsafe conversion with the proving compare one line above, the malformed-dictionary saturation rule survives and now returns `None` exactly at the zero boundary, and `validate_piece` and the staged cold path consume the `Option` without changing any rejection. The staged selector's differential test covers the full repcode grid against `do_offset_history`, including the zero-seeded history.
- The rank fill and the spread shift land with their equivalence references: the scatter fill stays under `cfg(test)` against the rank-grouped port, and the spread constants are pinned against a plain-division reference over every table size and probability. The power-of-two claim behind the shift holds by construction of `num_state_slices`.
- The FFI stage machine's cursor discipline holds on every traced path. A call never exits holding a complete unprocessed block header, because the short-header break fires only while the header is still incomplete, so the block-header hint never reads 0 with a block pending. The hostage hold-back keeps `staging.len() == cursor`, so the single-pass shortcut's truncate stays exact, and a frame that ends while output is pending always consumed input in the call that took the hostage. Positions commit only on success, and the sticky replay covers the divergence from the reference's undefined continuation after an error. The shortcut's frame walk takes block-header sizes at face value exactly as `ZSTD_findFrameCompressedSize` does, and its fit gate runs against the caller's remaining capacity.
- The transcript grid is not happy-path-only. Its 41 cells include truncated, corrupt, bad-checksum, bad-magic and partial-garbage edits plus cells that record the reference's post-error replay, and the driver compares every call's return, both cursors and error code. The zero-sequence direct decode keeps its error positions: the peek only reads, every decline returns before an output byte moves, and a declined gate re-runs the staging decode with the same checks in the same order.

## Test gaps

- The forced SIMD tiers have no in-repo differential gate. `ZSTDX_DEC_SIMD_TIER` is a bench affordance, and the bench Readme routes the decode subcommands through it, but no cargo test runs the X2 asm stretch and the scalar body on the same inputs. A regression in the asm block's operands or template reaches CI only through the machine's detected tier and whatever literals coverage the corpus carries. The `OnceLock` resolution requires the override to precede the first decode in the process, so the pair needs separate test binaries or a bench-harness invocation. Closed in a follow-up: the `tierdiff` bench subcommand re-execs the binary under both forced tiers and compares every corpus cell's output length and hash across the streaming, staged and in-dst decode shapes.
- The in-dst placement has no pin of its own gates. The 64 KiB literals floor, the pad-plus-tail room refusal, the HEADROOM refusal and the single-stream decline all fall back silently, and acceptance needs a block carrying at least 64 KiB of four-stream Huffman literals inside a target with room for the frame plus one block maximum. The corpus roundtrips exercise the placement only where a frame happens to carry such a block, so the placement's byte-exactness rides on aggregate coverage rather than a targeted fixture.
- The FFI transcript grid has no dictionary cells and no `windowLogMax` cell. The per-frame dictionary re-arm at frame boundaries and the streaming window clamp both interact with the stage machine's frame-boundary consult, and the grid's cells are all dictionary-free with the default window.
