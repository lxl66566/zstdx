# Sequence-loop port review

Scope: commit `c50d6f73`, "dec: port libzstd's sequence loop structure into the flat executor", which rewrote `crates/zstdx/src/decoding/sequence_execution.rs` and `crates/zstdx/src/decoding/sequence_section_decoder.rs`. Reference: `ZSTD_decompressSequences_body`, `ZSTD_decodeSequence`, `ZSTD_execSequence` and `ZSTD_execSequenceEnd` in libzstd 1.5.7 at `/root/programs/fork/zstd/lib/decompress/zstd_decompress_block.c`, plus `OF_base`/`OF_bits` in `lib/decompress/zstd_decompress_internal.h`. This was a review-only round: no library code changed, and every actionable finding is a next-round candidate, because concurrent tracks own these files.

## Method

The commit diff and the landed code were read side by side against the C reference. Every memory-safety precondition was then traced to its enforcement site: the HEADROOM chain from `FlatOut::ensure_block_space` through `decompress_block_flat`'s target truncation into the executor's `oend_w`, the literals tail through `zero_wildcopy_tail`, and the repcode writeback through `DecoderScratch::reset` and the frame-decoder error paths. `cargo test -p zstdx` is green on the branch, and `cargo clippy --release -p zstdx` reports four warnings, all pre-existing in `encoding/btlazy.rs`, `encoding/opt.rs` and `stream/encoder_mt.rs`, none in the ported files.

## Safety verdict: sound

The unconditional 16-byte literal copy is bounded on every path that reaches it.

Write side. The hot path admits a sequence only under `o_match_end <= oend_w`. The largest wildcopy overshoot past a sequence end is 15 bytes: `wildcopy16` and the 16-byte chunk loop of `wildcopy_match` write up to 15 past their end cursor, and `overlap_copy8` writes at most 8. Without headroom, `oend_w` sits 16 bytes below the target end, so every store stays inside the caller's slice. With headroom, `decompress_block_flat` truncates the target to `block_limit = written + block_out_max` before the executor sees it (`block_decoder.rs`), and `ensure_block_space` guarantees the backing allocation holds `block_max + WILDCOPY_SLACK` beyond the cursor (`flat_buffer.rs:228`). So the stores land in `out_end + 15` at most, inside the 16-byte slack, for the literal loop, the 16-byte match loop, the 8-byte overlap loop and the wrapped-source wildcopy alike. The `exec_sequence_end` paths never overshoot: they check `o_match_end > out_end` first and copy exact lengths, and their `wild` copies only run under the headroom instantiation after the same end check.

Read side. `zero_wildcopy_tail` runs before every flat execution (`block_decoder.rs:221`) and keeps `[len, len+16)` of the literals buffer allocated and zeroed, which covers the over-read of `copy16` and `wildcopy16` at any literal cursor, including an empty literals buffer, where `reserve(16)` gives `as_ptr` a real 16-byte allocation. The hot path checks `i_lit_end > lit_end` before the copy, and the exact path re-checks `*lit + ll > lit_end` before its plain copy.

Wrapped-generation reads. `copy_wrapped_match`'s wild fast path reads up to 15 bytes past `src + ml`. The guard `d >= ml && offset + ml <= seg_a_end` plus the hot-path budget bounds that read end at the previous generation's physical end plus 15, and the last block decoded in that generation had `end + block_max + WILDCOPY_SLACK` of buffer behind it, so the read stays inside the allocation and inside zero-initialized bytes (`buf.resize(target, 0)` growth).

Repcode history. The three locals are written back to `offset_hist` only on loop success; every error return inside the loop discards them, so a mid-block abort leaves the last successful block's history in place. Frame reuse reinitializes it: `DecoderScratch::reset` restores `[1, 4, 8]` (`scratch.rs:45`), and both `FrameDecoderState::new` and `reset` route through it. A poisoned history cannot leak into a pooled decoder's next frame. One ordering divergence exists and is unobservable: libzstd saves the reps after its `BIT_endOfDStream` check, zstdx writes back before `finish`, so a frame that fails the final padding check leaves different rep values behind. Both treat the frame as errored, and the next frame resets the history.

## Parity checks

- Field read order matches `ZSTD_decodeSequence` exactly: offset add-bits inside the offset branch, then match length, then the mid-sequence reload when `ll_bits + ml_bits + of_bits >= 31`, then literal length, then, for every sequence but the last, the three transitions in LL, ML, OF order followed by the end-of-sequence reload. The 31-bit threshold equals libzstd's `STREAM_ACCUMULATOR_MIN_64 - (LLFSELog+MLFSELog+OffFSELog)`, and the last sequence skips transitions and reload exactly as `isLastSeq` does. Initial states read in libzstd's LL, OF, ML order.
- The offset tables agree code by code. `OF_CODES` packs base `1 << code` and the executor subtracts 3 at use; libzstd pre-folds the same subtraction into `OF_base` (`0, 1, 1, 5, 13, 29, ...` with `OF_bits = code`). Codes 2 through 5 were checked value by value; real offsets cover the same ranges on both sides.
- Repcode semantics match. Code 0 resolves `rep[ll0]` with libzstd's history shuffle, and code 1 forms `idx = of_base - 1 + ll0 + bit`, which equals libzstd's wire value 1 to 3, with `idx == 1` selecting rep1, 2 rep2, 3 the `rep0 - 1` pseudo-slot, and `idx != 1` gating the rep2 rotation exactly as libzstd's `offset != 1` does. The zero guard is stricter than libzstd's `temp -= !temp` wrap: a dictionary-seeded zero history saturates and lands on the explicit `ZeroOffset` rejection.
- The combined check `i_lit_end > lit_end || o_match_end > oend_w` covers the same edge cases as libzstd's `iLitEnd > litLimit || oMatchEnd > oend_w`, and `exec_sequence_end` re-checks in libzstd's order: end-versus-target first, then literals, then the offset reach `offset > o_lit_end - virtual_start`.
- The `ofBits > 1` branch keeps libzstd's semantics: codes 2 and up read their add-bits inside the branch, rotate the history with three moves and never touch the zero guard, since `of_base + bits - 3 >= 1`.

## Findings

1. Low, next-round. Stale references to functions the commit deleted. `sequence_execution.rs:779` names `exec_one_flat` in `copy_wrapped_match`'s dispatch comment, `block_decoder.rs:38` and `block_decoder.rs:217` name `wildcopy_literals` in `zero_wildcopy_tail`'s contract, and `docs/src/dev/comparison.md` cited both. The comparison page is fixed in this round; the code comments belong to files under concurrent rewrite and are recorded here for the owning tracks.
2. Low, next-round. The inline repcode rotation in `execute_decoded_flat_inner` and `do_offset_history` implement the same spec table in two shapes, branchy locals and select form. `do_offset_history` carries the reference unit test; the inline form is pinned only end-to-end through the parity and corrupt gates. A regression test that pins the inline shape would need a factored form, and factoring it risks the loop's live set, so the gap is recorded rather than closed.
3. Informational. The hot path computes `op + ll` and `o_lit_end + ml` with non-wrapping adds where libzstd carries an explicit `MEM_32bits()` overflow guard in the combined check. On 32-bit targets the adds cannot wrap in practice, because both lengths stay under 132 KB while user-space allocations sit far below `usize::MAX`, but the reasoning is implicit. A one-line comment at the add sites would pin it.
4. Informational. `exec_sequence_end` takes `HEADROOM` as a runtime `bool` while `NOWRAP` stays a const generic, and its `out_base` parameter is read only under `seq_dump`. Both are deliberate cold-path choices; noting them here so a future reader does not mistake them for port debris.

## Verified clean

- The port left no dead code: `exec_one_flat`, `wildcopy_literals`, `decode_step_wide` and the `FUSED` generic are gone, and `SEQ_TABLE_SLOTS` remains live through `scratch.rs:151`. The staging `decode_step` keeps its batched two-read body and wire offsets, which MT stage A requires, and the divergence from the flat loop's per-field body is documented on both sides.
- The packed entry layout moved to libzstd's `ZSTD_seqSymbol` field order with endian-specific `EntryRef` offsets, and `entry_field_loads_match_shift_extraction` pins the load form against the shift form on both endiannesses.
- Comment placement follows the line-precise rule: every `unsafe` block carries a local SAFETY argument, and the loop's load-bearing choices (the unconditional copy, the reload threshold, the last-sequence skip) are annotated at their sites.
