# Performance Optimization · Encoding (excl. matchers)

> Matcher and level strategy: see [Matchers and Compression Levels](matchers.md); multithreading and streaming pipeline: see [Multithreading and Streaming](mt-stream.md).

## Entry and state management

- **zero-copy slice entry** `compress_slice_to_vec`: the match window directly borrows the input (raw-pointer window + unsafe Send), eliminating the read pass, window compaction, and per-call window allocation; output upfront-reserved, blocks written straight into the final output. text +40%, zeros +60%. `51b019e`
- **thread_local state pool** (hash tables/default FSE tables/BlockScratch, take()-style reuse across calls, nesting-safe): 1KiB payloads 3-7×, 4KiB +30-80%. `cb02c32`
- **emit path rework**: entropy tables take/restore by value instead of deep-cloning 3×FSETable+Huffman per block (the original several hundred allocs per block was the biggest black hole, ~30%); `start_matching_into` buffer direct-write replaced the callback closure (the closure captured 2×Vec + matcher state → register spills, one store sampled at 40%); matcher window reads unchecked. Itemized +2%/+2%/+11%, cumulative json +24%, text +39%. `68ae651` Lesson: **unchecked-read gains (+11%) far outweigh structural rework (+2%×2); bounds checks on byte-wise paths are the prime target**.
- block contents written in place into the frame output (reserve the 3-byte block header first, backfill after compression) + literals/sequence/precomputed-code buffers moved into the BlockScratch pool: random -6.8% instructions. `95b2006`
- zero-sequence blocks skip literal staging (matcher skips the whole-block copy, encoder reads the window directly): random 64K-1M +13%. `15d127d`
- **arithmetic tANS transition tables (2026-09-16)**: the encoder's FSE tables materialized a full `(max_symbol+1) × table_size` packed-entry matrix — ~54K u32 stores per fresh-table block (LL 36×512 + ML 53×512 + OF 32×256) plus the 3×256 row-pointer setup in `encode_sequences`. The tables now carry libzstd's `FSE_CTable` arithmetic form in ONE pooled buffer (≤10 KB total vs 218 KB): `tt[256]` u64 entries packing `(delta_nb_bits, delta_find_state)` and a `table_size`-wide u16 `state_table` of biased next states (`table_size + index`, ascending-position symbol-major rows). One step is `nb = (state + dnb) >> 16`, `emit = state & mask(nb)` (the run baseline is a multiple of the run width, so the biased state's low bits ARE the old precomputed diff), `next = state_table[(state >> nb) + dfs]`; the build writes O(table_size) entries and the row-pointer machinery disappears with the rows. Equivalence with the old run walk is structural (same spread, same cumul rows, doubles-first-in-index-order) and pinned by the rewritten `soa_matches_reference` differential (400 random tables, every (symbol, state) step vs the reference runs) plus `check_tables`; output byte-identical everywhere (30-file full-ladder dump, 120-cell ratio sweep, all modes). Effects: gungraun small json-4K −7.0% Ir / text-4K −5.2% / 16K −2.2..−2.4% / 64K −1.2..−2.0%; the 1 MiB encode slices put the hot-loop price at ~+25 Ir/seq on sequence-dense json (fastest/fast +1.8/+3.5% Ir) and −0.6..−1.6% on text — and the wall follows the build side, not the Ir: small band json-4K x1.79→1.62 (−9.4%), text-4K −6.1%, the whole 4K-1M band −1.6..−9.3% (json-64K fast crosses to x0.98); matrix json.fastest −2.0% (581→594 MiB/s), json.fast −3.9% (445→469), text fastest/fast −2.4/−3.3%; dll100 fastest +1.6-2.2% (367→373-375), fast +1-2%, balanced +1-5%. Lesson: the materialized form's per-sequence packed entry saved ALU but kept a 218 KB L2-resident working set behind every block — the L1-resident arithmetic tables win on wall at every measured shape even where Ir rises.

- **entropy-build scratch pooling (2026-09-16)**: the per-block FSE/huffman table builds allocated and zeroed their buffers on every build — on a json-4K fastest call that was ~15% of Ir in memsets alone (the `vec![0u32; probs.len()*table_size]` transition tables ×3, package-merge level lists, huffman `codes`, wire weights) plus the malloc/free churn (~3%). `FSETable`/`HuffmanTable` now return their transition/codes buffers to pools held in `BlockScratch` (`FseBuildScratch`/`HuffScratch`), and the builds write into recycled buffers: a buffer's `len` is its initialized prefix, so growth (the only zeroing left) happens once per size, not once per table — live rows are fully overwritten by the build walk and dead rows stay stale-but-unread (wire codes never exceed the histogram's `max_symbol`; `bulk::tests::pooled_calls_byte_identical` pins the repeated-call outputs). Recycling sites: table adoption in `compress_fastest`, the raw-block fallback, `reset_slice_state`, and the huffman weight-table temp inside `write_table_with`. Measured on the new gungraun small-payload bench (`zstdx-gungraun/benches/small.rs`, deterministic per-call Ir): json-4K −13.6% Ir, text-4K −11.1%, json/text-16K −7..8%, −7% at 64K. Wall (interleaved A/B): json-4K x1.96→1.83, text-4K x1.91→1.87 (abs +8%), json/text 8K/16K −4..6%, skewed-4K x0.90→0.80, json/text-1K x2.30/2.48→1.95/2.17; 64K-1M and the 32MiB matrix stay flat (json) to ahead (text fastest/fast +11-20%: per-block builds amortize there too). Byte-identical output: 5 shapes × levels 1/3/9/16/19 emit-diffed against the pre-change build. Residue: the 12 KB lane-zeroing in `choose_tables_fast` (the build walks and the row-pointer setup are gone with the arithmetic-form round above).
- **CTable build restructured to libzstd's shape (2026-09-18)**: the gap vs C was attrition, not algorithm — `build_table_from_probabilities_into` at 13.3K Ir/call over the 4 builds of a json-4K encode vs C's `FSE_buildCTable_wksp` 8.1K (a full `owner` 255-fill per table, a separate -1 placement round, a per-occurrence spread walk paying a skip check per step, and a cumul + cursor u32 pair, 2 KB stack traffic). Now C-shaped: the -1 placement rides the row-start pass (`start[s]` doubles as the state-table walk's cursor and transforms into the biased start state inside the tt fill, whose running total re-derives each row start — cumul and its copy are gone); builds without -1 weights (the small-payload norm: weight tables normalize with `useLowProbCount=0`, sequence tables below 2048 symbols) take C's fast path — symbol runs staged contiguously at eight bytes per unaligned u64 store into a pooled high-water spread buffer, then a fixed-step two-way unrolled scatter of constant trip count (`step` is odd for every table_log ≥ 4, so the walk covers each position exactly once; `spread[k]` is the k-th symbol-major occurrence, making the placement provably identical to the classic walk); `owner`/`spread` recycle without any per-build clearing (every slot up to `table_size` is written; the sum invariant is debug-asserted in the row-start pass). `soa_matches_reference` grew to 600 cases with every third banning -1 weights, pinning the fast path against the classic-walk reference. gungraun small: json-4K −1.34% Ir (x1.224→1.208 vs libzstd), text-4K −1.06%, 16K −0.4/−0.5%; wall-neutral on its own — the cut is loop-overhead Ir, not memory traffic (the huff0 half below completes the lesson). Full-ladder dump byte-identical.
- **FSETable thinned to one pooled buffer (2026-09-18)**: the struct carried `probs: [i32; 256]` + `start: [u16; 256]` inline (~1.5 KB), so EVERY hop memcpys it — the build return, the `FseTableMode` enum wraps, `FSEEncoder::new`, `compress_fastest`'s `old_tables` array (3×`Option<FSETable>` = one 4.6 KB memcpy per block), `replace_previous` ×3, the `BlockOutcome::Encoded(BlockTables)` return, `reset_slice_state`'s takes — callgrind put the whole memcpy class at 8.9K Ir of a 184.8K json-4K call (4.8%), where C pays ~0 (its literals staging is inline wildcopy and its CTables are workspace pointers). The fat arrays moved into the existing pooled `tab` buffer behind fixed offsets (`[tt: u64×256][probs: i32×256][start: u16×256][state_table: u16×table_size]`, +2.5 KB per pooled table), the struct drops to 32 B, and all those hops become register moves; the `probs_full` staging copy inside the build disappears the same way. Recycled tails stay stale-but-unread under a new `nsym` bound: `write_table`'s serialization and zero-run scans stop at `nsym`, and `symbol_bit_cost` returns `None` past it (the repeat-coverage check that reads a dead symbol — the one reader that could observe stale bytes; caught by `pooled_calls_byte_identical` before the bound went in). Byte-identical (full-ladder dump); gungraun small: json-4K −4.45% Ir (x1.181→1.128 vs libzstd), text-4K −3.47% (1.148→1.109), rand-4K −4.9%, 16K −1.0..1.2%, 64K −0.3..0.4%; the memcpy class itself 2.28M→0.29M Ir on the 256-call json-4K bench. Gotcha: the region offsets must be derived in ONE unit — the first cut mixed u16-index and byte arithmetic (`START_U16_OFF` 256 slots low), overlapping start into probs and smearing the serialization; the symptom (write_bits value-overflow on the legacy roundtrip path only) pointed far from the cause.

## FSE

- SoA flattened tables (probs/start/transitions in contiguous memory) replace 256×Vec + double sorting. `81afece`
- per-symbol spread precomputation; flat transition table `(next<<13)|(nb<<9)|baseline` O(1) state transitions + LL/ML code LUT: json 189→245 MB/s. `5619e80`
- 6 write_bits per sequence merged into 2 u64 spellings (transition bits ≤27bit, add-bits ≤51bit, one each): another +4%. `bbde2ea`
- transition bits and add-bits merged into one hot_push (combined ≤56bit safe cap, falls back to double push beyond it). json -0.4% instructions. `2d18813`
- **encode_sequences upfront reserve + raw pointers**: one reserve of `nb_seq*11 + 32` bytes (≤51 add bits on the last sequence, ≤87 per earlier one, plus the 8-byte flush-store overshoot) replaces the per-push capacity probe (a Vec field load + branch per sequence); the seqs stream and the three FSE transition-row tables move to raw pointers — the slice/Vec fields rode the stack through every iteration and were the function's hottest single instructions. Byte-identical output; gungraun json.fastest a further -1.3% (cumulative -4.0% with the emit split), json.fast -0.9%.
- **encode_sequences per-code row-pointer tables**: the loop-invariant half of each row address (`rows + (code << shift)`) is resolved once per block into 256-entry tables of raw pointers; the hot loop reaches a transition entry with one rsp-addressed stack load plus one indexed load through it. The first generation stored u32 row offsets and OR'd the state in, but that kept a third live base register per channel — registers the loop does not have, so all three row bases reloaded from the stack every sequence. Byte-identical output (full-ladder dump gate); gungraun fastest/fast −0.7..−0.8% Ir on json/text, balanced −0.15..−0.19%, skewed.fast −0.18% (skewed's low tiers stay on RLE one-state tables and miss the path). A SeqWord 24→16 B shrink trading the separate `add_nb` load for a packed width byte was falsified: the packing ALU lands in the hotter matcher emit (see negative.md).
- **precomputed transition diffs in FSE entries**: a flat row is indexed by the state itself, so the emitted value `state - baseline` is a build-time constant per row position — entries now pack `(next << 16) | (nb << 12) | diff` with the run offset written at build time, and every consumer (encode_sequences, `FSEEncoder::encode`/`encode_interleaved`) reads the diff straight from the entry. Kills one sub plus its feeding mov per channel per sequence, and the three end-of-loop state copies disappear (entries land in registers that update in place via `shr 16`). Byte-identical output (full-ladder dump gate); gungraun json fastest/fast −1.3%/−1.5% Ir, text −0.9%/−1.2%, skewed.fast −0.3%.
- **table mode selection** (port of the libzstd `selectEncodingType` fast branch): RLE single-code / Predefined threshold / Encoded + normalizeCount M2 normalization + optimalTableLog + last-sequence count decrement. json ratio 5.22→5.37. `1a17db3`
- **repeat mode (mode 3)**: when the previous block's table covers all active codes and the bit-cost estimate (Σ c·log2) ≤ new-table description + entropy lower bound, the whole table is reused with zero description bytes; a Predefined/RLE choice invalidates the remembered table (`PrevTable::{New,Keep,Clear}` three states guard against table-state desync with the decoder). json -2.2% instructions, ratio 5.99→6.00. `7769bf8`
- RLE degenerate single-state FSE table: table_size=1 takes exactly the same path as normal modes, zero special-case branches.
- **fastest-tier mispredict differential study (2026-09-14, LBR `perf record -j any` + `/M` flag on AMD)** — per-branch attribution of json.fastest's ~3.1M misses/pass (~17% of cycles): the single largest mispredicted branch is encode_sequences' bit-writer headroom check `nb+bits ≤ 63` (~18% of misses; the next target, and the branchy counterpart of the already-landed writer work above), then the scan_fast rep OR-fold — which the short-circuit `a == 0 || b == 0` had compiled into *three* unpredictable branches (a-cmp, b-cmp, combine, ~19%), extend_match's u64-compare loop exits (~9%), the two hash-match compares (~9%), and insert_covered's mod-2 unroll parity guard (~4%). Fix with the study: the fold as `(a == 0) | (b == 0)` — one branch, `a`-disambiguation on the taken path. Byte-identical on the full-ladder dump; branch-misses −1%, wall neutral (json −0.5%±noise) — the mispredict inventory shrank, making encode_sequences' headroom branch the clean next cut.
- **unconditional bit-writer flush (`hot_push_raw`, 2026-09-14)**: the headroom branch `bits + nb >= 64` — the study's largest single mispredict (~18% of json.fastest misses) — is gone by adopting libzstd's BIT_flushBits discipline: every push flushes its whole pending bytes (`k = bits/8 ≤ 7`, one unaligned u64 store, `acc >>= 8k`) before OR-ing the payload, so `bits < 8` on every entry and any nb ≤ 56 still fits the accumulator. Traded +0.4-0.6% Ir (the extra stores fire even when the old branch fell through) for the branch elimination: wall json.fastest 541→562 MiB/s (+4%), json.fast 425→447 (+5%), skewed.fastest 2758→2873 (+4%), text +1%, skewed.fast flat; full-ladder dump byte-identical. Lesson: **a ~18%-of-misses branch is worth ~5× its instruction-count price in stores**; the reverse trade (store folding to save <1% Ir — see negative.md's write_bits_64_cold row) never pays.
- **insert_covered peel-then-pairs** (with the study above): the `while p < end` insert loop auto-unrolled mod 2 behind a per-entry parity guard (~4% of json.fastest mispredicts); peeling the odd tail once and inserting in explicit pairs keeps the unroll without the guard. Byte-identical on the full-ladder dump; gungraun Ir json +0.05%/text flat vs the guard form (the two alternatives that *lost*: plain counted `for k in 0..count` stays rolled, +3.3% Ir; a hand-unrolled counted loop with per-iteration `start + k` addressing, +4.3% — see negative.md). Wall neutral.
- **encode_sequences output cursor** (2026-09-16): the per-sequence loop kept `pos` as a byte offset and reloaded the output base pointer from its stack slot every iteration (register pressure — sixteen live values) just to form the flush store's address, and spilled the loop counter on top. The loop now carries ONE output cursor pointer (advanced by each flush's byte count; the exit position is derived once at the end) and terminates on the SeqWord pointer instead of the counter. Byte-identical (full-ladder dump); gungraun fastest/fast json −0.35%/−0.42% Ir, fast text −0.39%; wall neutral on interleaved A/B (x-bands overlap every round — the loop is latency-bound: the two-level row-pointer loads and the serial accumulator chain set its floor, the cut is uop-side). The concat's variable shifts are at their floor for this entry form: `nb` is per-entry, not per-row (a symbol's double-states split nb/nb+1 — `fse_encoder.rs`'s baseline walk), so the per-code row-pointer tables cannot carry the widths to shorten the post-entry extraction chain.
- **NCount serialization pair at C parity (2026-09-18)**: `FSETable::write_table` + `normalize_count` sat at ~3.3K + ~2.9K Ir per json-4K encode. `write_table` paid a `BitWriter::write_bits` call plus an ilog2 width-ladder recompute per symbol; it now ports libzstd's `FSE_writeNCount_generic` shape onto the writer's hot state: `threshold`/`nb_bits` track ilog2(remaining) incrementally, the value/width arithmetic is libzstd's (`max = 2·threshold−1−remaining`, widen at ≥ threshold, one bit less below max), zero runs emit 24-zero chunks as one 0xFFFF pair, and the description accumulates in a register u64 flushed as unaligned 8-byte stores (`hot_state`/`set_hot_state`, one reserve of 4+15·nsym bits). `normalize_count` reslices both slices to the live alphabet once so the per-symbol loop indexes known-length slices bounds-check-free — the zip-enumerate form cost MORE than the checks it removed (zip bookkeeping replaced them; plain indexing over resliced slices is the form that elides). Per json-4K encode: write_table 3.29K→3.01K Ir (C's `FSE_writeNCount_generic` 3.32K), normalize_count 2.86K→2.29K (C 2.22K). gungraun small vs pre-change baseline: json-4K −0.51% Ir (x1.110→1.105), text-4K −0.44% (x1.082→1.077), 16K −0.14/−0.15%, 64K −0.05%, random unchanged; wall direction-positive (json-4K 536→540, text-4K 367→394 MiB/s, Ir is the gate on this box). Full-ladder dump byte-identical, 223 tests pass. The entry-flush bug the tests caught is in [pitfalls](../pitfalls/encoding.md).

## Huffman

- **boundary package-merge optimal length-limited codes** (Larmore-Hirschberg; production superseded 2026-09-18 by the two-queue `HUF_buildCTable` port below, `cfg(test)` optimality reference since) replacing the initial rank-weight ladder (the old scheme depended on count order, not magnitude — large losses on skewed histograms): all levels benefit, json Ultra 7.33→7.52, text fastest 196.6→206.0. `aa07308`
- `build_from_weights` counting sort: package-merge caps weights at 11, so 12 stack buckets with symbols scattered in ascending order reproduce the comparison sort's weight-ascending/symbol-ascending order exactly (byte-identical output, gate: full-ladder dump); removes the per-block heap Vec and the O(n log n) sort. text-4K small-payload encode +5% wall-clock, gungraun instruction counts drop on every text-shaped cell, no regressions elsewhere.
- The package-merge walk's earlier attrition rounds (scratch rework, fixed-capacity array stacks, per-level sort removal) are gone with the algorithm swap below; package-merge is `cfg(test)`-only now.
- **two-queue tree build replacing package-merge (2026-09-18)**: the walk itself was the residue — a fresh attribution put `build_from_counts_into` at 26.7K Ir/call (merge loop 12K + package formation 5.9K + backtrack 5.6K) against libzstd's whole `HUF_buildCTable_wksp` at 10.5K, a 2.5× algorithm-class gap: package-merge pays max_len levels of 2(n-1)-wide 8-byte-entry merges, C builds an unlimited-depth Huffman tree in O(n) (count bucket-sort scatter + two-queue merge over the sorted leaves with a count barrier at slot 0 and 2^30 markers for uncreated nodes) and only pays a depth-limit pass (`HUF_setMaxHeight` Kraft repayment) when the unlimited tree exceeds 11 bits — where unlimited depth fits, both are optimal, and the repayment's excess over package-merge measures ≤0.1% on every non-adversarial histogram (~2% on a fibonacci-count adversary C pays identically; pinned by `build_lengths_matches_optimal_and_is_kraft_exact`, which keeps package-merge as a cfg(test) optimality reference and checks Kraft-exactness + ≤2% cost over alphabet sizes 2..=256 × descending/fibonacci/random shapes). `HuffScratch` shrinks with the algorithm: the seven package-merge stacks (~38 KB) become one 513-entry `NodeElt` table + a 192-slot rank-position array (~5 KB). Output moves only on fresh json/text tables (dump: +2..+92 B per file, ≤0.002%; random/zeros/skewed byte-identical), all 30 dump files roundtrip bit-exact through the C decoder; the 120-cell sweep stays +8.67% geo-mean with the same pre-existing losing cells (json.fast mt −0.14/−0.12%) and text.best holds its +0.13% lead. gungraun small: json-4K −12.1% Ir (x1.394→1.224 vs libzstd; the build self 26.7K→5.9K/call, 0.57× C's own), text-4K −20.3% (x1.484→1.182 — deeper text tables paid more package-merge), json/text-16K −3.9%/−7.5%, 64K −1.3%/−2.6%, random ±0.1%; the 1 MiB encode bench is flat-to-better everywhere (text fast −2.7%, fastest −1.7%). Wall interleaved A/B vs libzstd: json-4K x1.563→1.442, text-4K 1.716→1.419, json/text-16K 1.416→1.311 / 1.258→1.160, 64K 1.487→1.432 / 1.479→1.390. Lesson: **before attrition-ing a hot loop, diff the algorithm class against the reference implementation — a 2.5× instruction gap in intrinsic-per-block work was structural, not codegen.**
- **one-form materialization + pooled aligned table (2026-09-18)**: the weight→code pass materialized THREE parallel forms per live symbol (`codes: Vec<(u32,u8)>` + `packed` u16 + `aligned` u64) where C fills one CElt — and the struct literal zero-initialized `packed` + `aligned` inline (2.25 KB memset per build, 2.6K Ir — the largest single remaining build-side fixed cost), with the `codes` pool (take/fill/recycle) on top. `codes` is gone: every consumer reads the `nb` nibble straight from `packed` (`estimate_compressed_size`, `can_encode`, `write_weights_into`; the alphabet length moves to an `nsym` field, and entries past either alphabet count zero either way), the pool machinery and the per-build fill disappear with it. `aligned` moves behind a pooled `Box<[u64; 256]>`: dead symbols are never read (the stream encoder only indexes symbols the table covers), so boxes recycle without clearing and every byte stays initialized (clone-safe); only the 512 B `packed` still needs its zeroed dead prefix. The uniform-code detection folds into the bucket loop (one non-empty weight bucket ⇔ every live symbol shares a length) instead of two branches per symbol. `build_from_weights` is allocation-free now, and `HuffmanTable` shrinks ~2.6 KB inline to ~0.5 KB + box, so the per-block adopt/replace moves copy a fifth of the bytes. HuffmanTable-shaped memset residue: 4.1K → 1.6K Ir/call; `build_from_weights_slice` 4.4K → 1.9K. Combined with the FSE round above, gungraun small: json-4K x1.224→1.181 (−3.6% Ir), text-4K 1.182→1.148 (−2.8%), 16K −1.0/−0.9%, random-4K −1.6%; 1 MiB encode 60 benchmarks, 0 regressed. Wall (alternated base/new binaries, ruz medians — the drift-free column): json-4K 461→484 MiB/s (+4.6%), text-4K 376→390 (+3.7%), json-16K +2.7%; the wall converts at MORE than the Ir rate because the removed work was memory-bound (rep-stosb on never-read bytes, 2.6 KB struct moves) — the counterpart lesson to the FSE half: **Ir cuts in the small band only convert to wall where they also cut memory traffic**. Full-ladder dump byte-identical; 120-cell sweep +8.67% unchanged; `pooled_calls_byte_identical` and the rewritten packed-based tests (201) pass.
- **left-aligned dual-accumulator stream loop (2026-09-12, port of libzstd `HUF_CStream`)**: entries move to a parallel `[u64; 256]` form — code in the top `nb` bits, `nb` in the low nibble — so per symbol one load feeds `c >>= nb; c |= e; b += nb` (the OR of the raw element dirties the four low bits; every following `>>=` discards that dirt before it can reach the pending window, so only each round's last add needs a cleaned operand). The pending window grows downward from the container top; a flush shifts it into the low bytes with one unaligned store and leaves the container untouched. Rounds are 5 symbols per container with two containers alternating (merge = one shift+OR), giving two independent shift/OR chains; with codes ≤ 11 bits the dirt/capacity margins hold at 7 + 4×11 fast / +11 clean = 62 ≤ 64. A BMI2 runtime dispatch (the decode side's pattern) is load-bearing: on the baseline target the legacy `shr r, cl` costs one `mov`+`and` per symbol and short-code corpora regress (skewed.fastest +4.9% total Ir measured without it — recovered to +0.3% with shrx). Byte-identical output (full-ladder dump gate; the differential unit test covers 1..11-bit codes × entry alignments × uniform/non-uniform). callgrind dll32 fast: huff0 stream 88.8M → 50M Ir, at libzstd's own 45.7M — the 2x per-symbol gap closed (14.5→10.7 Ir/symbol on dll codes, ~7.2 on skewed's short codes), dll total −3.7%; gungraun encode: json fastest/fast −3.9%/−1.8%, text −2.6%/−1.1%, balanced json/text −1.1%/−0.4%, best/opt/ultra ≤0.15%, zeros/random +0.1-0.4% (the extra 2KB aligned-array init per table build). Wall within noise on the 32MiB shapes (the loop is a ~5%-of-cycles share there and latency-tolerant); the win is instruction-side and literal-volume-side (dll-shaped corpora, streaming small blocks).
- **whole-element stream discipline + a real BMI2 body (2026-09-20, dll100 differential round — see [enc-dll-gap](../bench/enc-dll-gap.md))**: the dual-accumulator loop still paid an nb extract (`mov`+`and $0xf`), a `shr %cl` and a separate count add per symbol — 11.1 Ir/literal on dll codes vs libzstd's 7.2 (their 1.5.7 `HUF_CElt` is one `size_t`: nb in the low byte, code left-aligned, and ONE element op serves as shift count (x86 masks to 6 bits = nb), OR payload and — the whole-element add into the bit counter, whose low byte stays exactly Σnb because carries only propagate upward). Our table already carries that layout (nb in the low nibble means bits 4..7 are zero), so the loop now runs the same discipline: `$c >>= e & 63; c |= e; b = b.wrapping_add(e)` — the counter's exact low bits are read as `& 0xff` (flush test/advance), `& 0x3f` (container shift; the round bound keeps the true value ≤ 62) and `& 7` (carried remainder). The BMI2 dispatch was ALSO broken in effect: `write_packed_codes_dual_bmi2` delegated to the non-feature impl, which LLVM compiled once as a tail jump — no shrx body existed; the impl is now `inline(always)` so the wrapper carries its own feature-compiled copy (a delegation is not a feature-compiled copy). ## Block splitting (opt+ rows)

- **libzstd's post-parse block splitter ported (2026-09-16, `blocks/split.rs`)**: one 128 KiB block's staged sequences are recursively bisected (libzstd's `ZSTD_deriveBlockSplits`); a split commits when the halves' estimated sizes beat the whole range's, and each committed range is emitted as its own block. The estimator runs the real table builds and the same selection the emission runs against the block-start entropy state (huffman desc via `write_table_desc`, FSE desc via `write_table` into a scratch buffer, stream costs via `estimate_compressed_size`/`repeat_bit_cost`), so estimates track emission rather than bounding it. `MIN_SEQUENCES_BLOCK_SPLITTING` 300, split cap 196, gate exactly `ZSTD_resolveBlockSplitterMode`'s auto rule (`Strategy::Opt` && window ≥ 2^17, post-shape-adjust — `Matcher::block_splitting_enabled`). Emission rolls the remembered tables across the cut: a later partition repeats the table the previous one wrote, so the treeless/repeat savings survive; the net per-stream outcome (New/Keep/Clear vs block start) feeds the caller's stock adoption. Speed tax: ~(2·splits+1)·3 estimates per block, each one huffman build + ≤3 FSE builds (measured below: 0.2-1.4% of the cells).

Correct by construction — no partition was emitted, so the decoder's repcode history never diverged — and unreachable in practice: every partition carries ≥150 sequences whose encoded form cannot lose to its raw bytes. ## Histogram and incompressibility detection

- **pre-match incompressibility gate (all strategies)**: a block that is near-certainly raw skips the match search entirely — one strided content-tag probe pass (slot = high 15 hash bits of a sampled 8-byte window, entry = low 32 bits, ~2000 samples per 128 KiB block; any hit keeps the matcher running, so duplicated-but-uniform-entropy data still parses) plus, only when the probe is clean, an exact 4-lane byte histogram gated at Miller-Madow-corrected ≥7.97 bits/byte. Ratio-safe by construction: the opt tree's fill is lazy from `next_update`, so a skipped block stays available as later match history (`update_tree` clamps its catch-up fill to the live window); the table strategies (fast/dfast/chain) track a `gap_start` watermark opened at the gated block's start, and the next scanning block's `catch_up_insertions` dense-fills `[gap_start, block_start)` (window-clamped, oldest-to-newest — exactly the state a full scan's miss-path inserts would have left) before its first probe. The watermark is written from the gate side only, so the three scan-loop bodies stay byte-identical to the ungated build — any growth there re-rolls the fast tiers' code layout (see negative.md: the placement lottery entry). Two sampled distinct micro-screens (reject at <32 distinct after 64 samples, <96 after 512; uniform bytes expect 57/221) keep never-gating corpora out of the full pass: 16-letter skewed and json exit at 64 samples, text-like ~76-symbol alphabets at 512, so the gate costs ~0.1-0.5% instructions on compressible shapes. The entropy decision must be exact, not sampled: a 2016-sample Miller-Madow estimate of max-entropy input has std ≈ 0.11 bits (the correction fixes the mean, not the spread — see negative.md), so the 7.97 bar would coin-flip per block; a wrongly kept block forces a full scan plus catch-up fill, hundreds of times the histogram cost. random.best 12→1574 MiB/s (libzstd-12: 615), random.opt 1573 vs 14 (112×), random.ultra 1542 vs 6 (257×); extending to the table levels: random.fast 1469→1678 (x1.39→1.25 vs libzstd-3), random.balanced 1405→1688 (x1.29→1.09 vs libzstd-6), random.fastest 1652→1681 (x1.33→1.32); full-corpus full-ladder dump byte-identical, 120-cell ratio sweep flat. 2026-09-12, sticky `gate_hold` (same precedent as the literals gate's): once a block clears the exact pass, subsequent blocks gate on the probe alone until any rejection clears the hold — the histogram runs once per incompressible run instead of once per block (it sits at the x86 mem-op floor: 3 mem-ops/byte — byte load + RMW load+store — at 3 mem-ops/cycle, ~1.04 cyc/B measured via perf-annotate, so the pass could only be skipped, never cheapened; u64-load extract feeds would be undone by load-narrowing, unrolling drops only non-bound ALU). ## Small-payload ratio (1-128 KiB)

- **The gap and its attribution (2026-09-21, R8)**: the CLI-vs-CLI recon (zstdx `-l -c` vs zstd 1.5.7 `-q -l -c`, corpus slices at off 0/1M/16M) measured text at +7.5..+13.7% output (+68..+137 permille) at BOTH level 1 and 9 over 1-64 KiB, json 4K +4% at l1; 16K-64K shrank and json l3/l9 already won. Frame-parser section diffs (rebuilt tooling: FHD/block/literals/sequence decode, `FSE_readNCount` emulation) ranked the mechanisms: **(1) frame overhead, +4 B on every frame** — a trailing empty raw block on grid-exact inputs (the streaming reader cannot mark a just-filled block last until a read returns EOF; the slice path mirrored it for byte-identity) and a window descriptor where libzstd writes the single-segment form (+1 B) — 13 permille of a 300 B frame; **(2) cParams row selection** — libzstd switches `ZSTD_defaultCParameters` tables at srcSize ≤ 256/128/16 KiB (searchLength 4 through the whole lazy family, its ≤ 16 KiB table swaps l9/l10 lazy2→btlazy2, searchLog 5), our rows never keyed on size; **(3) parser shape at l1** — the stock fast-row bars are large-input tunings (miss ramp `1 + miss>>2` vs libzstd's near-unstepped small-row scan, `ml >= 6` accept bar); **(4) literal Huffman descriptions, +6..+10 B** — we always built at tableLog 11 where libzstd caps by `highbit(srcSize-1)-1`. The entropy-side suspects were quantified OUT of the lead (sequence sections at parity, checksum parity — both CLIs default it on — and the reject-floor margins moved ≤ 10 B): the gap was frame shape + row policy + parse bars, with entropy a tail.
- **Frame-shape closure**: the slice path marks its final real block last (no empty tail block); the streaming core tracks the newest block header's output offset ([`BlockTail`]) and patches the last-block flag in place at `finish` when the buffer still holds it, while a pledge that exactly fills the grid closes at `write` time (3 B shorter, one-shot-shaped whatever the consumer drained); a pledged size the window already covers takes the single-segment header (libzstd's `windowSize >= pledgedSrcSize` form). The unshaped-streaming contract changed accordingly: grid-exact lengths now differ from the slice path by the documented 3-byte closing block (decode-equality + shape tests; `compress_to_vec` is genuinely streaming and cannot know EOF early). Effect: −4 B/frame everywhere (zeros 32 MiB −3 B, text opt/ultra −0.012..−0.021%); 120-cell sweep 11 cells moved, every one smaller, geo-mean +8.67→+8.69%.
- **Literal Huffman tableLog cap (port of `HUF_optimalTableLog`'s cheap path)**: `optimal_literal_log` — `min(11, highbit(total-1)-1)` raised to `min(highbit(total)+1, highbit(max_symbol)+2)`, clamped 5..=11 — replaces the fixed 11 in `build_from_counts_into`. Small frames build shallower trees with smaller weight descriptions (json 4K l1: desc 34→26 B; text 1K l19: 45→32 B). Large blocks keep 11 by construction (128 KiB literals saturate the cap).
- **The small-src policy band and the alphabet screen live with the matchers** ([matchers](matchers.md)); the screen's cost contract is an encoding-side lesson: one extra O(n) pass over the window is 20-50% of a fastest-tier small call (the first full-window distinct scan measured skewed-16K fastest at −47%), so the screen samples (≤ 640 strided reads, register-resident bitmap — a `[u64;4]` indexed by `b>>6` compiles to a store-forwarding chain at ~2.8 cycles/sample) and caches its verdict keyed by window identity for pooled repeat calls.
