# Performance Optimization · Encoding (excl. matchers)

> Matcher and level strategy: see [Matchers and Compression Levels](matchers.md); multithreading and streaming pipeline: see [Multithreading and Streaming](mt-stream.md).

## Entry and state management

- **zero-copy slice entry** `compress_slice_to_vec`: the match window directly borrows the input (raw-pointer window + unsafe Send), eliminating the read pass, window compaction, and per-call window allocation; output upfront-reserved, blocks written straight into the final output. text +40%, zeros +60%. `51b019e`
- **thread_local state pool** (hash tables/default FSE tables/BlockScratch, take()-style reuse across calls, nesting-safe): 1KiB payloads 3-7×, 4KiB +30-80%. `cb02c32`
- **emit path rework**: entropy tables take/restore by value instead of deep-cloning 3×FSETable+Huffman per block (the original several hundred allocs per block was the biggest black hole, ~30%); `start_matching_into` buffer direct-write replaced the callback closure (the closure captured 2×Vec + matcher state → register spills, one store sampled at 40%); matcher window reads unchecked. Itemized +2%/+2%/+11%, cumulative json +24%, text +39%. `68ae651` Lesson: **unchecked-read gains (+11%) far outweigh structural rework (+2%×2); bounds checks on byte-wise paths are the prime target**.
- block contents written in place into the frame output (reserve the 3-byte block header first, backfill after compression) + literals/sequence/precomputed-code buffers moved into the BlockScratch pool: random -6.8% instructions. `95b2006`
- zero-sequence blocks skip literal staging (matcher skips the whole-block copy, encoder reads the window directly): random 64K-1M +13%. `15d127d`
- **entropy-build scratch pooling (2026-09-16)**: the per-block FSE/huffman table builds allocated and zeroed their buffers on every build — on a json-4K fastest call that was ~15% of Ir in memsets alone (the `vec![0u32; probs.len()*table_size]` transition tables ×3, package-merge level lists, huffman `codes`, wire weights) plus the malloc/free churn (~3%). `FSETable`/`HuffmanTable` now return their transition/codes buffers to pools held in `BlockScratch` (`FseBuildScratch`/`HuffScratch`), and the builds write into recycled buffers: a buffer's `len` is its initialized prefix, so growth (the only zeroing left) happens once per size, not once per table — live rows are fully overwritten by the build walk and dead rows stay stale-but-unread (wire codes never exceed the histogram's `max_symbol`; `bulk::tests::pooled_calls_byte_identical` pins the repeated-call outputs). Recycling sites: table adoption in `compress_fastest`, the raw-block fallback, `reset_slice_state`, and the huffman weight-table temp inside `write_table_with`. Measured on the new gungraun small-payload bench (`zstdx-gungraun/benches/small.rs`, deterministic per-call Ir): json-4K −13.6% Ir, text-4K −11.1%, json/text-16K −7..8%, −7% at 64K. Wall (interleaved A/B): json-4K x1.96→1.83, text-4K x1.91→1.87 (abs +8%), json/text 8K/16K −4..6%, skewed-4K x0.90→0.80, json/text-1K x2.30/2.48→1.95/2.17; 64K-1M and the 32MiB matrix stay flat (json) to ahead (text fastest/fast +11-20%: per-block builds amortize there too). Byte-identical output: 5 shapes × levels 1/3/9/16/19 emit-diffed against the pre-change build. Residue for the next cut: the build walks themselves (libzstd computes FSE transitions arithmetically from per-symbol `deltaNbBits`/`deltaFindState` instead of materializing a (max_symbol+1)×table_size entry table), the 3×256 row-pointer setup per block in `encode_sequences`, and the 12 KB lane-zeroing in `choose_tables_fast`.

## FSE

- SoA flattened tables (probs/start/transitions in contiguous memory) replace 256×Vec + double sorting. `81afece`
- per-symbol spread precomputation; flat transition table `(next<<13)|(nb<<9)|baseline` O(1) state transitions + LL/ML code LUT: json 189→245 MB/s. `5619e80`
- 6 write_bits per sequence merged into 2 u64 spellings (transition bits ≤27bit, add-bits ≤51bit, one each): another +4%. `bbde2ea`
- transition bits and add-bits merged into one hot_push (combined ≤56bit safe cap, falls back to double push beyond it). json -0.4% instructions. `2d18813`
- **encode_sequences upfront reserve + raw pointers**: one reserve of `nb_seq*11 + 32` bytes (≤51 add bits on the last sequence, ≤87 per earlier one, plus the 8-byte flush-store overshoot) replaces the per-push capacity probe (a Vec field load + branch per sequence); the seqs stream and the three FSE transition-row tables move to raw pointers — the slice/Vec fields rode the stack through every iteration and were the function's hottest single instructions. Byte-identical output; gungraun json.fastest a further -1.3% (cumulative -4.0% with the emit split), json.fast -0.9%.
- **encode_sequences per-code row-pointer tables**: the loop-invariant half of each row address (`rows + (code << shift)`) is resolved once per block into 256-entry tables of raw pointers; the hot loop reaches a transition entry with one rsp-addressed stack load plus one indexed load through it. The first generation stored u32 row offsets and OR'd the state in, but that kept a third live base register per channel — registers the loop does not have, so all three row bases reloaded from the stack every sequence. Byte-identical output (full-ladder dump gate); gungraun fastest/fast −0.7..−0.8% Ir on json/text, balanced −0.15..−0.19%, skewed.fast −0.18% (skewed's low tiers stay on RLE one-state tables and miss the path). A SeqWord 24→16 B shrink trading the separate `add_nb` load for a packed width byte was falsified: the packing ALU lands in the hotter matcher emit (see negative.md).
- **precomputed transition diffs in FSE entries**: a flat row is indexed by the state itself, so the emitted value `state - baseline` is a build-time constant per row position — entries now pack `(next << 16) | (nb << 12) | diff` with the run offset written at build time, and every consumer (encode_sequences, `FSEEncoder::encode`/`encode_interleaved`) reads the diff straight from the entry. Kills one sub plus its feeding mov per channel per sequence, and the three end-of-loop state copies disappear (entries land in registers that update in place via `shr 16`). Byte-identical output (full-ladder dump gate); gungraun json fastest/fast −1.3%/−1.5% Ir, text −0.9%/−1.2%, skewed.fast −0.3%.
- **table mode selection** (port of the libzstd `selectEncodingType` fast branch): RLE single-code / Predefined threshold / Encoded + normalizeCount M2 normalization + optimalTableLog + last-sequence count decrement. json ratio 5.22→5.37. `1a17db3`
- **repeat mode (mode 3)**: when the previous block's table covers all active codes and the bit-cost estimate (Σ c·log2) ≤ new-table description + entropy lower bound, the whole table is reused with zero description bytes; a Predefined/RLE choice invalidates the remembered table (`PrevTable::{New,Keep,Clear}` three states guard against table-state desync with the decoder). json -2.2% instructions, ratio 5.99→6.00. `7769bf8`
- RLE degenerate single-state FSE table: table_size=1 takes exactly the same path as normal modes, zero special-case branches.
- **fastest-tier mispredict differential study (2026-09-14, LBR `perf record -j any` + `/M` flag on AMD)** — per-branch attribution of json.fastest's ~3.1M misses/pass (~17% of cycles): the single largest mispredicted branch is encode_sequences' bit-writer headroom check `nb+bits ≤ 63` (~18% of misses; the next target, and the branchy counterpart of the already-landed writer work above), then the scan_fast rep OR-fold — which the short-circuit `a == 0 || b == 0` had compiled into *three* unpredictable branches (a-cmp, b-cmp, combine, ~19%), extend_match's u64-compare loop exits (~9%), the two hash-match compares (~9%), and insert_covered's mod-2 unroll parity guard (~4%). Fix with the study: the fold as `(a == 0) | (b == 0)` — one branch, `a`-disambiguation on the taken path. Byte-identical on the full-ladder dump; branch-misses −1%, wall neutral (json −0.5%±noise) — the mispredict inventory shrank, making encode_sequences' headroom branch the clean next cut.
- **unconditional bit-writer flush (`hot_push_raw`, 2026-09-14)**: the headroom branch `bits + nb >= 64` — the study's largest single mispredict (~18% of json.fastest misses) — is gone by adopting libzstd's BIT_flushBits discipline: every push flushes its whole pending bytes (`k = bits/8 ≤ 7`, one unaligned u64 store, `acc >>= 8k`) before OR-ing the payload, so `bits < 8` on every entry and any nb ≤ 56 still fits the accumulator. Traded +0.4-0.6% Ir (the extra stores fire even when the old branch fell through) for the branch elimination: wall json.fastest 541→562 MiB/s (+4%), json.fast 425→447 (+5%), skewed.fastest 2758→2873 (+4%), text +1%, skewed.fast flat; full-ladder dump byte-identical. Lesson: **a ~18%-of-misses branch is worth ~5× its instruction-count price in stores**; the reverse trade (store folding to save <1% Ir — see negative.md's write_bits_64_cold row) never pays.
- **insert_covered peel-then-pairs** (with the study above): the `while p < end` insert loop auto-unrolled mod 2 behind a per-entry parity guard (~4% of json.fastest mispredicts); peeling the odd tail once and inserting in explicit pairs keeps the unroll without the guard. Byte-identical on the full-ladder dump; gungraun Ir json +0.05%/text flat vs the guard form (the two alternatives that *lost*: plain counted `for k in 0..count` stays rolled, +3.3% Ir; a hand-unrolled counted loop with per-iteration `start + k` addressing, +4.3% — see negative.md). Wall neutral.
- **encode_sequences output cursor** (2026-09-16): the per-sequence loop kept `pos` as a byte offset and reloaded the output base pointer from its stack slot every iteration (register pressure — sixteen live values) just to form the flush store's address, and spilled the loop counter on top. The loop now carries ONE output cursor pointer (advanced by each flush's byte count; the exit position is derived once at the end) and terminates on the SeqWord pointer instead of the counter. Byte-identical (full-ladder dump); gungraun fastest/fast json −0.35%/−0.42% Ir, fast text −0.39%; wall neutral on interleaved A/B (x-bands overlap every round — the loop is latency-bound: the two-level row-pointer loads and the serial accumulator chain set its floor, the cut is uop-side). The concat's variable shifts are at their floor for this entry form: `nb` is per-entry, not per-row (a symbol's double-states split nb/nb+1 — `fse_encoder.rs`'s baseline walk), so the per-code row-pointer tables cannot carry the widths to shorten the post-entry extraction chain.

## Huffman

- **boundary package-merge optimal length-limited codes** (Larmore-Hirschberg) replacing the initial rank-weight ladder (the old scheme depended on count order, not magnitude — large losses on skewed histograms): all levels benefit, json Ultra 7.33→7.52, text fastest 196.6→206.0. `aa07308`
- `build_from_weights` counting sort: package-merge caps weights at 11, so 12 stack buckets with symbols scattered in ascending order reproduce the comparison sort's weight-ascending/symbol-ascending order exactly (byte-identical output, gate: full-ladder dump); removes the per-block heap Vec and the O(n log n) sort. text-4K small-payload encode +5% wall-clock, gungraun instruction counts drop on every text-shaped cell, no regressions elsewhere.
- `package_merge_lengths` scratch rework: only the previous level list is ever read, so two swapped buffers replace the `Vec<Vec<Ent>>` (was two allocations per level, 11 levels per table); `Ent` weight u64→u32 (12→8 bytes, block literals are capped far below 2^32 so package sums cannot overflow). Byte-identical output; gungraun text fastest -0.7%, text fast -1.2%, skewed fastest -0.5%; cumulative text-4K +8%.
- per-level package sort removal: packages are disjoint adjacent-pair sums of the (weight, node)-sorted previous level, so pkg[k+1] ≥ pkg[k] follows from w[2k+2] ≥ w[2k] and w[2k+3] ≥ w[2k+1], and ties break by strictly increasing arena id — the list is provably already in the sorted order, making the sort a no-op (verified by a 2M-random-vector brute force with a sortedness debug-assert + full-ladder dump byte-identical). The merge levels are now pure O(n) merges; gungraun text fastest/fast −0.34% instructions, skewed fastest −0.19%, text-4K +3% wall-clock.
- scalar 4-symbol batch accumulation: packed u16 `(code<<4)|nb` code table; flush to <8bit first, then branchlessly accumulate 4 symbols into a u64; a single unaligned store flushes whole bytes. skewed +71%, json +4%. **Superseded (2026-09-12)** by the dual-accumulator loop below for the generic path.
- **left-aligned dual-accumulator stream loop (2026-09-12, port of libzstd `HUF_CStream`)**: entries move to a parallel `[u64; 256]` form — code in the top `nb` bits, `nb` in the low nibble — so per symbol one load feeds `c >>= nb; c |= e; b += nb` (the OR of the raw element dirties the four low bits; every following `>>=` discards that dirt before it can reach the pending window, so only each round's last add needs a cleaned operand). The pending window grows downward from the container top; a flush shifts it into the low bytes with one unaligned store and leaves the container untouched. Rounds are 5 symbols per container with two containers alternating (merge = one shift+OR), giving two independent shift/OR chains; with codes ≤ 11 bits the dirt/capacity margins hold at 7 + 4×11 fast / +11 clean = 62 ≤ 64. A BMI2 runtime dispatch (the decode side's pattern) is load-bearing: on the baseline target the legacy `shr r, cl` costs one `mov`+`and` per symbol and short-code corpora regress (skewed.fastest +4.9% total Ir measured without it — recovered to +0.3% with shrx). Byte-identical output (full-ladder dump gate; the differential unit test covers 1..11-bit codes × entry alignments × uniform/non-uniform). callgrind dll32 fast: huff0 stream 88.8M → 50M Ir, at libzstd's own 45.7M — the 2x per-symbol gap closed (14.5→10.7 Ir/symbol on dll codes, ~7.2 on skewed's short codes), dll total −3.7%; gungraun encode: json fastest/fast −3.9%/−1.8%, text −2.6%/−1.1%, balanced json/text −1.1%/−0.4%, best/opt/ultra ≤0.15%, zeros/random +0.1-0.4% (the extra 2KB aligned-array init per table build). Wall within noise on the 32MiB shapes (the loop is a ~5%-of-cycles share there and latency-tolerant); the win is instruction-side and literal-volume-side (dll-shaped corpora, streaming small blocks).
- **AVX-512VBMI 4-bit code packing kernel** (uniform 9..16-symbol alphabets): 64 symbols/batch, `permutex2var_epi8`×2 indexing a 256-entry LUT + two permutes to un-interleave paired nibbles. skewed instructions -48%, throughput +43%. `2be2207`
- RLE literals mode (all literals the same byte → type1 header + 1 content byte). Gotcha: in the 5-bit size format, size_format occupies only 1 bit (see the pitfalls notes).

## Histogram and incompressibility detection

- **pre-match incompressibility gate (all strategies)**: a block that is near-certainly raw skips the match search entirely — one strided content-tag probe pass (slot = high 15 hash bits of a sampled 8-byte window, entry = low 32 bits, ~2000 samples per 128 KiB block; any hit keeps the matcher running, so duplicated-but-uniform-entropy data still parses) plus, only when the probe is clean, an exact 4-lane byte histogram gated at Miller-Madow-corrected ≥7.97 bits/byte. Ratio-safe by construction: the opt tree's fill is lazy from `next_update`, so a skipped block stays available as later match history (`update_tree` clamps its catch-up fill to the live window); the table strategies (fast/dfast/chain) track a `gap_start` watermark opened at the gated block's start, and the next scanning block's `catch_up_insertions` dense-fills `[gap_start, block_start)` (window-clamped, oldest-to-newest — exactly the state a full scan's miss-path inserts would have left) before its first probe. The watermark is written from the gate side only, so the three scan-loop bodies stay byte-identical to the ungated build — any growth there re-rolls the fast tiers' code layout (see negative.md: the placement lottery entry). Two sampled distinct micro-screens (reject at <32 distinct after 64 samples, <96 after 512; uniform bytes expect 57/221) keep never-gating corpora out of the full pass: 16-letter skewed and json exit at 64 samples, text-like ~76-symbol alphabets at 512, so the gate costs ~0.1-0.5% instructions on compressible shapes. The entropy decision must be exact, not sampled: a 2016-sample Miller-Madow estimate of max-entropy input has std ≈ 0.11 bits (the correction fixes the mean, not the spread — see negative.md), so the 7.97 bar would coin-flip per block; a wrongly kept block forces a full scan plus catch-up fill, hundreds of times the histogram cost. random.best 12→1574 MiB/s (libzstd-12: 615), random.opt 1573 vs 14 (112×), random.ultra 1542 vs 6 (257×); extending to the table levels: random.fast 1469→1678 (x1.39→1.25 vs libzstd-3), random.balanced 1405→1688 (x1.29→1.09 vs libzstd-6), random.fastest 1652→1681 (x1.33→1.32); full-corpus full-ladder dump byte-identical, 120-cell ratio sweep flat. 2026-09-12, sticky `gate_hold` (same precedent as the literals gate's): once a block clears the exact pass, subsequent blocks gate on the probe alone until any rejection clears the hold — the histogram runs once per incompressible run instead of once per block (it sits at the x86 mem-op floor: 3 mem-ops/byte — byte load + RMW load+store — at 3 mem-ops/cycle, ~1.04 cyc/B measured via perf-annotate, so the pass could only be skipped, never cheapened; u64-load extract feeds would be undone by load-narrowing, unrolling drops only non-bound ALU). Risk model: a mis-held block needs ≥208 distinct sampled bytes + zero repeated 8-grams in the strided probe + exact entropy < 7.97 directly after a gated block, and what is lost is only the literals huffman saving — which at ≥208 distinct symbols cannot beat integer code lengths plus the table description. Measured byte-identical on the full-ladder dump, on a random→text transition file (L1), and even on a crafted flat-232-symbol adversary (16MiB random prefill to arm the hold) at L1 and L19 — the old path's own raw-fallback economics already emitted those blocks raw. random tiers 1.68→2.4-2.5 GB/s, ahead of libzstd at all six levels (fastest 2464 vs 2157, fast 2569 vs 2044, balanced 2505 vs 1525, best 2452 vs 218, opt 2427 vs 9, ultra 2253 vs 7); solo prof enc1 instructions −61% (4.58G→1.79G), the gate symbol gone from the profile (was 37.9% of cycles); 120-cell ratio sweep flat.
- literals histogram **4-way sub-tables** (split by position mod 4, avoiding store-forwarding serialization on the same counters): skewed cycles -7%, throughput +10%.
- ≤16 alphabet **AVX-512 exact histogram**: 16-slot `cmpeq_epi8_mask` + popcount accumulation; the popcount sum doubles as 17th-symbol detection (scalar fallback only when uncontaminated). skewed instructions -18%, +28%. `e76bb60`
- **Miller-Madow entropy sampling rejection gate**: strided sampling (~1024 points) + Miller-Madow bias correction + distinct>208 pre-screen + sticky `gate_hold`; rejects only at ≥8 bits/byte. random instructions -43%, +43% (1450→2060, overtaking libzstd L1). `cdc70c0`
- literals entropy lower-bound pre-check (exact histogram + Shannon bound + 8% margin; skip the Huffman attempt when it cannot beat raw; histogram and table build share one scan): random 455→1178 (+159%). `a32d2c1`
- three-table histogram fused into a single pass (one traversal of packed codes updates the ll/ml/of counters). `6690a05`
- fused pass lane-split: 4 sub-histograms per channel (12×1KB) break store-forward serialization on repeated-code runs; gated at nb_seq ≥ 128 (12KB zero/merge doesn't pay off on tiny blocks). choose_tables_fast cycles 2.83%→2.00% on json.fast; gungraun -0.07%.
- **sequence-code histograms sized to the 64-entry code space** (`SEQ_CODE_SPACE`; wire codes: LL ≤ 35, ML ≤ 52, OF ≤ 31): the merged histograms, mode-selection max-scan and normalization scratch cover 64 entries instead of 256, and the small-block direct path masks codes with 0x3f so the u8 index stays provably in range. The lane arrays must stay 256-wide: with 64-wide lanes the per-sequence increments lose their provably-in-range u8 index and grow three compare-and-panic pairs per sequence (+0.3% instructions, first attempt). Byte-identical output (full-ladder dump gate); gungraun json fastest/fast −0.4%/−0.5%, text −0.4%/−0.5%.
- log2 under no_std uses a linear-mantissa approximation (error <0.086, swallowed by the 8% margin). `9121215`

## Checksum (xxh64)

- **in-house 8-chain XXH64**: 2×32B per iteration, 8 accumulation chains in flight (4 chains +8%); shared with the decoder, twox-hash demoted to dev-dep, zero external runtime dependencies. `3c0bf97` `81d2119` Note: the AVX-512 vpmullq vector core was a negative result (serial dependency chain); 8 interleaved scalar chains is the right answer.
- **pass fusion**: the RLE uniformity scan runs XXH64 rounds while comparing (uniform-block hashing completed inside the single pass; on mismatch it returns a 32B-aligned resume offset to continue); raw-block copies absorb while copying; the zero-sequence-block gate rejects with early exit. zeros +22%, random +10%. `3c0bf97`
- **sidecar thread offload** (std+hash, input ≥256KiB, ≥2 cores): a thread_local SPSC ring (512 slots) posts block bytes, consumed by a dedicated worker; the `BlockChecksum` trait unifies inline/offload. random +13%, text +26%, skewed +14%, zeros +2%, json +4%. `df33295`
- worker **bounded-spin parking**: parks on a condvar after a ~300µs budget (80µs was not enough — the raw-block pipeline paces at worker saturation, so wakeup latency lands directly on the critical path); the head flip is published under the lock to prevent lost wakeups. Saturated runs see ~1 voluntary switch per frame, 0 ticks while idle. `70b5fd4`
- on the MT path the checksum is absorbed in parallel, inline in the calling thread; during streaming bursts the main thread hashes.

## Bit writing and miscellaneous

- BitWriter 64-bit flush uses a single unaligned u64 store instead of an 8-byte memcpy: all corpora +1-2%.
- sequence codes computed once and shared (choose_table and encode_sequences consume the same set of code arrays, META table lookup split from add-bits): identical output bits, cleaner code. `b0c2653`
- sequence code/add-bits single-pass precomputation (codes packed into a u32 stream, add-bits pre-merged into u64): json +3%. `d9a840b`
- the matcher pushes the packed sequence stream directly (`Matcher::start_matching_codes`, json -3.5% instructions) — see the matchers page for details. `6faba75`
- RLE detection chunked by u64 (the original closure's byte-wise indexing could not be vectorized); RLE blocks' skip_matching inserts only the first position (all 5-byte windows of a uniform run land in the same slot): zeros 7.3×. `6abb9ae` `d9f078a`
- after match emission, short-literal overrun-overwrite copy (≤8B literal run: `reserve(8)` + unaligned read/write + set_len; the read runs into the following match, write overflow ≤7B is overwritten by subsequent pushes).
- uniform block detection: 4×u64 batched compares + deliberate `#[inline(never)]` (inlining into large callers made the loop lose its data pointer and reload it from the stack every 32B, halving throughput — counterintuitive but measured).
