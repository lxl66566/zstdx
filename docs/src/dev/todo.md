## P1 · Encoding speed

4. **Fastest — json x1.52 vs libzstd-1** (2026-09-14; was 1.57 — the unconditional bit-writer flush removed the largest mispredict, json.fastest 541→562). The steady scan loop is branch/latency-bound, not instruction-bound: IPC ≈ 3, ~14 cyc/iter vs a ~4-5 cyc port floor, ~4 cyc/iter of it branch-mispredict cost (~8 branches/pair vs libzstd's ~5). **The differential loop study is done (2026-09-14, LBR per-branch attribution — see [perf/encoding](perf/encoding.md))**: the extra-branch inventory is named and now largely collected — the writer headroom branch (largest, ~18%) fell to the unconditional flush, the rep OR-fold's short-circuit compiled to 3 branches (fixed, one branch now), insert_covered's parity guard fixed by peel-then-pairs; extend_match loop exits and the two hash-match compares are inherent (libzstd pays the same class). Remaining mispredict budget is spread across the inherent set — no single lever left. Deeper hash pipelining for miss runs is blocked on register headroom, no identified source. json.fastest.mt8's gap is this same per-core deficit scaled through workers — it closes with the ST loop, not with MT scheduling. Angles not yet tried (all distinct from the falsified mechanisms in [negative.md](negative.md)):
   - **miss-run stepping** (advance 2 positions after N consecutive misses): the falsified step-2 was *in-match* insertion (rejected on ratio) and lazySkipping was the *chain* tier — a miss-only skip changes the parse differently and gets its own ratio-gated A/B;
   - **search-side batched probing** (AVX-512 hash/probe 2-4 positions, branchless candidate select): the falsified AVX-512 work was *insertion*-side (random-store floor); probing-side attacks the branch stream, which is the measured bound.
5. **Fast — json x1.09** (was 1.11; the unconditional bit-writer flush moved it, 425→447). The per-sequence encode path is near-tight. Remaining: the concat's variable shifts + the writer's shift/OR tail (~10.7% of json.fast cycles before the flush), the three-channel SIMD histogram in choose_tables_fast (2.2% of cycles — caps the win low), and the dfast matcher itself (still the dominant share of json.fast cycles). 6. **Balanced — json x1.34 vs zstd-9** (2026-09-14; was 1.40 after the pipelined head reads; interleaved) while carrying +19.5% density (7.11 vs 5.95), so the fair comparison is zstd-8/9 territory.
