## P1 · Decoding speed

2. **Streaming decode core residue — x1.27-1.35 json, x1.10-1.32 skewed, x1.04-1.21 text** (2026-09-14 pass). The streaming column is the honest core comparison (zstd's bulk API is a slow wrapper; our own stream-vs-bulk overhead is ≤2%), so this is the fused sequence loop vs libzstd's pipeline, not a wrapper cost. The loop is proven **throughput-bound, not latency-bound** (IPC 3.45, flat cycle profile, prefetch-negative — attribution in [decoding](perf/decoding.md)): the 8-deep ring-buffer pipeline was built in two variants and lost on every shape, so the overlap it would add already exists for free via OOO and the structural class is closed ([negative.md](negative.md)). SIMD copy scheduling is the one unassessed structural idea.

## P1 · Encoding speed

3. **Fastest — json x1.52 vs libzstd-1** (2026-09-14; was 1.57 — the unconditional bit-writer flush removed the largest mispredict, json.fastest 541→562). The steady scan loop is branch/latency-bound, not instruction-bound: IPC ≈ 3, ~14 cyc/iter vs a ~4-5 cyc port floor, ~4 cyc/iter of it branch-mispredict cost (~8 branches/pair vs libzstd's ~5). **The differential loop study is done (2026-09-14, LBR per-branch attribution — see [perf/encoding](perf/encoding.md))**: the extra-branch inventory is named and now largely collected — the writer headroom branch (largest, ~18%) fell to the unconditional flush, the rep OR-fold's short-circuit compiled to 3 branches (fixed, one branch now), insert_covered's parity guard fixed by peel-then-pairs; extend_match loop exits and the two hash-match compares are inherent (libzstd pays the same class). Remaining mispredict budget is spread across the inherent set — no single lever left. Deeper hash pipelining for miss runs is blocked on register headroom, no identified source. json.fastest.mt8's gap is this same per-core deficit scaled through workers — it closes with the ST loop, not with MT scheduling. Angles not yet tried (all distinct from the falsified mechanisms in [negative.md](negative.md)):
   - **miss-run stepping** (advance 2 positions after N consecutive misses): the falsified step-2 was *in-match* insertion (rejected on ratio) and lazySkipping was the *chain* tier — a miss-only skip changes the parse differently and gets its own ratio-gated A/B;
   - **search-side batched probing** (AVX-512 hash/probe 2-4 positions, branchless candidate select): the falsified AVX-512 work was *insertion*-side (random-store floor); probing-side attacks the branch stream, which is the measured bound.
4. **Fast — json x1.09** (was 1.11; the unconditional bit-writer flush moved it, 425→447). The per-sequence encode path is near-tight. Remaining: the concat's variable shifts + the writer's shift/OR tail (~10.7% of json.fast cycles before the flush), the three-channel SIMD histogram in choose_tables_fast (2.2% of cycles — caps the win low), and the dfast matcher itself (still the dominant share of json.fast cycles). Position-u64 carry and seqStore-cursor emit are falsified ([negative.md](negative.md)).
5. **Balanced — json x1.34 vs zstd-9** (2026-09-14; was 1.40 after the pipelined head reads; interleaved) while carrying +19.5% density (7.11 vs 5.95), so the fair comparison is zstd-8/9 territory. What remains latency-side is only the chain-link chase itself (irreducible within this design: each link's address depends on the previous link's value, software prefetch cannot chase pointer chains) and the scan walk's own exposed head read (no +1 carry exists — the miss path and emits move pos unpredictably). Table sizing is ratio-locked (C20 minimal-exact for W21), the second-chance search is ratio-load-bearing. **The walk's own premise is changeable via LDM (item 11)**: if gear-hash candidates cover the 1-2MiB tile repeats, the chain window can shrink back below W21 — shorter, cache-warmer walks and the W21 json solo cost (−14%) recovered while keeping the reach; the falsified window shrinks (256K/384K catastrophic) were tested *without* an LDM candidate source.
