## P1 · Decoding speed

2. **Streaming decode core residue — x1.27-1.35 json, x1.10-1.32 skewed, x1.04-1.21 text** (2026-09-14 pass). The streaming column is the honest core comparison (zstd's bulk API is a slow wrapper; our own stream-vs-bulk overhead is ≤2%), so this is the fused sequence loop vs libzstd's pipeline, not a wrapper cost. The loop is proven **throughput-bound, not latency-bound** (IPC 3.45, flat cycle profile, prefetch-negative — attribution in [decoding](perf/decoding.md)): the 8-deep ring-buffer pipeline was built in two variants and lost on every shape, so the overlap it would add already exists for free via OOO and the structural class is closed ([negative.md](negative.md)). What remains is instruction-count attrition vs libzstd's hand-tuned loop (entry unpacking 6+ uops/sequence, shlx/shrx chains, ~20 live values with residual spilling) — uop-by-uop cuts convert ~1:1 into wall on a throughput-bound loop, but the easy ones are taken. **SIMD copy scheduling is assessed and falsified (2026-09-15, [negative](negative.md))**: libzstd's wildcopy issue structure on the existing kernels shrinks the exec half as designed (−0.5-0.6M Ir json) but the fused loop is one register-allocation domain — the saturated budget returns the saving as decode-half spills on every shape, and even removing the statically dead `ml > 0` branch nets +0.3-0.4% Ir. No structural lever is left; only decode-half uop attrition (entry unpacking, shlx/shrx chains) whose every source change re-rolls the whole loop's allocation (±600-800K Ir on json), which makes each further cut a lottery against a ~10 Ir/seq spill set.

## P1 · Encoding speed

3. **Fastest — json x1.52 vs libzstd-1** (2026-09-14; was 1.57 — the unconditional bit-writer flush removed the largest mispredict, json.fastest 541→562). The steady scan loop is branch/latency-bound, not instruction-bound: IPC ≈ 3, ~14 cyc/iter vs a ~4-5 cyc port floor, ~4 cyc/iter of it branch-mispredict cost (~8 branches/pair vs libzstd's ~5). **The differential loop study is done (2026-09-14, LBR per-branch attribution — see [perf/encoding](perf/encoding.md))**: the extra-branch inventory is named and now largely collected — the writer headroom branch (largest, ~18%) fell to the unconditional flush, the rep OR-fold's short-circuit compiled to 3 branches (fixed, one branch now), insert_covered's parity guard fixed by peel-then-pairs; extend_match loop exits and the two hash-match compares are inherent (libzstd pays the same class). Remaining mispredict budget is spread across the inherent set — no single lever left. Deeper hash pipelining for miss runs is blocked on register headroom, no identified source. json.fastest.mt8's gap is this same per-core deficit scaled through workers — it closes with the ST loop, not with MT scheduling. Both todo angles are now tried and falsified (2026-09-15, ratio-gated interleaved A/Bs — see [negative.md](negative.md)): **miss-run stepping** wins json both ways (−3.2% size, 567→617 MiB/s) but regresses text +2.3..+7.4% at every threshold and under parse-statistic gating (span-EMA, ml-EMA) — text's damaged short-match stretches are locally json-shaped, no in-loop discriminator exists; the dense-insert rescue hits the random-store floor (skewed −54% speed). **Search-side batched probing** (scalar pair-of-pairs, single exit branch, scalar-exact lane placement) is output-neutral but adds +3.8% Ir and −10..14% wall on json/text — json's miss runs are 1-2 pairs, so batch entry + dropout re-probe never amortize; the AVX-512 flavor would only add gather costs on the same structure. Positive residue from the stepping A/Bs: json.fastest's parse is weak-match-polluted (skipping mid-run weak matches improves it on both axes) — a shape-safe acceptance-bar/fragmentation lever on match-dense parses is the one unexplored direction left here. **Tried 2026-09-16** ([negative](negative/matchers.md)): the fed-back-literal-price bar (the chain store gate's own pricing, transplanted to the fast hash path) IS shape-safe and wins json.fastest −1.25% size in every mode with text/skewed unharmed — the pollution is recoverable — but the scan loop cannot host it: a dormant bar (code present, never taken, byte-identical output) costs text.fastest −12% and json.fastest −4% wall, and the outlined-cold form does not recover.
